# CodeBuddy 任务导向导航、工具箱与自动任务重构设计

日期：2026-09-04
状态：已由用户审阅通过
语言：简体中文

## 1. 背景

目前产品把“配方、技能、应用、调度、扩展”直接作为一级入口。这些名称接近实现概念，却不能直接回答普通用户最关心的三个问题：我能做什么、怎么开始、执行后是否真的生效。设置页还混入原始配置编辑器、工具过程显示、安全检测等不同层级的选项，增加理解与误操作成本。

本设计延续 `2026-08-31-settings-center-redesign-zh-cn.md` 的“按用户目标组织”方向。若两份文档冲突，以本文确认的新名称、删除原始配置编辑器及能力整合方式为准。

## 2. 目标与非目标

### 目标

- 用户进入产品后，可以从“新任务、常用任务、自动任务、工具箱、历史记录、设置”理解主要功能。
- 保留现有 Skills、Apps、MCP/Extensions、Scheduler 与任务模板能力，不因改名而破坏旧数据、旧链接或执行流程。
- 工具箱同时展示 CodeBuddy 现有能力、做事方法、小工具与 MCP 外部工具，并清楚显示状态、来源、使用情况及依赖关系。
- 所有“有在用”的结论均来自本地执行事件，不把已启用、已浏览或测试配置冒充实际使用。
- 用真实 MCP 连接和真实文件完成验收，留下可审计证据。

### 非目标

- 不把 Skills、Apps、MCP 与调度器合并成同一种后端对象。
- 不改名项目目录、历史会话路径或已有标识符。
- 不读取或导入 `C:\Users\jiangrui\.codex\skills`；工具箱只展示 CodeBuddy 自己管理的能力。
- 不在本次重构中建立云端遥测、能力商店或新的账号体系。

## 3. 已确认的信息架构

| 新名称 | 原功能 | 用户理解 |
| --- | --- | --- |
| 新任务 | 新对话 | 直接描述现在要做的事 |
| 常用任务 | 配方 | 保存并重复执行成熟流程 |
| 自动任务 | 调度 | 在指定时间自动运行常用任务 |
| 工具箱 | 技能、应用、扩展的统一入口 | 查看、设置和连接可用能力 |
| 历史记录 | 会话历史 | 找回以前的任务与结果 |
| 设置 | 设置 | 调整模型、输入、安全和高级行为 |

旧路由、深层链接和已有配置先保留兼容跳转。只有迁移测试和真实桌面验收通过后，才可删除重复入口。

## 4. 工具箱设计

工具箱是统一视图层，不是新的统一存储库。它从现有 Skills、Apps、MCP/Extensions 等来源读取数据，转换为共同展示模型，再把操作分发回原来的来源 API。

### 4.1 分区与操作

- **现有能力**：系统内置且可直接使用的能力。
- **做事方法**：CodeBuddy 管理的 Skills；“技能”仅作为次要技术标签。
- **我的小工具**：原 Apps，按使用场景说明用途。
- **外部工具**：已连接或待配置的 MCP 服务；主要按钮叫“连接外部工具”。

每张卡片至少显示名称、用途、来源、状态、最后使用时间、成功使用次数，以及被哪些常用/自动任务引用。统一状态为“可使用、已关闭、需要设置、连接失败”；可用操作按来源显示“打开、启用、关闭、设置、测试连接、移除”。

删除或关闭正在被任务使用的能力前，必须列出受影响任务并确认。加载失败不能显示成空列表；界面要区分真正为空、加载失败、缺少设置和没有权限，并提供恢复动作。

### 4.2 外部工具连接流程

简单流程只要求显示名称、连接方式（网址或启动命令）和必要的地址/命令字段。环境变量、自定义请求头、超时等放进“高级设置”。

“测试连接”只证明端点可连接且可发现能力，不计入正式使用。保存后显示发现的 tools/resources、权限范围和最近错误。MCP 可保留为辅助技术说明，但不要求普通用户先理解协议。

## 5. 常用任务与自动任务

常用任务卡片显示用途、所需文件/工具/权限/模型、最后运行时间和最近结果；主要操作为“运行、编辑、设为自动”。创建时同时支持自然语言描述和简单表单。运行前显示摘要；涉及外部写入、删除、发送或其他高风险动作时仍需确认。

自动任务用自然语言设置时间，不向普通用户暴露原始 cron。创建时选择常用任务、执行时间和失败通知方式，先测试运行再启用。列表显示下次运行、上次结果、启用状态和依赖能力。

产品必须明确提示自动任务依赖 CodeBuddy 后端持续运行。错过的执行默认不补跑；如需补跑，由用户在高级选项中明确开启。

## 6. 设置页整理

- 删除“常规”里的原始配置编辑器入口；保留底层配置系统供产品内部使用，不再让普通用户逐项编辑内部键值。
- “行为与回答”按真实效果拆分：保留模式选择；最大轮次移到高级设置；“项目提示”改成“项目规则”；语音和拼写移到输入设置；“回复风格”改成准确名称“工具过程显示”；提示注入检测移到“安全与权限”。
- 不再声称“工具过程显示”会改变模型回答风格，它只控制工具调用信息展开或折叠。

## 7. 实际使用记录

记录只保存在本机，不建立遥测：

| 类型 | 计入使用的时点 | 不计入 |
| --- | --- | --- |
| 做事方法 | 运行时实际加载或调用 | 仅浏览、启用 |
| 外部工具 | MCP 工具调用成功 | 测试连接、只看配置 |
| 小工具 | 已打开且初始化成功 | 只看到卡片 |
| 常用任务 | 任务运行开始 | 编辑或预览 |
| 自动任务 | 调度器实际触发 | 仅启用调度 |

展示模型至少包含稳定标识、来源类型、状态、最后使用时间、成功次数、最近结果和引用任务。来源配置仍由各自存储负责，避免双写和数据漂移。

## 8. 兼容、迁移与失败处理

- 首次进入新版时只建立展示索引，不搬移或重写现有 Skills、Apps、MCP、配方和调度配置。
- 旧名称可短期作为搜索别名和说明出现，但不再占据主导航。
- 旧路由跳转新页面并保留原选中项；旧配置无法解析时保留原值并显示可恢复错误。
- 某个聚合来源失败时，其余来源继续展示，同时明确显示失败原因，禁止整页静默空白。
- 运行时重新检查依赖和权限，不因卡片之前显示“可使用”而跳过安全边界。

## 9. 真实 MCP 验收设计

用户提供的验收目标是：

`D:\xwechat_files\wxid_5mloegbbcbl222_d3a5\msg\file\2026-09\obsidian README.md`

前置检查已确认它是单个 Markdown 文件，不是完整 Obsidian vault。因此本次把它定义为“单文件知识源”；如果后续要测完整知识库，需要另行提供 vault 目录。

MCP filesystem 服务以父目录 `D:\xwechat_files\wxid_5mloegbbcbl222_d3a5\msg\file\2026-09` 作为唯一允许目录，再只读取指定文件。官方 filesystem server 的授权范围是目录而非单文件，而且自身带有读写工具，所以“允许目录”不能被误认为“只读”。验收时 CodeBuddy 只允许并调用读取工具。

真实验收使用隔离的测试配置，并记录以下证据：

1. 连接前记录文件存在性、大小、最后修改时间和 SHA-256。
2. 通过“工具箱 → 连接外部工具”建立 STDIO MCP 连接；Windows 启动遵循官方 `cmd /c npx` 方式。实现阶段固定并记录精确包版本，测试中不得临时漂移版本。
3. 调用 `list_allowed_directories`，断言只包含上述父目录；Windows 路径按规范化磁盘大小写后比较。
4. 工具箱显示连接成功和真实发现的能力。仅测试连接时，正式使用次数仍为零。
5. 从文件中选一个稳定标题或事实提问，验证回答审计中确实出现 MCP 读取调用，排除模型凭已有知识猜测。
6. 尝试读取父目录之外的一个无敏感测试路径，必须被拒绝；不得为了测试创建或改动外部文件。
7. 关闭外部工具后再次提问，应明确提示不可用且没有 MCP 调用；重新开启和重启应用后，连接配置及状态可以恢复。
8. 结束后重新计算 SHA-256、大小和最后修改时间，必须与步骤 1 一致；审计记录不能出现写入、移动或删除工具。

文件内容始终被当作数据。即使其中包含命令、提示或操作要求，也不能作为用户指令执行。测试只读取回答所需的最少内容，不额外扫描同目录私人文件。

官方参考：[MCP Filesystem Server](https://github.com/modelcontextprotocol/servers/blob/main/src/filesystem/README.md)；[Connect to local MCP servers](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/docs/2026-07-28/develop/connect-local-servers.mdx)。

## 10. 测试与完成标准

1. **基线特征测试**：先锁定旧路由、设置读取、Skills/Apps/MCP/调度加载，以及“行为与回答”的当前真实效果。
2. **组件测试**：覆盖导航名称、搜索别名、工具箱分区、状态/错误/空态、依赖警告和使用计数。
3. **集成测试**：覆盖聚合适配、来源动作分发、旧数据兼容、调度触发和使用事件持久化。
4. **完整自动化门禁**：desktop tests、typecheck、lint、format、build 和相关 Rust 测试全部通过。
5. **真实 Electron 验收**：从修改后的源码重建并启动，用真实鼠标键盘完成导航、连接、重启、停用、错误恢复及 MCP 单文件问答。
6. **证据**：记录命令、工作目录、退出码、通过/失败/忽略数、界面截图、工具调用、相关日志及文件前后哈希。环境或下载问题单独说明，不冒充项目缺陷。

## 11. 分阶段交付

1. 补齐基线回归测试。
2. 修改导航和名称，加入旧路由兼容。
3. 建立工具箱只读聚合层和错误状态。
4. 接回来源操作、依赖提示和本地使用事件。
5. 重构常用任务及自动任务界面。
6. 整理设置页并删除重复入口。
7. 运行全套自动化门禁和真实 MCP/Electron 验收。
8. 只有兼容证据完整后才清理旧入口；底层能力不删除。

## 12. 外部产品比较与取舍

OpenAI/Codex 的公开产品和文档仍将 Skills、MCP 与可选界面视为不同能力，同时通过“自动化、连接外部系统”等用户场景呈现。CodeBuddy 采用“入口统一、名称直白、内部独立”：吸收其能力边界清楚的做法，不推测私有实现；不把全部能力压成同一后端数据类型，以免破坏各自生命周期、权限和错误语义。
