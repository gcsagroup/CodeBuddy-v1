# CodeBuddy 設定中心重構設計

## 目標

把目前以橫向分頁及實作模組堆疊的設定頁，重構為依使用者目的組織的設定中心。保留既有模型路由、本機推論、Provider、權限、記憶、憑證、擴充套件與應用程式設定，不因重構而刪除或降級功能。

## 已確認決策

- 採用「分組側欄 + 設定搜尋」。
- 設定頁負責組態；下載、載入、卸載、連線測試與執行記錄進入獨立模型總控制台。
- 一般使用者只看到「CodeBuddy 模型」與「自訂模型連線」，不顯示廠商市集。
- CodeBuddy 模型完成前顯示「開發中」，不可選取。
- 自訂連線支援本機、區域網路與自建公網端點；預設採 OpenAI 相容協定，透過 `/v1/models` 探索模型，失敗時可手動輸入模型 ID。
- 後端能力不可用時保留入口，顯示原因與修復方式，不再靜默隱藏頁面。
- 系統提示範本屬於進階功能；一般使用者透過「行為與回答」調整體驗。

## 資訊架構

### 常用

- **一般**：啟動、視窗、防止休眠與成本顯示。
- **外觀與語言**：主題、介面語言與顯示偏好。
- **通知與更新**：任務通知、系統通知、版本與更新策略。

### AI

- **模型與執行**：目前模型、連線狀態、快速切換與 Agent 模型設定。
- **行為與回答**：預設模式、回答風格、工具細節、拼字檢查與專案提示。
- **記憶**：專案記憶開關及可讀的新增、編輯、刪除；配額、過期、匯出與清理放入進階管理。

### 連線與安全

- **工具與連線**：擴充套件、外部後端及狀態。
- **帳號與憑證**：GitHub 與自訂端點密鑰，不回顯明文。
- **權限與隱私**：工具權限、唯讀判斷、工作區授權、遙測與資料邊界。

### 進階

- **快捷鍵**：全域、應用程式、搜尋與視窗快捷鍵。
- **系統提示範本**：範本差異、驗證、儲存及還原預設值。
- **開發者與診斷**：原始組態、能力宣告、記錄與診斷匯出。

## 核心流程

左側使用固定分組側欄，右側一次顯示一個頁面。搜尋結果顯示名稱、說明及路徑。每個設定標示作用範圍及生效時機。舊深層連結映射到新路徑。

模型與執行頁只包含 CodeBuddy 模型、已設定連線與 Agent 模型設定。自訂連線依序選擇 Ollama 或 OpenAI 相容協定、輸入 URL 與選用密鑰、讀取模型清單、選擇模型，再儲存並返回模型選擇器。只有探索失敗時才顯示手動模型 ID。連線向導不自動發出可能計費的推論要求；串流與工具呼叫由實際工作階段驗證。失敗的連線不得成為預設模型。

公網端點必須使用 HTTPS。HTTP 僅允許回環位址及使用者明確確認的區域網路位址。密鑰存入既有安全憑證儲存，不寫入專案、記錄或診斷匯出。

記憶第一屏只回答是否啟用、作用專案、記住內容及修改方式。關閉不刪除資料；單筆刪除與清空專案分別確認。`AGENTS.md` 等強制規則與記憶分離。

系統提示範本在儲存前驗證 Jinja 語法、必要變數及最小試算。提供預設差異、風險等級及還原預設值；高風險範本驗證失敗時不得儲存。

## 相容、錯誤與交付

- 沿用既有 Provider、模型預設值、憑證儲存及本機模型目錄。
- 不刪除舊組態鍵；以適配層把舊 Provider 投影為自訂連線。
- 本機推論入口不得只靠 `localInference` 布林值決定是否顯示。
- 儲存失敗保留表單；登入、權限、下載與安全確認視為可續跑等待。
- 模型下載前檢查磁碟空間；刪除前顯示路徑、容量、載入及預設狀態。
- 診斷匯出必須預設移除密鑰、令牌、請求正文與使用者檔案內容。

交付依序為：設定外殼；模型與連線；行為、記憶與權限；工具、憑證與進階；三語文案、Release 與真實 Windows 桌面驗收。每階段測試通過後才進入下一階段。

## 驗收

元件測試涵蓋導覽、搜尋、深層連結、不可用能力、持久化與危險操作。後端測試涵蓋探索、手動模型 ID、驗證、TLS、逾時、協定及原子更新。完整回歸 Provider 路由、本機推論、權限等待、工作區授權、記憶、憑證及更新。打包後端宣告的能力必須與實際編譯功能一致，並在真實 Windows 桌面及 Release 安裝包完成重啟持久化流程。

## 非目標

- 不建立第三方廠商市集。
- 不在自有模型完成前偽造可用狀態。
- 不重寫推論引擎或 Provider 協定。
- 不改變既有權限、修復狀態機或儲存語意。

## 已核准補充：本機連線與 Agent 模型

- 移除模型控制台中的 GGUF/HuggingFace 推薦、搜尋與下載介面，不刪除底層相容程式或使用者既有模型檔案。
- 「模型與執行」只顯示 CodeBuddy 自有模型（開發中）、已設定連線與新增連線入口，不顯示廠商市集。
- 所有模型選擇器保留「廠商」與「模型」兩個下拉選單。廠商只列出設定成功且可啟用的連線；模型只列出所選廠商探索或儲存的模型。
- 廠商下拉選單底部固定提供「使用其他廠商…」。該入口只開啟 Ollama（建議）、OpenAI 相容與手動設定，不開啟完整廠商目錄。
- Ollama 預設位址為 `http://127.0.0.1:11434`。先檢測連線，再自動探索模型；探索失敗時才允許手動填寫模型 ID。失敗草稿不取代既有可用設定。
- 新連線儲存成功後返回原模型選擇器，並選取新廠商與模型。既有雲端連線保留且繼續可選，但不重新推薦。
- 原「模型控制台」改為「Agent 模型設定」：包含預設 Agent 模型，以及可選的 Planner、Coder、Tester、Reviewer 進階路由。
- 進階路由關閉時四個角色跟隨預設 Agent 模型；開啟後每個角色分別使用「已設定廠商 + 對應模型」。不向一般使用者公開工作階段標題、上下文壓縮與權限判斷等內部輔助模型。
- 連線失效或模型消失時顯示不可用狀態，不靜默回退或改寫使用者選擇。

### 官方行為對照與取捨

- 採用 Ollama 官方 `GET /api/tags` 模型清單介面與本機 `11434` 連接埠慣例；介面預設使用明確的 `127.0.0.1`。
- 採用 OpenAI 官方 `GET /v1/models` 的 `data[].id` 結構作為 OpenAI 相容端點的探索契約。
- 不推測或複製 Codex 私有設定實作；只採用可觀察的簡潔設定與不公開內部輔助模型原則。
- 拒絕完整廠商市集、自動下載大型模型，以及在連線測試中送出可能計費的推論要求。

參考：[Ollama List models](https://docs.ollama.com/api/tags)、[OpenAI List models](https://platform.openai.com/docs/api-reference/models/list)。
