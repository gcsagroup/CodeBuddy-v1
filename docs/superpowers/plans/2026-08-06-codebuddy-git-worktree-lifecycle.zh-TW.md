# CodeBuddy Git 工作樹生命週期計畫：Task 1 相容性修訂

本文是英文主計畫中 Task 1 的繁體中文修訂說明。Task 1 除原定三個檔案外，還必須修改
`crates/goose/src/agents/agent.rs`：若只持久化描述符而不阻斷危險恢復路徑，舊狀態仍可能被執行。

採用明確的三種模式：

- `direct`：維持目前直接工作區行為；描述符不授予 Git 權限，仍須既有工作階段/工作區綁定。
- `legacy_unresolved`：舊狀態沒有描述符且 `source_repo` 與 `worktree_path` 不同；保留兩條路徑供檢視，但不提供可執行目錄，也不推斷 Git 工作樹歸屬。
- `git_worktree`：必須包含完整且經驗證的 Git 中繼資料；Task 1 只定義與驗證結構，不建立、重開或路由至工作樹。

載入時，缺少描述符且兩條路徑等價的狀態遷移為 `direct`；路徑不同的狀態遷移為
`legacy_unresolved`，不得拒絕或靜默隱藏。儲存時先複製並正規化狀態，確保新寫入狀態皆含描述符。
暫時保留舊路徑欄位，並要求其與描述符投影一致。

恢復檢查點時，必須在基線擷取、證據收集與工具執行之前識別 `legacy_unresolved`，保留任務供檢視，
並回傳明確的 needs-attention；不得把驗證錯誤吞成「沒有可繼續任務」。連結重播是在目前已綁定目錄中新建執行，
不是檢查點恢復，必須以迴歸測試固定此差異。

路徑等價必須重用既有可信正規化邏輯，不得以自造字串比較授予權限。Git 物件 ID 接受 40 或 64 位十六進位；
路徑字串或物件 ID 本身都不能證明工作樹歸屬。

最小 RED 測試：

1. 缺少描述符且路徑等價時遷移為無 Git 中繼資料的 `direct`。
2. 路徑不同時仍可讀取為 `legacy_unresolved`，並保留兩條路徑。
3. `legacy_unresolved` 不提供已驗證執行目錄。
4. 其檢查點恢復在基線與工具呼叫前進入 needs-attention，正常 `direct` 恢復不回歸。
5. 狀態清單仍顯示未解決的歷史任務。
6. 儲存舊形狀狀態後，持久化結果包含非空描述符。
7. direct/未解決模式攜帶 Git 中繼資料、git_worktree 缺中繼資料、不支援版本、空路徑、非法 OID、投影不一致皆失敗關閉。
8. snake_case 序列化、40/64 位 OID、Windows 正規路徑等價與連結重播邊界維持穩定。

Task 1 只驗收持久化合約、安全遷移、消費者阻斷與投影；不代表工作樹探索、建立、隔離、重開、套用或捨棄已實作。
