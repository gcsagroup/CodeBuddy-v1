## 修复边界与职责

1. **登记与准入分离。** 执行义务和原始 shell 回执用同一 exact-command/cwd 身份记录；已支持的 bounded invocation 保留原格式，其他 shell 命令保留完整原文、不拆解为允许子命令。权限、只读策略、bounded 执行入口继续用原分类器，登记本身不执行、不授权。
2. **用现有调用身份连接证据。** inspect 增加 callId、原命令、结束时间、当前资源版本状态和未知动作明细。覆盖提案允许精确引用同一索引的 callId，由宿主解析到唯一 audit ID；不新增证据库、不模糊匹配 ID、不自动替模型决定业务覆盖。
3. **版本按资源归并。** 同一个提案包含多次编辑时，对每个路径校验最新的被选回执；没有被选的新版本、外部改动、缺少哈希仍拒绝。执行义务使用同一 invocation 的最新回执，不拿更早成功掩盖后续失败。
4. **区分已知失败与未知结果。** 平台 shell 有真实退出码且正常收齐输出时，文件变化是已观测的部分效果，不自动升级成永久 unknown。输出管道排空超时仍可能有活着的子进程，保留未知，不能只拿父进程退出码解除。超时/取消的停止确认由现有 shell 执行器生产，Windows taskkill 精确 PID/树调用成功且 wait 成功才确认；缺失/失败保持未知。确认停止不表示文件回滚、外部效果成功或任务完成。其他工具的未知、审计 Cancelled/TimedOut、Ambiguous 与外部副作用边界不放宽。
5. **压缩和历史恢复可解释。** 未知动作仍保留原 callId、命令与回执摘要，inspect 能查到，不要求模型去项目记忆中找；不同 taskScopeDigest 的旧失败不污染当前任务。
6. **正常开发说明。** shell 工具明确非交互、服务与检查分开、重定向/保留 PID、检查状态后再启动，不按进程名全杀。只是准确描述现有工具能力，不新增后台任务系统。

## 成熟实现参照

通过 OpenAI Docs 核对 [Shell 官方指南](https://developers.openai.com/api/docs/guides/tools-shell)：退出与超时分别返回，保留非零退出的输出，让模型据实恢复。采用的是这种事实区分，不推断 Codex 桌面内部完成策略。

[Local shell 示例](https://developers.openai.com/api/docs/guides/tools-local-shell)展示进程组检查与超时终止；其 Windows 示例只 kill 直接进程，不能照搬成“整棵进程树已停”的保证。本轮保留 CodeBuddy 的 Windows 精确 PID `/T`，并检查实际返回状态；非 Windows 未获得树停止事实时仍保持未确认。
