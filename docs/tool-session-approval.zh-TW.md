# 工具對話授權

瀏覽器控制、圖片生成、影片生成、桌面寵物製作與專案記憶共用既有授權卡片：拒絕、僅此次允許、本對話允許此工具。按鈕由執行階段傳回的可用操作決定；前端不自行授予權限。

對話授權只涵蓋目前對話中的特定工具，不授予其他工具或其他對話，也不儲存為全域允許。下一輪重新設定相同工具時保留授權；移除工具、更換工作區、服務位址或執行歸屬後重新確認。程式重新啟動後重新授權。專案記憶仍須單獨審核候選內容，寵物仍須由使用者選擇啟用。

MCP 工具清單更新時，同一連線中定義、參數結構和中繼資料均未變更的工具保留授權。工具變更、移除或重新連線會使舊授權失效。

本機 MCP 服務由目前對話持有；只更新提示詞或模型上下文不會重新啟動設定未變且健康的服務。更改命令、參數、環境、工具篩選條件或停用服務會釋放舊連線與授權。明確釋放對話能力也會清除原生網頁與內建工具授權，重新啟用時重新確認。

`list_mcp_resources`、`list_mcp_resource_templates`、`read_mcp_resource` 依目前對話、特定工具及服務連線分別授權；列出資源不等於允許讀取，更換服務不繼承舊授權。圖片與影片的 `inspect` 與同一工具的生成操作共用服務授權，查詢舊位址的工作仍單獨確認。

## 全入口檢查範圍

| 入口 | 行為 |
| --- | --- |
| 右側瀏覽器、圖片、影片、寵物、專案記憶 | 對話授權；候選記憶審核與寵物啟用仍獨立 |
| MCP 工具：獨立瀏覽器、使用者瀏覽器、電腦操作、時間天氣、PDF、圖表及外部服務 | 共用 MCP 授權入口；標記為破壞性的工具逐次確認 |
| MCP 資源清單、範本清單、資源讀取 | 依工具與服務連線授權 |
| `web_fetch` | 依網站授權，保留原生網路邊界 |
| 檔案與圖片讀取、搜尋、技能、依賴路徑、十個 Git 唯讀工具 | 既有唯讀規則，通常無須授權卡片 |
| 寫入、編輯、命令、切換工作目錄 | 原生沙箱決定執行與逐次提升 |
| 十個 Git 寫入工具 | 保留破壞性標記、逐次確認與預檢回執 |
| 提問、退出計畫模式、目標、待辦、背景工作、子代理控制、工具探索 | 原生狀態機與歸屬校驗，不將使用者回答替換為工具授權 |

檢查涵蓋目前原始碼註冊路徑與公共審批入口。第三方工具清單會動態變動；公共回歸使用隔離 HTTP／stdio 服務驗證授權，不執行所有第三方真實副作用。

明確設定為每次詢問、觸發額外安全確認，以及標記為破壞性的 MCP 工具仍只提供單次確認。原生命令繼續遵循 Harness 的沙箱與審批規則。明確禁止或停用工具始終優先於既有對話授權。
