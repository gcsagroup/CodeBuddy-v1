# Reusing remote MCP connections for new sessions

This change fixes repeated remote MCP connections when creating sessions. It preserves the model, reasoning setting, selected tools and frontend. Source is the existing `D:\CodeBuddy-v1` directory, which has no `.git`; source SHA256 hashes are recorded in the acceptance receipt. No branch, commit, push, dependency installation or upgrade occurred.

## Cause and design

Previously, the adapter mounted MCP inside each Agent's session capability plugin. Reconfiguring that plugin disposed the connections, and each new session connected again. Earlier real desktop samples spent 2.625s / 8.126s connecting Exa; see the [previous investigation](2026-10-14-harness-latency-comparison.en.md).

The implementation reuses the installed official `0.2.1-alpha.2` `dsh-agent-preset-registry`, `dsh-scope` and Cordis lifecycle. The registry creates standing scopes and `acquireScope` supplies native leases, retaining retired revisions until their final reference is released. These packages are MIT licensed; [upstream](https://github.com/deepseek-ai/deepseek-harness). No upstream packages were upgraded.

- Identical remote MCP configurations share one standing composition within a runtime. Identity covers the canonical full configuration, including names, URLs, credentials, timeouts and reconnect options. The digest is an in-memory index; credentials and generated connection definitions are not persisted.
- The registry is private so connector compositions do not become durable user Agent preset selections. Native execution, scheduling and completion ownership remain unchanged.
- Sessions borrow the composition through the official scope parent chain. Tools, resources and instructions remain scoped. Every invocation still passes the calling session's permission checks. Sessions with MCP disabled do not inherit its tools.
- Changed configurations select another composition; existing sessions retain their connections. Eight reusable definitions are retained. Harness keeps retired generations alive while leased, rather than using a second connection reference counter. Failed initial startup is not cached, so later acquisition can retry.
- Harness `tools/change` refreshes inherited tool masks after dynamic MCP tool updates, while preserving native tool restrictions. Existing resource and MCP Apps metadata adaptation remains.
- Stdio stays session/workspace scoped because its process may hold working-directory or session state. A process restart still requires an initial connection.

Rejected approaches: retaining per-session reconstruction, disabling Exa, or implementing a separate client connection pool. This reuses Harness composition/scope/lease ownership; the official MCP SDK and existing `mcp-bridge.mjs` still handle protocol and Apps metadata. It does not claim removal of all adaptation or replacement of that bridge's reconnect implementation.

- `runtime/harness/mcp-presets.mjs`: private native registry, configuration identity, lease acquisition, bounded retention and inherited tool updates.
- `runtime/harness/mcp-composition.mjs`: parallel activation within a standing scope, preserving per-extension failure status.
- `runtime/harness/index.mjs`: session bindings and lease release, local stdio lifetime and original extension-result ordering.
