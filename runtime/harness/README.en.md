# CodeBuddy Harness runtime

Approval unavailability is distinct from user rejection. When native `approval:never` meets a host approval requirement, return `APPROVAL_UNAVAILABLE`; children must return the blocked action to the parent without expanding grants or automatically replaying it.

Both exports default the save dialog to the system Desktop and write only after confirmation.

`sdk-budget-contract.mjs` verifies the locked SDK and applies in-memory compatibility transforms without writing to `node_modules`. One final projection supplies both request fit and dispatch. Exhaustion fails before HTTP as `LOCAL_OUTPUT_BUDGET_EXHAUSTED`; short length becomes `OUTPUT_TRUNCATED`. Local-budget/short-length recovery may run once per native turn, only after a real surface reduction and improved fit; regular pressure compaction keeps upstream policy, and transport `always` cannot replenish recovery attempts. Explicit Completions caps 1/128, ordinary stop, original usage and Session v4 keep their meanings. `index.mjs` serializes contract loading before importing the original implementation in `driver.mjs`; metadata and schedule entries establish the same contract first. Version or SHA drift fails startup and requires review; prefer an equivalent upstream contract when available, as recorded in PROVENANCE.json. Native tokenMeter pressure and final adapter fit remain distinct measurements.

Remote MCP connections are reused across sessions through the official `agent-preset-registry` standing scopes and leases. Matching configurations connect once; changed configurations use isolated revisions while existing sessions retain their connections. Up to eight reusable definitions are retained; Harness preserves retired revisions while leased. Stdio remains workspace/session scoped. Tool-list changes refresh inherited tool masks, and execution still requires per-session authorization. See design and real desktop acceptance（archived in Git：`docs/reconstruction/2026-10-14-mcp-reuse.en.md`）.

Official `goal`, `goal-round-driver`, and `tool-goal` own durable objectives, CAS updates, automatic rounds, round limits, and pausing. `prompt` stays open while a native goal is active and armed, waiting for official continuation; an ordinary conversation without a goal ends normally. Its `goal` result is the official GoalView. Stop cancels execution and disarms continuation; restart remains disarmed and never replays work automatically. Explicitly paused goals resume through structured `prompt(...,{resumeGoal:{goalId,revision}})`, which attaches permissions and events before invoking the official resume operation. `getGoal` is read-only. `controlGoal` supports pause, and resume within an attached run; standalone idle resume is rejected.

Model requests use the official bounded retry defaults: five retries, exponential backoff starting at 500ms, and a maximum interval of 10 seconds. `llm/retry`, `goal/change`, `turn/start`, and `todo/write` retain native identities through `harness_event`; todos belong only to the current turn. `model_diagnostic` records first-chunk/end latency, HTTP status, chunk counts, and allowlisted network error codes. It never records content, credentials, headers, or URLs, and does not modify fetch, streams, or retry decisions.

The Host fixes the official settings at `maxActiveSubagents: 3` and `maxDepth: 1`: each root conversation's native tree can run three children concurrently, and children cannot delegate another level. Obsolete `roleModels`, `maxParallelSubagents`, and `maxParallelCoders` do not affect execution; saved role routes cannot replace the model currently selected for the root conversation.

The MIT-licensed official npm distribution and plugins are pinned to 0.2.1-alpha.2, a developer preview. The profile composes official boot, Session Controller, AgentLoop, JSONL persistence, MCP, skills, subagents, jobs and compaction. There is no second model loop. See PROVENANCE.json; npm/source byte equivalence is unverified. [Upstream repository](https://github.com/deepseek-ai/deepseek-harness).

Use Node 24+. The approved dependency entrypoint is `npm ci --ignore-scripts --no-audit --no-fund`. This batch installed, downloaded and upgraded no dependencies and changed no system PATH.

Length recovery and zero-output length overflow require an explicit provider output counter, including a reported zero. Missing usage or output fields remain unknown and retain the original `max-tokens` outcome; neither text estimates nor SDK default zeros supply that evidence.

Responses requires at least 16 output tokens when its cap is enabled ([official constraint](https://developers.openai.com/api/reference/ruby/resources/responses/methods/create)). An explicitly smaller cap fails as `INVALID_OUTPUT_BUDGET` before HTTP, without raising the cap, compaction or retry. Context allowance below 16 uses bounded native budget recovery. A legal Completions cap of 1 remains supported. Explicit `supportsMaxOutputTokens=false` still omits the server-side cap.

## Adapter interface

Summary preparation also consumes the adapter's actual fit. After existing middleware and final projection, the LLM service rejects `COMPACTION_OUTPUT_BUDGET_EXHAUSTED` before HTTP if the complete requested summary output (4,096 tokens by default) cannot fit. Native compaction geometrically shortens tool-balanced ends within the same transaction and rebuilds both input and the shadowed set; unsummarized tail events remain active and unchanged. Bounded local preparation finds a fitting span rather than the longest span or an exhaustive proof. The final candidate uses the bound registration snapshot and configuration and makes one summary HTTP request. Actual length or cancellation never starts another summary request. Failure to find a fitting span commits no checkpoint and preserves the original failure. The existing pressure-only lone-checkpoint guard also covers the final shortened input.

Native tool image references are read and verified by the attachment store before the adapter creates valid ACP presentation blocks. An unreadable preview degrades only image display, preserving the real tool terminal status and original receipt. Old records are repaired only in replay projection, without tool replay or history rewriting. After optional image I/O, replay reads the current durable/live high water mark before synchronously resetting and publishing history.

`createHarnessDriver({dataDir,cwd,instructionsHome})` requires an isolated data root. Call `createSession({sessionId,cwd,provider,model,options})`, `prompt(sessionId,content,{onEvent,onPermission,signal})`, then `close()`. Provider fields include baseUrl (API root), apiKey, protocol, headers, compat, contextWindow, maxTokens, inputModalities and reasoningEfforts. Model/MCP credentials remain in driver memory. The on-disk Host providers map stays empty; legacy and ambient credentials are not discovered.

`configureSession(sessionId,options)` applies while idle; the application persists settings and reapplies them after restart:

- systemPrompt, maxTokens, temperature and thinkingEffort affect actual requests. Efforts must be declared by the provider.
- Custom connections select a preview endpoint from the model list's `owned_by`: `/v1/chat/completions/render` for vLLM, `/v1/tokenize` for SGLang, preserving the API base path and authentication. Previews render the actual chat template without inference. Only template-changing modes are offered; equivalent modes collapse and the service default is preserved. Results share the existing capability cache and refresh with model listings. Missing preview endpoints, failures or ignored parameters do not establish effort support; model details show “No verified controls”. Generic parameter enums and model names are not capability evidence. References: [vLLM reasoning controls](https://docs.vllm.ai/en/stable/features/reasoning_outputs/), [SGLang tokenization](https://github.com/sgl-project/sglang/blob/main/python/sglang/srt/entrypoints/openai/serving_tokenize.py).
- maxTurns bounds official steps across the prompt's root and children. max_turns preserves history and never means business completion.
- autoCompactThreshold (between 0 and 1), autoCompact and `compact(sessionId,{signal})` use official token-meter/compaction-basic; original evidence events remain intact.
- The compaction compatibility hook inherits the current conversation's reasoning control for a matching route, avoiding chat-template changes that invalidate the prefix cache. It preserves explicit summary controls, independent summary models and changed session settings. The summary retains the upstream instructions and complete input for its selected span. Its output budget increases from 1,024 to 4,096 tokens to fit reasoning and a complete checkpoint, without requesting longer prose. The locked selector repair preserves the latest original `source.kind=user` event even when generated runtime-context or skill-catalog messages follow it. Within the existing tail budget, it chooses a larger priced, tool-balanced contiguous span on either side, preferring spans other than a lone checkpoint; a long turn can still compact subsequent tool history without cloning or reordering user input. If only a checkpoint remains eligible, forced recovery and manual compaction keep that fallback while the existing pressure guard skips it. Summarizing a later span may sacrifice prefix-cache reuse. Truncation rejection, cancellation and checkpoint transactions remain upstream. A summary does not guarantee lossless retention for arbitrary tasks. Reassess the compatibility hook when upgrading Harness.
- tools: `[{name,description,inputSchema,execute}]`. Execute receives `(args,{sessionId,signal,callId})` and returns a JSON object through the official registry, validation and approval pipeline.
- mcpServers uses official stdio/streamable-http configuration. Tools are mcp__server__tool. Independent servers connect concurrently, retaining each ready/error result in configuration order. Failed connections are disposed; other capabilities stay usable. Reconfiguration retries. `extensionStatus(sessionId)` reports status. `testExtension(server)` temporarily connects, discovers and disposes; failures reject. Connection, discovery, synchronous calls and individual Tasks requests default to 300 seconds; explicit `toolCallTimeoutMs` takes precedence. Extension `timeout` is in seconds, with the same conversion for testing and sessions; existing reconfiguration applies saved changes. Version negotiation may involve multiple requests, so this is not an overall startup deadline.
- Initial connection/reconnection detects async support from negotiated capabilities and tool definitions. Legacy 2025 Tasks requires both server `tasks.requests.tools.call` and tool `execution.taskSupport` optional/required. Modern 2026 Tasks uses the `io.modelcontextprotocol/tasks` extension; the server decides whether to return a task. Other tools run synchronously, without guessing names or issuing probe actions. `mcp-tasks.mjs` polls in the adapter and returns only the final MCP receipt to Harness; accepted calls are never resubmitted. The 300-second limit applies per request, not to total async execution; user cancellation remains available. A cancellation acknowledgement does not prove remote termination. Task input interactions and automatic recovery across process restarts are not supported. SDK 2.2.0 has no Tasks runtime, so modern Tasks uses a pinned internal-codec compatibility shim; revalidate and prefer removing it when upgrading. Design reference: [MCP Tasks](https://tasks.extensions.modelcontextprotocol.io/).
- toolFilter:{allow?,deny?} filters inherited tools. Same-scope MCP/host registrations require the application's shared permission gate to enforce exact allowlists.
- The generic native `subagent` accepts `{description,prompt,cwd?}` and inherits the provider, model, and reasoning effort of the parent's actual request. No `subagent_<role>` tools or child model selection are registered. Harness owns creation, concurrency, depth, and result delivery; child file and command operations still use the existing permission gate.

onEvent may return a Promise. Events are serialized and awaited before subsequent approval or host execution. Events carry sessionId; render children separately. tool_result.structuredContent/error are original official outcomes. Foreground shell results contain exitCode, aborted and timedOut; background handles are not verification results. Streaming attemptId and durable messageId differ.

Every tool requires onPermission to return true. Children inherit the callback through verified live ownership. Files additionally use workspace policy; native shells are not claimed to have kernel sandbox isolation. Cancellation interrupts children and owned jobs and returns actual states; running/stopping remains unconfirmed. Jobs are process-local; restart recovery rechecks and continues durable conversations, not old OS processes.

Other methods: listTools, callTool (idle maintenance window), steer (active official inbox), history, listSessions, rename, fork, follow and upload.

Images enter prompt parts as `{type:'image',mediaType,data:<base64>,name?}` with image declared in the model inputModalities. Official admission validates, normalizes and persists references. Generic files use `upload(sessionId,{data:<base64>,name})`, followed by `{type:'file',receiptId}` in the same session prompt. A receipt is consumed once; the model receives a handle for reading the file on demand.

`../transcripts.mjs` persists the ACP display projection while Harness owns execution history. `openTranscriptJournal(store)` recovers unfinished NDJSON at startup; `begin({sessionId,turnId,users,title?})` returns append, appendUsage and finalize. Each append awaits fsync. Finalize atomically projects chunks and replay high water marks in the runtime store, then removes the journal. Await appends before UI notifications. Recovery does not invent completion evidence.

ACP `session/cancel` requests cancellation. The adapter reserves occupancy before its first asynchronous validation. It sends the real terminal to the original caller and same-session observers; when finalization exits, it deletes occupancy before synchronously sending the existing `session_info_update` with `activeRunId: null`. The terminal, Host release, and original prompt RPC result are distinct observations; writing the cancel notification does not replace them.

## Skills and memory

AGENTS.md loading uses the official agent-instructions plugin. `instructionsHome` selects this application's global root, defaults to the isolated data root, and receives CODEBUDDY_HOME in the product. Official discovery handles project and nested instructions. This pinned version captures environment paths synchronously during apply; the wrapper changes Process variables only during that synchronous initialization and restores them immediately. It never changes User/Machine environment variables.

Official spawn creates a flat child scope. After verifying parent ownership, the driver explicitly composes host tools, MCP, system instructions and compaction during child agent/created. Execution and approval retain the actual child sessionId; native delegation inherits model and effort without a role override.

Official skill roots are project .dsh/skills and .agents/skills, plus data-root skills and agents/skills. listSkills, refreshSkills and explicit /skill-name invocation use official implementations.

This pinned version has no standalone built-in memory provider. Third-party memory uses official MCP. Local CodeBuddy records reuse storage-domain/storage-json under codebuddy_memory: synchronous memory.get(scope,key)/list(scope), asynchronous set(scope,key,JSONvalue)/delete(scope,key). The application owns schemas, project scopes, candidate activation and retrieval semantics; no second memory model or database is added.
