# Harness 11：按需工具与真实容量

源码：D:\CodeBuddy-v1，main / 01610d03764570282eee439cd2bfb49fcd373e98，加本轮及既有未提交修改。未创建分支、提交或推送；用户配置、历史不被验收夹具覆盖。

## 原因与改动

- 初始请求原先包含 25 个完整工具定义。现在只常驻读取与发现入口，其他原生文件、命令、技能、记忆、目标、子 Agent、后台任务、Git、MCP 能力通过发现入口加载。工具实现、校验、权限、执行、持久化仍归 Harness；工具专属说明随加载出现。删除重复宿主 persona，缩短 CodePro 提示。
- 当前固定版本没有通用于 OpenAI 兼容服务的完整工具搜索插件，因此保留 `tool-discovery.mjs` 这一投影适配，不另建执行器。`deferLoading` 标记本身不提供工具搜索能力。受限视觉和审查 Agent 保持原来的零工具或结果工具边界。
- 删除 CodeBuddy 自有的 32768 默认容量常量，读取已安装 Harness pi-ai 的默认配置。未知容量仍标为 fallback，而非模型能力。显式目录连接通过原生 `llm.discoverModels` 读取；自定义部署保留必要服务字段转换和更小的手工预算。
- Ollama Cloud 的 OpenAI 模型列表未给容量，但 `/api/show` 给出 kimi-k3.context_length=1048576。增加该原生元数据补充读取、按模型缓存和并发合并。只对官方云端采用该值；本地模型架构容量不等于已分配 num_ctx，不照搬。
- 自动压缩继续由官方 compaction-basic 和 token meter 控制，步骤间检查；已有锁定版本的单一摘要检查点重复压缩兼容修复保留。没有另加 CodeBuddy 压缩循环。

参考：[Harness 模型解析与发现](https://raw.githubusercontent.com/deepseek-ai/deepseek-harness/master/packages/llm/llm-pi-ai/README.md)、[Ollama 云端上下文说明](https://docs.ollama.com/context-length)。容量元数据不等于超长满窗口请求的实测承诺。
