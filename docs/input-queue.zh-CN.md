# 消息队列与立即切换

普通发送在执行期间按顺序排队，不打断当前任务。立即切换只选择当前条目；全部立即发送选择点击时的所有待发送条目。两者先保存选择，再取消当前执行及其子任务，等待结束后在同一会话开启下一轮。已经完成的外部操作不会撤销。

排队条目可以编辑、删除、排序或清空；正在切换或交付的条目被冻结。保存失败保留编辑内容。批量发送保留独立消息 ID、顺序和附件，不先拼接并删除原始条目。新加入的消息不混入已经选定的批次。

停止会暂停剩余草稿。重启后草稿仍在，用户选择发送后继续。传输回执不明时保留条目并核对原生记录，不自动重复发送；重复操作使用原命令 ID。旧版浏览器队列只在后台接收成功后迁移。

执行与工具权限仍由现有 Harness 链路负责。交付账本仅管理尚未进入原生执行的消息，原生消费回执才代表已消费。立即切换不保证远端模型服务器马上释放计算资源，也不能撤销已经完成的工具副作用。

编辑前会先暂停队列，防止上一轮结束时发出旧文本；保存或取消编辑后，点击发送草稿继续。

自动交付落盘期间若直接发送抢先占用会话，队列恢复为待发送并等待该轮结束；不会因此暂停或标记为发送结果不明。已选批次保留顺序，不取消选择时尚未观察到的新执行。

排队提交先保存完整的本地待确认记录，再立即清空输入框。确认到达不会清空后续输入；本地保存失败则保留原文。确认期间可继续编辑新草稿，但等待上一条确认后才能再次提交。后台拒绝或回执丢失时保留原消息，并通过刷新 / 重试确认处理。
