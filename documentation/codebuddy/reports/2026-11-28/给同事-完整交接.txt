二、具体改了什么，为什么改

1. 运行中补充消息分成“引导”和“排队”，默认引导。
引导会把新要求尽快交给当前任务，让模型有机会调整。它可以先回答再继续，也可以直接按新要求做，不强迫每条回复“收到”。普通引导不会为了尽快回一句话而杀掉正在写文件、执行命令或生图的任务。
排队则等当前这一轮自然结束，按顺序逐条发送，各带各的附件，目前不把几条拼成一段。每条只有“优先发送、编辑、删除”；优先发送是在当前步骤结束后交给模型，不是停止整个任务。卡片限制高度，多条在里面滚动，不会把聊天框顶上去。Enter 按所选方式发送，Ctrl+Enter 临时用另一种方式。

2. 防止连续发送时串字、丢消息和重复发送。
先保存每条完整消息，再清掉对应草稿；回执也按顺序处理。界面会尽早显示引导气泡。图片还在准备、任务恰好结束、窗口重载等情况都有专门回归。无法确认已经送到哪里的消息会保守保留，不会偷偷重发一遍。中断时屏幕上可能保留半截回复，但未确认完成的部分不会当成完整回复继续塞给模型。

3. 减少长思考、长正文和自动下滚越跑越卡的问题。
主要原因之一是：每来一点新文字，已经完成的 Markdown 内容也反复处理；文件信息更新还会连带刷新原本没变的内容。现在复用完成的内容块，稳定文件展示信息；正文不再为逐词淡入制造大量动画节点。
下滚继续由原来的滚动组件负责，按实际页面增长跟随。上翻阅读或选字时不会被新内容强行拽回，点击回到最新可以回来。去掉了模型调用次数、最近返回工具提示和重复的“已停止”，保留真实状态和用时。
改善已经在长输出中观察到，但不能保证模型本身匀速吐字，也没有宣称所有卡顿都根治。

4. 修了“补充后写不了 Markdown、子 Agent 写入失败”的权限问题。
原来补充输入会把某些本来允许的写入改成“需要询问”；但完全访问对应的原生策略又不允许弹这个询问，于是写入反而失败。现在保留原本允许的结果，再继续经过原生安全检查。没有把只读、工作区外禁止、显式拒绝或所有外部工具一并放开。主 Agent 和真实子 Agent 的文件写入都复测过。

5. 代码导航不再把普通可信只读查询反复当成需要审批的操作，并修了实际运行问题。
复用原来的 Serena、MCP 和语言服务，只暴露概览、定义、引用三个入口；同一任务可复用连接，避免每查一次重新启动。取消和超时会核对旧进程确实结束，不会盲目重发有疑问的查询。
审查还发现项目里旧的导航缓存可能包含能执行代码的内容，因此同时隔离缓存、禁用项目启动命令，避免“只读免询问”反而扩大风险。不能只合并免审批那一行。
TypeScript 的固定语言服务有正式准备和打包检查。生成的工具文件不随 Git 带走，接收机器仍要按 README 检查是否齐全；混合语言项目也要确认启用了对应语言。

6. 右侧文档标签加了边框、背景和选中区分，让多个标签更明显。
这部分只改外观。DOCX 打不开另有本机程序完整性标签的问题，曾在明确授权后只修正了 LibreOffice EXE；代码导航 Python 也做过同样的单文件修正。这两项是本机权限信息，不会随 Git 同步，没有加入自动批量改权限的代码。其他机器如遇到相同现象，必须先查自己的实际原因，不能照着全盘改权限。
