## 1. 給經理的結論

目標是在 CodeBuddy 寫完程式並完成基礎測試後，呼叫 SecVibe 審查本次變更。收到漏洞位置、證據與建議後，由 Agent 修復、測試及複查，交付程式與安全報告。Agent 執行引擎 繼續負責執行、調度、權限、恢復與任務完成；SecVibe 是外部審查能力。

現有架構具備可重用的接入點。待確認的主要前提是：供應方是否提供第三方可用的審計 API/MCP、穩定結果格式及商業使用許可。完整的安全 Agent 產品不等於已確認存在開放審計 API。

## 3. 建議架構與方案比較

```text
使用者請求／已啟用的專案策略
→ CodeBuddy Harness 工具調用
→ SecVibe 輕量適配
→ 官方 MCP 或審計 API
→ 結構化發現與報告
→ Harness 修復、功能測試、複查、交付
```

優先官方 MCP，重用現有工具橋接；其次是官方審計 HTTP API，封裝為薄工具適配。若僅有 CLI，須驗證非互動參數、JSON 結果、退出碼、取消及再分發條件。僅有互動聊天時，先作人工審查入口，不承諾自動閉環。

MCP 有工具發現、調用及結構化結果機制，適合此接法；這並不證明 SecVibe 已支援 MCP。[官方工具規範](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)

不嵌入整套 SecVibe/Pi 執行核心，也不另造調度器。外部審查作業狀態與 Harness 任務完成狀態分開。首版利用現有聊天、工具紀錄與報告檔，專用漏洞面板可後續增加。

## 4. 可重用模組

- `runtime/harness/profile.mjs`、`index.mjs`：插件、Agent 與工具執行。
- `runtime/harness/mcp-bridge.mjs`：MCP 連線、註冊與工具調用。
- `runtime/harness/mcp-tasks.mjs`：僅在服務真正協商支援時使用 Tasks。
- `runtime/mcp-settings.mjs`：目前同步超時預設 300 秒；超時應顯示失敗或未完成。
- `runtime/harness/tool-discovery.mjs`：按需載入工具，避免每輪注入完整規則。
- `runtime/secrets.mjs`、`settings.mjs`：重用憑證與設定邊界，秘密不進提示詞或一般日誌。

## 5. 輸入、結果與可靠性

以下是擬議適配需求，並非官方接口：輸入包含獲准的檔案清單、基線 revision、本機未提交與新增檔內容雜湊、關聯上下文及檢查類別。結果包含審查 ID、狀態、覆蓋範圍/缺口、報告；問題項應含穩定標識、路徑/行號、規則或 CWE、嚴重度、證據與建議。

報告綁定實際快照，程式碼改變即標示過期。超時、限流、鑑權失敗、取消、部分完成與成功無告警應分開；空清單不代表安全。長作業重用 Tasks 或供應方作業 ID，處理取消與幂等重試，避免重複計費。單純 diff 可能漏掉跨檔案問題，應帶必要上下文；若對方只接受整倉，上傳範圍與成本須重新確認。

外部報告不取得執行權限，修復仍走 Harness 原有工具。首版先由使用者主動調用，再啟用指定專案的自動策略。若要求未通過就禁止交付，需確認策略並接入既有生命週期，不能只靠提示詞。本輪不變更公共協議或完成語義。

## 6. 資料與驗收邊界

排除無關目錄、快取、真實憑證及越界連結，以合成密鑰測試偵測。需確認接收方、保存期限、訓練用途、刪除方式和商業許可。本機 CLI 仍可能呼叫雲端模型。

官方 Cloud 隱私協議（標示 2026-09-26 更新）說明雲端處理專案資料、可能轉送相關上下文至模型供應商，資料一般留存至刪除或帳戶移除，部分備份另有有限保留期。這是條款陳述，尚未獨立驗證；商業審計 API 條款仍待確認。[來源](https://secvibe.gcsa.com/privacy/zh-CN/)

實施順序：取得接口文件與測試額度 → 隔離樣例完成審查/修復/複查 → 工具與產品接入 → 大專案、斷線、取消及去重驗收 → 確認自動策略。使用漏洞、已修復版本及無漏洞對照，核對位置、證據、誤報、跨檔案能力、功能回歸、耗時及費用。具體排期在最小驗證後評估。
