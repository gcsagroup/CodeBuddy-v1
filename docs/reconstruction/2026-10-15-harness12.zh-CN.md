# Harness 12：冷启动与模型容量切换

来源：D:\CodeBuddy-v1，main / 01610d03764570282eee439cd2bfb49fcd373e98，加既有及本轮未提交修改。未新建分支、提交或推送。

## 已证实原因

1. ChatInput 的旧前端初始值为 128000；还有环境预定义、canonical、全提供商 known_models 和固定值四级决策。backend canonical 接口竟始终返回 null，导致输入栏额外查询所有提供商。128k 闪现是这条适配链的缺陷，并非 Harness 正在把模型容量从 128k 扩容到 1M。
2. Harness Host 被推迟到第一次发送时才激活；扩展列表和会话准备反复解密同一配置，Windows PowerShell 子进程开销进入首轮关键路径；所有提供商列表读取还触发各服务元数据联网请求。
3. 旧安装版 37.029 秒样本中，本地准备 25.359 秒、模型请求至正文 2.682 秒。历史日志未细分本地阶段，不能反向宣称已查明该次每毫秒的原因。新增阶段测量后，另一真实 Gemma LAN 冷进程样本本地准备 13.419 秒，其中 Host 6.006 秒、扩展 3.072 秒、路由 2.896 秒（前三者并行）、选项 1.242 秒、原生会话 6.134 秒；exa MCP 握手 4.836 秒。模型首正文 6.730 秒。其跟进轮正文延迟仍含模型思考，应与本地准备区分。

## 修改边界

- runtime/server.mjs：已配置模型的桌面启动后立即异步激活官方 Host；就绪端口不等待 Host，且不创建会话、不发送模型请求、不执行 MCP 动作。仅浏览无模型的导入历史仍不激活运行时。
- runtime/settings.mjs：在设置 owner 生命周期内缓存当前扩展定义，配置变更即失效、失败不缓存，向消费者返回深拷贝；不做全局明文缓存，不改变磁盘加密格式或权限。
- runtime/providers.mjs、runtime/compat.mjs：canonical 返回所选模型的同一容量解析结果，普通 inventory 只读本地列表；一次路由准备中的凭据解析合并。保留每个准备阶段耗时，不记录密钥、提示词或端点。
- useModelCapacity.ts、ChatInput.tsx：删除前端固定容量及多源裁决，等待后端期间显示未知，结果绑定提供商/模型/运行时容量提示，旧选择晚到的结果失效。未知容量不触发压缩警报。ContextWindowIndicator.tsx 保持原布局。
- 执行、调度、原生 MCP 注册表/作用域、token meter 与 compaction 仍归 Harness。Electron/ACP、用户配置、凭据、历史迁移、MCP Apps/图像兼容与独立工具适配保留。未宣称仓库中所有旧 Rust 文件均删除；独立 goose MCP 工具不承担 Agent 执行循环。
