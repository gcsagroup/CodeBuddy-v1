# 可選 Hindsight 記憶索引

本地 Project Memory 是記憶內容、來源、審核、有效期和刪除狀態的唯一管理入口。Hindsight 僅提供語義候選排序；桌面狀態、權限、任務進度及完成回執不屬於長期記憶。

## 啟用

預設關閉。管理者可在後端啟動環境或本機設定加入 `CODEPRO_HINDSIGHT_URL=http://127.0.0.1:18988`，重新啟動後端。此版只接受不含認證資訊、查詢參數或子路徑的 loopback HTTP 根位址；不支援遠端服務。清除此設定即可停用。設定頁目前沒有獨立開關。

Hindsight 需啟用 `create_bank`、`list_documents`、`delete_document`、`sync_retain`、`recall` MCP 工具。宿主透過 `/mcp/` 建立自己計算的 bank，其餘呼叫固定在 `/mcp/{bank}/`；模型不選擇 bank。每個正規化專案目錄及本地記憶配置目錄組合使用獨立 bank。

服務應自行維持僅本機監聽。啟用即允許將本地有效的專案記憶交給該服務建立索引；Hindsight 若使用雲端抽取模型，內容也會送至該模型供應商。請按自己的資料要求配置服務。此整合不複製模型金鑰。

## 執行方式

- 寫入先提交本地；專案記憶寫入、編輯、刪除與搜尋會觸發背景對帳。使用者範圍的偏好不會複製到專案 bank。
- 背景工作比較外部文件與本地當前版本，刪除舊版本並補入缺少的版本。同一專案的背景工作合併執行；失敗每 30 秒重試。後端關閉後停止，下一次記憶操作重新對帳。
- 搜尋保留本地精確文字結果，再補充語義候選。網路查詢預算 1.5 秒；服務故障時重新讀取本地結果並回報降級。
- 命中必須對應本地當前有效記錄的 ID 與完整版本指紋。返回給 Agent 的正文來自本地。被刪除、過期、證據失效或已更新的版本不會復活。
- 語義相似不代表能回答問題。沒有足夠依據時應回答未知；不自動執行成本較高的 `reflect`。

## 邊界

首次背景索引尚未完成時，語義候選可能不完整。外部服務離線時，本地刪除立即生效；外部副本須待服務恢復且背景對帳成功後才刪除。停用整合不會清除外部資料。移動專案目錄或更換本地配置目錄會使用另一個 bank，舊 bank 的清理應明確指定。

目前只增強明確的記憶搜尋；任務開始時原有的有界本地記憶注入維持原行為。外部 MCP 的只讀工具可以按需隱藏定義，但執行校驗使用當前有效目錄，並保留宿主明確拒絕。

## 驗證入口

在目前開發 worktree 執行 `cargo test -p goose --lib project_memory --jobs 1 -- --test-threads=1` 及 `cargo test -p goose --lib read_only_analysis --jobs 1 -- --test-threads=1`。依 README 維持既有 toolchain 與環境。

真實 Hindsight 回歸為 `hindsight_live_roundtrip_update_delete_and_isolation`，預設忽略；明確允許本機模型費用和合成測試資料後，以 `cargo test -p goose --lib hindsight_live_roundtrip_update_delete_and_isolation --jobs 1 -- --ignored --test-threads=1` 執行。預期服務位於 `127.0.0.1:18988`。

2026-09-30 已使用本次重建後端與 Kimi 完成真實儲存、新對話改寫查詢、續聊未知項及 Hindsight 離線回退驗收。會話最終狀態均為 finished，並核對本地記錄、實際工具回執與使用者可見回答。真實服務回歸另涵蓋更新、過時版本拒絕、隔離與刪除同步。

範圍限制：僅少量合成案例，不代表所有模型均通過；自然語言刪除/清空的完整會話尚未驗收。檢索呼叫約 40–195 毫秒，離線回退約 1.55 秒；完整任務仍包含模型等待和完成核驗，本輪出現過超過兩分鐘的模型等待與兩次預檢暫時不可用。

參考：[Hindsight MCP 官方文件](https://hindsight.vectorize.io/developer/mcp-server)。

## 本次配套修復

只讀續聊的執行權限依目前有效工具目錄判定，按需隱藏定義不再誤當撤銷工具；明確拒絕仍保留。記憶任務維持 8 輪上限，最終回答保留 1 輪，避免沿用開發任務保留 5 輪而在第 4 輪過早移除工具。任務協定的 inspect 及格式錯誤回執提供參數結構範例；模型仍須選擇真實來源與證據，宿主不自動補齊或接受錯誤欄位。

純記憶工作使用既有 ToolAction 任務類型，不再被 SimpleChange 的工作區檔案差異門檻攔截。完成時仍核對有效需求版本、具體記憶目標和記憶模組回執；同一記憶回執不能證明另一條記憶或檔案已交付。
