## 3. 清单标记

- **保留**：当前已有机制保持唯一入口，不从远端覆盖。
- **提取**：GitHub 独有实现为主，适配必要接口；不代表已确认可以零修改搬入。
- **重接**：保留功能需求或底层实现，但授权、生命周期、持久化和消费者使用当前链路。
- **排除**：不属于本次移植，或与已批准边界明确冲突。

## 5. 关键冲突的处置规则

### 5.1 只保留一个业务控制入口

Main/Worker 提出动作；当前 Tool/Permission 校验身份、授权和参数；绑定的 Runtime 执行动作准入与停止约束；Computer 适配器验证窗口、焦点、截图和输入锁；驱动执行并返回事实；现有证据/恢复/ACP/UI 消费结果。

Runtime 的现有准入在有 durable 绑定时生效，不把当前 `Option` 路径假定成全覆盖。实施须覆盖实际启用的 Main 与 Worker 入口，避免通过构造无绑定 ToolCallContext 绕开准入；不为本次移植强制所有历史会话迁移成新 run。

### 5.2 三层结果分开，不新增平行状态机

| 事实 | 谁提供 | 不能推导出什么 |
| --- | --- | --- |
| 请求被拒绝、未派发，或驱动确认已派发 | 工具边界/驱动回执 | 已派发不等于页面效果正确；失败响应也不必然等于没有副作用 |
| 后置条件匹配、不匹配、不可判断 | 绑定同次动作的观察与验证 | 观察成功不自动结清任意旧未知动作；目标变化不自动证明精确文本正确 |
| 用户要求是否完成 | Main 语义提议 + 当前宿主证据与终态门槛 | 工具 success、输入动画、视觉模型描述都不能直接提交完成 |

远端 `input_dispatched`、`postcondition_not_met`、`ambiguous_effect` 等必须有完整的生产者/消费者映射。若需要新增公共字段或持久化语义，S2 前提出最小版本化合同、缺省/旧数据行为与回滚边界；本清单不预先批准任意新枚举。

### 5.3 不自动重放未知输入

- 同一次动作只能选择一个执行器。输入前已确认“不支持”可以走明确能力分流；输入后超时、断连或结果不明，不改用原生实现再执行一次。
- 远端通过特定错误文本判定 session ended before dispatch 并重试一次。必须核实固定驱动版本是否保证该错误在输入前发生；未取得依据前不启用有副作用自动重试。
- provider generation、窗口/进程、snapshot 失效后重新观察；重连不能让旧截图凭据复活。
- 当前 input lock 只解决资源互斥，不等于任务授权或暂停检查。等待锁/审批期间状态变化后，执行前必须再次核对适用的授权、取消和目标状态。
- 取消前已派发的动作不谎报“未执行”；停止后禁止新派发，已有不确定结果保留并交接。

### 5.4 当前配置与用户数据优先

- 视觉路由以 GitHub 能力为来源，但不能恢复远端“停用清空/拒绝保留组合”语义，也不能丢失 Main。
- 不内置启用组长内网地址作为未配置用户的截图接收方。无有效路由时报告不可用，或仅使用已允许且实际可用的其他感知方式。
- 旧记录保留原值，不根据新截图、最近消息或 HTTP/窗口可见性补造旧操作成功。外发未知检查点的隔离范围须明确，不能通过换目标绕过未解决的发送风险。
- 视觉结果始终是不可信观察；既不能提供授权，也不能把屏幕上的指令提升为用户要求。

## 6. 分阶段边界与放行条件

### S0：清单与验收边界（本轮）

交付本文、固定来源、职责取舍、分阶段验收和剩余调查项。只检查文档内容、链接和差异；不构建，不声称功能已移植。

### S1：可受控使用的驱动与基础操作

范围：C01–C06 的必要部分、I01–I04/I07 的必要接入、I10 的必要资产合同。先用假驱动验证，再在后续获准的真实桌面环境验证观察/截图/输入/停止。

第一批不是“裸驱动”：当前授权、只读约束、操作方式限制、取消、输入锁、审计和不重放未知副作用必须同时成立。尚未完成结果映射的动作不能对用户开放。验证范围内采用已有可表达的回执，不先公开新语义再等待 S2 修消费者。

本阶段不新增视觉模型配置，不启用新的免确认发送，不新增文档追加/文件重命名行为。未移植的已有功能保持原策略；若驱动路径会影响既有消息发送，必须证明不回归，否则阻止该路径启用，不能静默退化安全。

放行：A01–A08；不存在暂停/权限旁路、重复输入或已有工具回归。阶段可供隔离验收，不等于完整 Computer Use 已交付。

### S2：证据、恢复与用户反馈闭环

范围：C07、I05/I06/I09，以及 S1 中相关边界的完整消费者接入。保留当前运行归属，完善已派发/已验证/未知的消费，不移植旧任务状态裁决。

放行：A09–A13 和受影响的 A01–A08 回归。模型拿到明确失败性质和有权限的下一步；无安全恢复路径时诚实停止交接，不能无限猜参数或重复点击。

### S3：视觉辅助与配置兼容

范围：C05/C09/C10 的相关能力、I08。先确定当前配置 + 视觉字段的兼容增量，再实施。共用现有 provider 调用能力，明确额外请求的预算、取消和使用量归属；不带入完整旧 Agent Loop。

放行：A14–A16，以及受影响的基础输入/停止回归。视觉失效不能扩大授权、改变图片接收方或阻塞为不可停止的长请求。

### S4：高影响业务动作与综合验收

范围：C08/C11；按消息发送、文档追加、文件重命名分别组织验收，不用其中一项通过代表全部通过。

放行：A17–A20，加各阶段仍适用的关键门禁。真实发送只对明确批准的测试账号、联系人和正文执行；没有批准则自动夹具可测、真实外发标 NOT_RUN，不操作真实业务对象。

阶段通过后可继续已获准范围内工作，不要求每个普通步骤反复审批；新安装、真实外发、数据迁移或职责变化仍按仓库规则单独授权。非阻塞体验改进进待办，不为追求无限覆盖扩成长周期重构。

## 8. 验证、证据与回滚

### 8.1 验证入口

- 文档阶段只检查内容、路径/锚点和 diff；不编译产品。
- 实施阶段依据 [README](../../../README.md) 和相应组件规则选择受影响目标。Rust 先格式化，相关测试集中执行，交付前运行适用 Clippy；只改 UI 不默认编译 Rust。
- 优先复用来源的 `crates/goose/tests/computer_provider_cua.rs`、现有 `codepro_computer_tools.rs`、消息循环夹具及当前权限/Runtime 测试。来源测试里“应免审批”“worked”等期待也要按当前合同审查，不能无条件沿用。
- 源码启动沿 README，在 `ui/desktop` 执行 `corepack pnpm run start-gui`（已安装替代入口按 README）；不另造构建入口。准备平台资产会触发下载时，先核对安装授权，不以“构建需要”为理由自动执行。
- 不并发多份 Rust 编译，不每阶段重复全量测试；修改后重跑受影响目标，综合交付再覆盖跨层边界。真实 E2E 必须使用含本批改动的既有工作区。

### 8.2 最小交付证据

每个阶段记录：接收方 revision + dirty 源码清单、来源固定 SHA、实际改动/排除项、命令与退出码、未执行事项。运行证据尽量复用原工具审计、会话和 Runtime 记录，不另造证据数据库。

动作链需能关联业务 session/run/task（适用时）、request/attempt、真实权限结论、驱动 generation、窗口/截图、派发和观察结果。前端状态、后台回执与最终产物交叉核对。日志不保存凭据或整段聊天/截图内容来代替最小关联信息。

实机阶段固定候选后端/驱动身份。报告分别写清：静态审查、自动测试、构建、E2E-ready、真实产品验收；组长的历史验收或另一工作区旧二进制不能替代本次结果。

### 8.3 停止与回滚边界

- 出现越权输入、重复外发/输入、误覆盖数据、停止失效或任务归属混乱，阻止该能力放行；不能靠隐藏错误或放宽门槛继续。
- 发现必须更换 owner、新持久化语义或扩大安装/数据范围，停止相关切片并提交具体设计增量；不受影响的已授权工作可继续。
- 回滚先阻止新输入并处理当前在途动作；不能承诺撤销已经发生的桌面副作用。
- 后续按独立行为提交，回退仅针对本批已明确归属的变更，不 reset/覆盖现有 dirty 工作，不删除会话、检查点或未知结果。
- 配置迁移必须有可恢复备份/兼容方案后才写新格式；旧客户端不能读取时明确阻止或提示，不能静默清空。回滚代码不等于已经回滚数据。

## 9. 实施前仍需逐项查清的技术问题

这些是有边界的调查，不是要求用户代替工程判断，也不意味着重新批准整个架构。

1. **CUA 与原生执行器分工**：逐工具列出支持/不支持、前台/后台输入行为及无标题窗口例外；选择在输入前完成，不做输入后的隐式重试 fallback。
2. **重连和停止证据**：确认固定驱动的 ended-before-dispatch 保证、取消响应、MCP 关闭与进程退出关系；没有证明就不自动重放或宣布已停止。
3. **动作结果映射**：确定远端新增回执如何进入当前 audit/evidence/完成检查/UI；复用现有状态，必须新增的字段单独走版本与兼容审查。
4. **主 Agent/Worker 入口覆盖**：检查当前无 durable scope 路径、嵌套调用、等待锁后检查，以及全局模块关闭与任务局部停止的交互。
5. **视觉配置迁移**：当前 v1 扩展与远端 v2 的读取/保存/降级矩阵；不预设采用远端原始 v2 即可兼容。
6. **发送与对账存储**：核对已有 message effect ledger 的 owner/绑定、旧 unknown 读取和终态提交，不并行创建第二套消息效果账本。

默认实施方向：先 S1，再 S2，再 S3/S4；不附带新自动发送政策、不启用固定内网视觉服务、不带入无关 Git/搜索功能。上述技术调查若证明某一默认方向不可实现，先报告具体证据与替代边界。
