# 工具会话授权

浏览器控制、图片生成、视频生成、桌面宠物制作和项目记忆共用现有授权卡片：拒绝、仅此次允许、本会话允许此工具。按钮由运行时返回的可用操作决定；前端不自行授予权限。

会话授权只覆盖当前对话中的具体工具，不授予其他工具或其他对话，不保存为全局允许。下一轮重新配置同一个工具时保留授权；移除工具、更换工作区、服务地址或执行归属后重新确认。程序重启后重新授权。项目记忆仍须单独审核候选内容，宠物仍须由用户选择启用。

MCP 工具列表刷新时，同一连接中定义、参数结构和元数据均未变化的工具保留授权。工具变化、移除或重新连接会使旧授权失效。

本地 MCP 服务由当前会话持有；仅更新提示词、模型上下文等配置不会重启配置未变且健康的服务。改变命令、参数、环境、工具过滤条件或停用服务会释放旧连接和授权。显式释放会话能力也会清除原生网页及内置工具授权，重新启用时重新确认。

`list_mcp_resources`、`list_mcp_resource_templates` 和 `read_mcp_resource` 按当前对话、具体工具及服务连接分别授权；列出资源不等于允许读取，更换服务不继承旧授权。图片与视频的 `inspect` 与同一工具的生成操作共用服务授权，查询旧地址的任务仍单独确认。

## 全入口检查范围

| 入口 | 行为 |
| --- | --- |
| 右侧浏览器、图片、视频、宠物、项目记忆 | 会话授权；候选记忆审核和宠物启用仍独立 |
| MCP 工具，包括独立浏览器、用户浏览器、电脑操作、时间天气、PDF、图表及外部服务 | 共用 MCP 授权入口；具体工具标记为破坏性时逐次确认 |
| MCP 资源列表、模板列表、资源读取 | 按工具与服务连接进行会话授权 |
| `web_fetch` | 按站点进行会话授权，保留原生网络边界 |
| `read`、`read_image`、`glob`、`grep`、`skill`、依赖路径查询、Git 的十个只读工具 | 已有只读规则决定放行，通常无需授权卡片 |
| `write`、`edit`、`pwsh`／`bash`、切换工作目录 | 原生沙箱决定执行及逐次提升，不用整类工具授权绕过边界 |
| Git 的十个写操作 | 现有破坏性标记与逐次确认；恢复、推送、终止冲突仍校验预检回执 |
| 提问、退出计划模式、目标、待办、后台任务、子代理控制、工具发现 | 各自原生状态机与归属校验，不把用户回答或控制操作替换为工具授权 |

本表覆盖当前源码的注册路径和公共审批入口。第三方服务的工具列表会动态变化，公共回归使用隔离 HTTP／stdio 服务验证授权，不执行所有第三方真实副作用。

明确设置为每次询问、触发额外安全确认，以及标记为破坏性的 MCP 工具仍仅提供单次确认。原生命令继续遵循 Harness 的沙箱与审批规则。明确禁止或禁用工具始终优先于已有会话授权。
