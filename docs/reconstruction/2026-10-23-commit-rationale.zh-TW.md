# CodeBuddy：逐提交修改說明與原因

## `6491d44` — 安裝包與原生工具修正

**改了什麼：** 調整 Windows 安裝/卸載進度、詳情與排版；將 `UsePreviousAppDir` 設為 `no`，預設目錄恢復 `%LOCALAPPDATA%\Programs\CodeBuddy`，仍可手動選擇。完善 macOS DMG 布局、簽名與架構檢查、已執行工具的替換、Keychain 自檢，以及電腦控制的視窗位置和按鍵處理。

**為什麼改：** Windows 並非把 D 槽寫死在預設配置，而是安裝器繼承了舊位置。因此修正的是路徑繼承，不是移動原始碼、改變建置暫存目錄或遷移資料。Mac 存在同名舊掛載卷時，Finder 布局可能失敗，因此改為操作明確建立的 Finder 視窗。其餘原生工具調整用於檢查實際簽名、架構和憑據存取，並讓視窗移動後的位置可核驗；螢幕位置與視窗內輸入座標保持區分。

## `11e8c28` — Harness、瀏覽器、模型預設與桌面互動整合

**改了什麼：**

- 接入 `/goal`、`/plan`、目標編輯與計畫審核，執行、壓縮與完成仍由官方 Harness 管理。
- 新增會話綁定的內建瀏覽器、Playwright 入口及電腦操作技能；首輪提供權限允許的寫檔、編輯及瀏覽器工具。
- 截圖經官方附件入庫並保存持久參照；觀察失敗時保留已執行動作回執。
- 新安裝提供 LAN 與 Ollama Cloud，統一預設來源，保留既有配置及使用者刪除預設的選擇。
- 優化長程式碼串流、工具參數狀態及檔案卡片；增加寵物新對話、附件和任務提示；精簡設定入口並保留舊資料位置相容性及卸載資料邊界。

**為什麼改：** 實際驗收曾出現只輸出程式碼未寫檔、寫完仍請使用者儲存的情況，因此增加首輪工具並要求依真實回執報告結果。模型仍負責判斷使用者是否只要範例，不以關鍵字強制寫檔，也不略過權限過濾。

原先截圖未經官方附件入庫，導致下一次模型請求缺少 `attachmentId`，因此必須保留入庫與持久參照鏈路。動作執行與圖片觀察是不同事實，觀察失敗不應抹掉已執行回執，以免重複點擊或輸入。

長程式碼反覆高亮是已重現的效能開銷，因此串流與超過 8000 字元的歷史程式碼使用完整純文字，保留複製與捲動；布局更新合併至動畫幀。參數生成單獨顯示，避免被誤認為工具已執行。

雙預設讓新使用者安裝後能選擇 LAN 或 Cloud；只在首次初始化套用，避免覆蓋舊設定。Cloud 首項改為實測 `kimi-k2.6`，因為 `kimi-k3` 空正文已直接 API 重現，並非應當修補的前端顯示問題。共享 Key 的分發檔由 Git 忽略，拉取原始碼不會自動取得。

目標、計畫、寵物提示與完成狀態使用 Harness 或會話的真實狀態，避免不同介面各自推斷。儲存目標不等於執行，重啟不自行恢復長期目標，點擊跳轉不等於已查看。移除遷移設定入口仍須保留既有資料位置讀取，避免已遷移使用者啟動後讀到錯誤目錄。

## `7ebdfcc` — 三語合併交接與驗收說明

**改了什麼：** 新增簡體、繁體、英文交接文件，整理範圍、關聯檔案、依賴版本、建置方式、憑據交接與驗收限制；為舊階段紀錄補充最新狀態。
