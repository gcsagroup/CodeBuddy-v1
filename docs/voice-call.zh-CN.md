# 电话页：GemmaE2B → QwenTTS

当前电话页已替换 Haru。链路为本地采音和停顿分段 → GemmaE2B 原生音频理解及文本流 → QwenTTS 流式 PCM → 浏览器播放，不经过 ASR 转写服务，也不进入 Agent 工具执行。

## 使用

主对话右上角电话按钮打开右侧通话页。选择智能体后开始通话，系统使用所选名称和完整人设。人设不通过关键词提取或猜测性别等信息；音色使用已部署 TTS 默认值，本版没有音色配置界面。

正常说话并停顿约 650 毫秒后提交这一句。持续噪声影响停顿检测时，可以点击“说完了”。本地保留约 300 毫秒前导音频，检测约 160 毫秒持续有声后进入发言状态；单段约 14 秒自动结束，服务端上限 15 秒。此为能量型检测而非神经网络 VAD，轻声、嘈杂环境和外放回声仍需真实麦克风验收。建议使用耳机。

Gemma 文本增量显示在固定字幕栏，首段达到标点或约 8 字后送 TTS，后续约 24 字或标点分段。TTS 单槽串行合成，文本生成与合成重叠。字幕按本次回复更新；新发言会中止旧生成并清空未播放音频。静音会丢弃尚未提交的本地录音；挂断释放音频设备、播放节点和网络请求。

## 服务与边界

- Gemma：`http://192.168.50.231:8001/v1/chat/completions`，模型 `gemma-4-e2b-voice`。直接上传 `input_audio` WAV，关闭 thinking，只消费 `delta.content`。
- TTS：`http://192.168.50.231:18004/v1/audio/speech`，`stream: true`。响应为 NDJSON，`chunk.audio_b64` 是 24 kHz、单声道 PCM16，结束事件为 `done`。
- `/voice-call` 复用本地运行时密钥认证。`runtime/voice-call.mjs` 拥有逐轮请求、取消和流式转发；前端 `VoiceCall` 拥有麦克风、停顿检测、播放和 UI 回调；`UtteranceCapture` 仅判断音频边界。
- 轮次编号隔离迟到回复；关闭连接中止两个服务的在途请求。TTS 返回 429 时只在尚未接纳的请求上短暂重试，最多约 2 秒，不重复已接纳的合成。
- 当前 Gemma 部署为 2048 context、每请求最多一段音频。通话内保留多轮文字记忆，随当前原生音频和完整人设一起发送；不持久化，挂断或重新接通后重新开始。超出服务上下文仍会显示本轮错误，不静默截断人设。
- Haru 的历史实现和实验记录见 `haru-voice-call.zh-CN.md`，不代表当前执行链路。

## 通话记忆：第一版滑动窗口

按用户最新要求，撤回逐轮 Harness 压缩接入，当前不发送摘要压缩请求。当前发言仍作为原生音频直接交给 Gemma 生成回复，再流式调用 TTS；回复音频合成完毕后，使用同一 Gemma 做一次简短原话转写，仅用于后续历史窗口，不改变当前回复的原生音频输入链路，也不需要新增服务。

窗口保存最近三轮用户转写和助手已生成文字，加上当前音频发言。历史文字总预算为 1200 UTF-8 字节，超限时从最旧完整轮次开始淘汰，不截断当前发言或人设。预算是针对当前 2048 上下文部署的保守窗口限制，不等于精确 token 计数。超长单轮可能不进入后续窗口；窗口外信息会遗忘，没有长期或跨通话记忆。

下一轮等待前序原话转写完成以保证发言顺序；已生成文字不保证已经播放。打断后保留已提交用户发言，取消旧回复生成和播放。后台转写失败只记 `[voice-memory]` 日志，该轮用户内容标记为未知，不向前台弹错、不挂断。挂断取消在途转写并释放窗口，每个 WebSocket 独立持有内存，不写主对话历史或磁盘，不触发 Agent 工具。

真实服务四轮测试使用完整 Sandrone 人设：告知“猫叫豆包，三岁”→追问→纠正为四岁→再追问，最终回答“名字是豆包，现在是四岁”。第四轮提交录音到首 PCM 为 2.27 秒；使用合成语音经过项目 WebSocket 链路，不代表真人麦克风端到端延迟。直接拼接历史音频方案因实测模型混淆历史和当前问题而未采用；此前逐轮压缩方案因连续追问延迟过高而撤回。

最终滑动文字窗口版本四轮首 PCM 分别为 0.96、2.23、2.42、2.27 秒（后续轮次含前序转写等待）。最终电话页浏览器测试通过，提交 WAV 到首音频排入播放约 1.14 秒，覆盖完整播放、字幕、静音、挂断和重连。以上均是小样本合成语音测试，不是 P50/P95，也不替代真人麦克风验收。
