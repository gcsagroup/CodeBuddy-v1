# 运行提示与模型选择

这是本轮运行情况的提示，不是模型评级、任务失败判定或新的 Agent 执行核心。截图仅参考卡片布局，未推断 Codex 私有触发逻辑。

## 触发与交互

| 已观察到的事实 | 默认显示条件 | 提示方向 |
|---|---|---|
| 请求在连接或等待内容 | 本次请求 90 秒 | 服务忙碌或连接延迟，不能据此判断模型能力 |
| 正在接收本次模型生成 | 本次请求 180 秒 | 可等待、换模型或降低思考强度；不宣布失败 |
| 工具回执连续未成功 | 3 次 | 先检查参数、权限和环境，不归咎模型 |
| 响应格式/空响应/截断等恢复 | 3 次且无成功工具回执 | 模型或服务格式可能不适合本任务，可尝试其他已配置模型 |

等待审批、运行工具、压缩上下文、子任务与取消期间不显示此卡。一次请求结束或工具实际启动时清除生成计时；成功工具回执清除失败计数。HTTP 与网络失败保留现有连接诊断，不计为模型响应恢复。计数是观察事实，不是“任务无进展”的语义裁决；只读检查成功也会清零。

“继续等待”只隐藏当前轮次的卡片，不发请求。新轮次可重新提示。关闭应用或重载后不保证保留隐藏选择；不持久化模型评分或用户偏好。“停止并选择模型”先通过原有取消控制器停止，收到空闲状态后打开已有模型选择器；不自动选择、重发或改写任务，不删除文件。切换聊天会取消待打开选择器的 UI 请求。

## 实现边界

- `runtime/harness/driver.mjs` 消费已有 `commandEvidence/hasFailedCommand` 的进程失败事实，只补充工具回执显示元数据。
- `runtime/work-status.mjs` 持有本轮临时观察计数和请求开始时间，经既有 `execution_activity` 状态消息发送。无定时网络请求、额外模型评分、权限或完成状态改动。
- `chatSessionStore` 校验可选字段及所属聊天/轮次；旧客户端可忽略，旧服务缺字段则不显示对应提示，不迁移持久化数据。
- `useWorkStatus` 决定显示，`RunAdviceCard` 展示三语卡片；`BaseChat/ChatInput` 复用取消与模型列表入口。按本轮隐藏，不按模型名称硬编码。

## 公开方案比较

[OpenAI Agents SDK](https://openai.github.io/openai-agents-js/guides/running-agents/) 提供运行上限和独立错误类型；[LangChain 工具调用限制](https://reference.langchain.com/javascript/langchain/index/toolCallLimitMiddleware) 区分线程与本轮计数，并配置达到上限后的行为。本功能借鉴按轮次观测及错误分类，没有引入硬停止上限，不能把到达上限当成模型能力不足。

[Anthropic 长任务实践](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents) 强调跨上下文保留进展及验证实际结果。提示卡不能替代结果验证，也不能修复生成项目本身。

OpenAI Agents SDK 与 LangChain.js 的公开仓库均为 MIT 许可，本次查阅时公开文档与主分支可访问；本次仅借鉴设计，不复制代码、不安装依赖，也不替换已锁定的 DeepSeek Harness。直接导入另一套 Agent 循环会重复执行、取消和状态职责，因此不采用。

交付复核与独立验收已于 2026-11-10 按用户要求移除。此前多模型安装验收发现的功能缺陷、复核漏判和 Gemma 恢复问题仍需单独解决；提示出现不代表这些问题已修复。

## 请求失败与红色提示（2026-11-12）

Harness 的原生 `llm/retry` 表示仍在恢复，显示次数和等待时间；只有主会话原生 `turn/end` 明确以错误结束，才投影为本轮最终失败提示。子任务失败交由主 Agent 处理，不直接宣布整轮停止。关闭提示不代表请求恢复，发送“继续”也不能恢复服务额度。

错误判断与展示各有一个负责人：模型适配器/Harness 提供结构化错误并决定重试；`runtime/work-status.mjs` 将它投影为有界的用户提示；桌面消费既有 `execution_activity`，不解析服务商原文来二次判断额度、网络或执行结果。

| 已有事实 | 展示与恢复方向 |
|---|---|
| `QUOTA` / `ACCOUNT_QUOTA` | 账户额度不足或使用上限；检查余额与限制，恢复额度或换可用连接后继续 |
| `RATE_LIMIT` / 仅观察到 HTTP 429 | 请求受限；稍后继续，持续出现再检查请求限制、服务状态与账户额度。429 本身不能证明余额耗尽 |
| 仅观察到 HTTP 402，原生错误未知 | 服务要求处理额度或付费状态；不据此新增额度错误分类或修改重试策略 |
| HTTP 413 | 请求体过大；减少本轮输入、图片或附件，检查网关大小限制。不能仅凭 413 宣布 token 窗口已满 |
| 上下文/输出预算/响应截断 | 保留原生具体原因，避免笼统归为 HTTP 400 参数错误或 HTTP 429 限流 |
| 身份验证、访问权限、模型连接不可用 | 引导检查对应连接；不统一建议充值或重新发送整条任务 |
| 连接、超时、TLS 失败 | 仅使用结构化传输码提供方向，不把超时归因于用户网络，也不建议关闭证书校验 |
| 未知错误或 HTTP 200 后流式处理失败 | 明确未完成及未知范围，引导检查连接、服务和“查看未完成原因”；200 不等于完整生成成功 |

已知的原生语义优先于粗粒度 HTTP 状态。例如 `QUOTA + HTTP 400/429` 仍展示额度问题。HTTP 状态优先使用原生错误自带的值；否则补充同一主请求的失败观察，已带错误码时须与原生错误一致。压缩、图片识别、执行报告等带 `purpose` 的辅助请求，以及旧请求迟到的诊断，不覆盖主请求的错误、计时或重试提示。已经正常结束的模型响应不用于解释后续宿主错误；缺少可关联诊断时降级为已知原生事实，不拼接上一请求的状态。

最终提示给出“发生了什么、本轮已停止、下一步、详情入口”。不直接回显任意服务商正文，不宣称全部操作已保存、失败已回滚或可以无条件重试；已完成工作的事实仍以工具回执、文件和原生会话记录为准。完整服务错误仍在原有终结报告中，未新增诊断持久化或另一套恢复状态机。

### 公开实现的取舍

- [Codex 的错误类型与重试策略](https://github.com/openai/codex/blob/main/codex-rs/protocol/src/error.rs)：借鉴额度、限流、上下文和传输错误分开，以及界面信息有界；不推断其桌面私有逻辑，也不照搬供应商专用额度字段。
- [Claude Code 错误参考](https://code.claude.com/docs/en/errors)：借鉴重试过程与最终失败分开、同为 429 仍需区分使用上限与瞬时限流、提供对应恢复方向；不移植其网关降级和超时策略。
- [DeepSeek Harness 重试插件](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm-retry/README.md)：继续使用本仓库锁定版本掌握重试与取消，展示层不再套一层重试。用户显式选择的 `always` 策略保持原义；本批未升级依赖。
- [pi agent 会话执行链](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/src/core/agent-session.ts)：借鉴区分恢复中与最终稳定结束、上下文超限走压缩专用路径；不把另一套 Agent 循环接入当前 Host。

### 验证边界

`runtime/tests/work-status.test.mjs` 覆盖错误优先级、未知错误、辅助/迟到诊断隔离及现有子任务、取消、计时行为。`runtime/harness/test/recovery.test.mjs` 使用真实锁定 Harness 加本地可控 Provider，覆盖已写入文件后发生 400/402/429、原生有限重试、失败通知与恢复后沿用工具回执，确认显示变化不增发请求、不重复写入。受控 Provider 不能证明真实账号余额、任意供应商的分类准确性或同事旧安装包的故障原因。

### 社区反馈驱动的补测（2026-11-13）

下面的用户报告及评论作为风险线索，不直接当作本仓库缺陷；具体版本、环境和复现范围各不相同。

| 外部线索 | 本仓库的取舍与验证 |
|---|---|
| [Codex #46423 评论](https://github.com/openai/codex/issues/46423)：断流恢复后可能重复工具副作用 | 补测完整工具提案后的断流：完整响应确认前不能执行；原生重试完成后只执行一次。另保留“已完成工具后下一请求断流”的回归，校验真实回执进入续接输入 |
| [Claude Code #81330 评论](https://github.com/anthropics/claude-code/issues/81330)：显示次数与限额不符 | 仅消费原生当次次数/额度；无有效额度或次数已超过额度时只显示第几次，不造出 5/2。`always` 不伪造有限上限，实际退避仍可取消 |
| [pi #11016](https://github.com/earendil-works/pi/pull/11016)：图片较多时请求体过大 | 明确 413 与 token 超限不同；不移植 Copilot 专用错误匹配或自动压缩策略 |
| [pi #10996](https://github.com/earendil-works/pi/issues/10996)：认证刷新中的网络失败未重试 | 网络与认证由适配器分类；界面不因为发生在认证阶段就判密钥错误，也不扫描 URL、错误原文或请求 ID 决定重试 |
| [DSH #10512](https://github.com/deepseek-ai/deepseek-harness/discussions/10512)：超窗后摘要请求也超窗 | 保留当前分段/兜底压缩及目标窗口验收，重跑相关压缩回归；不在提示模块再创建恢复循环 |
| [Reddit 用户反馈](https://www.reddit.com/r/ClaudeCode/comments/1u964zh/constantly_hitting_api_errors_in_claude_code/)：半途断流与空响应难区分；[另一组评论](https://www.reddit.com/r/ClaudeCode/comments/1udf5c0/api_error_constantly_on_48/)反映重试提示停住 | 补测 HTTP 200 流内额度错误、ECONNRESET、证书错误、未知错误及非有限等待值；不把“持续显示重试”当作实际发出了下一请求，不照搬未经证实的换地区等建议 |

请求体大小的解释依据 [RFC 9110 的 413 定义](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.5.14)。本轮只提供对应恢复建议，未新增自动重发、副作用去重协议或供应商错误关键词表。

### 突发网络、设备及操作系统异常的边界

| 情况 | 现有负责人、处理与验证范围 |
|---|---|
| DNS、连接拒绝、超时、TLS、响应半途断开 | 适配器提供错误，Harness 负责原生重试与取消，提示层解释。覆盖真实本地断流、恢复、取消及结构化传输码；没有关闭网络或改系统代理 |
| 桌面连接中断 | Compat 保留已接纳执行，前端重连后加载同一会话及活动轮次，不重发原任务。`session-reconnect.test.mjs` 覆盖断连期间继续执行、补齐通知与重连后显式停止 |
| 休眠唤醒 | Electron `powerMonitor` 发出 `system-resume`，App 调用既有 ACP 重连。`App.test.tsx` 验证事件到重连入口；未真实休眠整机，不据此声称所有驱动、VPN或网络恢复时序均已验收 |
| 磁盘空间不足、I/O 错误、权限拒绝或文件占用 | Store 在队列内原子提交；临时 Windows 替换失败有界重试，非暂态错误直接上报并保留旧快照。日志存储失败保留可恢复 journal。`store-atomicity`、`session-persistence` 通过隔离故障注入及真实文件占用验证，不占满真实磁盘 |
| 保存或压缩期间进程被杀 | 原生日志/journal 持有持久事实；重新加载后恢复已提交数据、对账未结束维护操作，不自动重做工具。`session-persistence`、`compaction-acp` 使用隔离子进程实际 kill 后重启验证；不保证未写入磁盘的内容可恢复 |
| Windows 子程序 DLL 初始化失败 | 进程局部禁止阻塞的系统错误弹窗，保留真实退出状态，后续命令仍能执行。`windows-process-startup.test.mjs` 运行合成失败 DLL 与受限子进程，不改系统 WER 或安全设置 |
| 安装版后端意外退出 | `harnessService` 检测退出，主进程当前会退出应用并保留会话数据；需要重新打开，不是无感自动续跑。本批没有修改此策略 |
| 主聊天渲染进程崩溃/OOM、真实断电、整机蓝屏、硬盘损坏 | 不能依靠已经停止的进程显示红字。主聊天窗口未见完整自动重载策略；已有持久化恢复测试不等于这些真实整机事故验收，不作完全恢复承诺 |

本轮补测的基线限制：`history-replay-compaction.test.mjs` 有三项既有失败，精确帧数量/内容断言没有排除新增的 `session_info_update(activeRunId)`。使用 HEAD 的原版 `work-status.mjs` 在相同工作区通过临时模块解析替换复测，三项同样失败；本批不修改该无关测试或会话加载逻辑，也不把它们报告为通过。上述渲染进程及整机事故缺口亦未混入本次错误提示提交。
