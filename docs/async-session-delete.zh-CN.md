# 异步删除会话

2026-11-10 用户批准：确认删除只等待后端检查及小型删除记录落盘；成功后界面关闭确认框并移除会话。MCP 连接释放、关联自动任务停用、失败会话日志清理和完整状态文件整理在后台继续。工作区文件保留。

`runtime/store.mjs` 持有逻辑删除事实；`session-deletions/<SHA256(sessionId)>.json` 是唯一持久化删除标记，记录产品 ID、原生 ID 和接受时间，不复制消息内容。所有读取和后续提交都会屏蔽已删除记录。未能持久化标记时返回错误，前端保留会话与确认框。旧快照写入尚未完成时也不能使会话恢复。

`Compat` 在原会话锁内核对正在运行的任务、工具与后台进程；运行中仍拒绝删除。接受后资源清理按会话独立进行，失败记录保留并以退避间隔重试，重启时恢复。完成全部清理和状态刷盘后才删除标记。已接受的删除不因资源清理失败而撤销；后台错误写入运行日志。前端沿用原删除接口与成功通知，不需要长轮询，也不添加固定等待动画。

删除不会删除项目目录或扩大为清理全部原生归档的功能。恢复日志中属于已删除会话的未投影消息不会再次写回。没有引入云服务、数据库或新依赖。

兼容性：没有删除记录的旧 profile 直接加载，不改状态文件版本。若需要降级到不识别删除标记的旧版本，应先在新版完成清理；不要在仍有待清理标记时让旧版本打开同一 profile，否则旧版可能展示旧快照中的会话。正常新版本重启会恢复清理。

方案比较：纯前端隐藏无法保证刷新或重启后仍删除；仅将原请求放到后台不能解决确认时全量复制大历史的问题。本实现采用小型持久化标记与读取屏蔽，后台快照整理复用未修改会话的序列化缓存。参考 [Microsoft 异步请求模式](https://learn.microsoft.com/en-us/azure/architecture/patterns/asynchronous-request-reply) 和 [AWS 事务 Outbox](https://docs.aws.amazon.com/prescriptive-guidance/latest/cloud-design-patterns/transactional-outbox.html) 的持久化受理、幂等和失败恢复原则；未复制外部代码。现有 ACP 接口返回意味着逻辑删除已提交，后台资源回收可以尚未结束。
