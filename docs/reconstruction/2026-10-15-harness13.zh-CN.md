## 原因与修复

首轮等待包含会话准备、网络连接、服务处理、模型思考、正文输出。真实 Gemma 请求在约 0.74 秒收到思考增量，但约 11.97 秒才收到正文；这部分不等于前端没有流式输出。原 37 秒事件没有足够原始记录，未宣称找到其唯一原因。

已验证的本地开销：全局扩展已有权威配置，却重复解密会话中的历史定义；远程 MCP 初始化后才启动独立本地 MCP；每轮更新重写所有历史的 JSON 缩进；模型容量与远程 MCP 到首次发送时才准备。

修复：仅在未配置的会话扩展需要历史回退时解密；并行初始化两类 MCP，继续沿官方 AgentPresetRegistry 租约复用；状态文件使用紧凑 JSON，保留原子替换与失败回滚；启动时并行探测已配置模型的元数据、连接已启用的远程 MCP。启动准备不创建会话、不调用模型生成、不执行工具、不启动工作区相关 stdio 工具。设置变更仍走当前配置与连接指纹，不绕过权限。

## Harness 与旧核心

执行、调度、模型请求、目标续轮、压缩继续由锁定的官方 Harness 0.2.1-alpha.2 插件负责。[上游](https://github.com/deepseek-ai/deepseek-harness) 为 MIT 许可，当前处于开发预览；本批复用已安装版本，不升级依赖。

删除桌面 Rust 后端启动回退。安装包移除含旧 Agent 的 goose.exe，改为只链接 goose-mcp 工具依赖的 codebuddy-tools.exe。该程序仅接受三个 MCP 子命令；agent、serve、acp 均拒绝。二进制从 332,407,808 字节降至 41,534,464 字节。Rust Agent、Provider、ACP、调度器均不在工具程序依赖树中。

| 能力 | 当前所有者与迁移边界 |
| --- | --- |
| 文件、搜索、Shell、技能、子 Agent、任务、压缩 | 官方 Harness 插件 |
| 项目记忆存储 | Harness storage/domain，CodeBuddy 保留 UI 与召回适配 |
| 文档、PDF、表格、图表、时间天气 | 独立工具程序；复用现有实现，避免丢失工具合同 |
| 桌面识图与点击 | 保留独立 qwen-computer-use MCP 和已有视觉适配 |
| MCP Apps、历史、设置、权限投影 | 必要的产品适配，不新增 Agent 循环 |

旧 Rust 源码仍在仓库作迁移参考，本批是删除发行与启动依赖，不能称为整个仓库已无 Rust 或旧源码全部删除。文档工具需要在设置中启用；仅使用原生 Shell 生成 docx 不算文档 MCP 验收通过。
