## Important distinctions

The lease error checks persisted binding identity against the authoritative in-process lease. A stale state overwrite or concurrent recovery is a plausible investigation path, not a demonstrated cause. Do not delete the check or silently authorize a different directory. Preserve the user's pending draft and recover once only when directory identity and scope remain valid.

The history query currently examines text blocks in message JSON, not session titles. Consequently, having a search field does not mean title search works. The failure was observed using actual keyboard input in the native application, and the SQL corroborates the missing field.

Mouse observations expire after 30 seconds. PowerShell operations have a 20-second timeout. The audit deliberately encountered stale observations and a missing screenshot_id, then refreshed state, supplied the required arguments and obtained worked/isError=false with visible navigation. This proves low-level input, not autonomous completion of a WeChat task.

The current execution policy was LocalMachine RemoteSigned, and the computer scripts ran. No execution-policy bypass or system-policy change was performed. The original 32-action history was not provided as a trace. Existing retry handling reviews two failures and detects three failures for the same tool/argument fingerprint. Different screenshot IDs or command text can create different fingerprints; this warrants additional testing, but does not prove the historical root cause. Uncertain external effects must be observed before retrying.

The native autonomous-mode wording is misleading, but not every approval is erroneous. The registered local computer-action branch and scoped worker permissions need to be included in the policy explanation; a blanket rule that every application launch always asks would also be inaccurate.

Execution details already collapse and expand. The native audit confirmed technical titles, an expandable output section, existing task summaries and concise/detailed settings. Improve these surfaces rather than building a duplicate detail system. A file read should not be generically described as executing that file. User-visible progress should summarize verifiable actions, not expose private reasoning.

## Sequencing and public Codex comparison

Fix the clean-build blocker first, followed by computer-tool contract/retry handling and lease recovery, then fork capability gating, permission wording and title search. Refine narration and broader history management afterward. Each implementation needs focused automation and applicable real-product acceptance; unavailable services stay explicitly pending.

Published Codex documentation distinguishes technical access boundaries from approval policy and describes automatic workspace actions with additional approval outside that scope. Adopt clear scope and visible reasons; reject the assumption that autonomous means global approval bypass. CodeBuddy's actual policy still controls its behavior. [OpenAI: Agent approvals & security](https://learn.chatgpt.com/docs/agent-approvals-security)

The currently exposed Codex task tools also distinguish resuming a task from forking completed history. Adopt independent session/history boundaries without inferring private lease internals. Conditional state updates, normalized retry errors, search fields and narration changes are proposals derived from this project's code, not claims about Codex's private implementation.
