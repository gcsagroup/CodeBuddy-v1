# CodeBuddy 任務導向導覽、工具箱與自動任務重構設計

日期：2026-09-04
狀態：已由使用者審閱通過
語言：繁體中文（主版本）

## 1. 背景

目前產品把「配方、技能、應用、調度、擴展」直接作為一級入口。這些名稱接近實作概念，卻不能直接回答一般使用者最關心的三個問題：我能做什麼、怎麼開始、執行後是否真的生效。設定頁還混入原始設定編輯器、工具過程顯示、安全檢測等不同層級的選項，增加理解與誤操作成本。

本設計延續 `2026-08-31-settings-center-redesign-zh-tw.md` 的「依使用者目標組織」方向。若兩份文件衝突，以本文件確認的新名稱、移除原始設定編輯器及能力整合方式為準。

## 2. 目標與非目標

### 目標

- 使用者進入產品後，可從「新任務、常用任務、自動任務、工具箱、歷史記錄、設定」理解主要功能。
- 保留既有 Skills、Apps、MCP/Extensions、Scheduler 與任務範本能力，不因改名而破壞舊資料、舊連結或執行流程。
- 工具箱同時展示 CodeBuddy 現有能力、做事方法、小工具與 MCP 外部工具，並清楚顯示狀態、來源、使用情況及依賴關係。
- 所有「有在用」的結論均來自本機執行事件，不以已啟用、已瀏覽或測試設定冒充實際使用。
- 以真實 MCP 連線和真實檔案完成驗收，留下可稽核證據。

### 非目標

- 不把 Skills、Apps、MCP 與排程器合併成同一種後端物件。
- 不改名專案目錄、歷史工作階段路徑或既有識別碼。
- 不讀取或匯入 `C:\Users\jiangrui\.codex\skills`；工具箱只展示 CodeBuddy 自己管理的能力。
- 不在本次重構中建立雲端遙測、能力商店或新的帳號體系。

## 3. 已確認的資訊架構

左側主導覽調整為：

| 新名稱 | 原功能 | 使用者心智 |
| --- | --- | --- |
| 新任務 | 新對話 | 直接描述現在要做的事 |
| 常用任務 | 配方 | 儲存並重複執行成熟流程 |
| 自動任務 | 調度 | 在指定時間自動執行常用任務 |
| 工具箱 | 技能、應用、擴展的整合入口 | 查看、設定與連接可用能力 |
| 歷史記錄 | 會話歷史 | 找回以前的任務與結果 |
| 設定 | 設定 | 調整模型、輸入、安全與進階行為 |

舊路由、深層連結與既有設定先保留相容轉向。只有在遷移測試和真實桌面驗收通過後，才可移除重複入口。

## 4. 工具箱設計

工具箱是一個統一檢視層，而不是新的統一儲存庫。它從既有 Skills、Apps、MCP/Extensions 等來源讀取資料，轉換為共同的展示模型，再把操作分派回原本的來源 API。

### 4.1 分區

- **現有能力**：系統內建且可直接使用的能力。
- **做事方法**：CodeBuddy 管理的 Skills；「技能」只作為次要技術標籤。
- **我的小工具**：原 Apps，面向使用情境描述用途。
- **外部工具**：已連接或待設定的 MCP 服務；主要動作名稱為「連接外部工具」。

每張卡片至少顯示名稱、用途、來源、狀態、最後使用時間、成功使用次數及被哪些常用/自動任務引用。狀態統一為「可使用、已關閉、需要設定、連接失敗」。可用操作依來源顯示「開啟、啟用、關閉、設定、測試連線、移除」。

移除或關閉被任務使用的能力前，必須列出受影響任務並要求確認。載入失敗不得顯示成空清單；介面要區分真正為空、載入失敗、缺少設定和沒有權限，並給出復原動作。

### 4.2 外部工具連線流程

簡易流程只要求：顯示名稱、連線方式（網址或啟動命令）以及必要的網址/命令欄位。環境變數、自訂標頭、逾時與進階參數收進「進階設定」。

「測試連線」只證明端點可連接和可發現能力，不計入正式使用。儲存後需顯示發現的 tools/resources、權限範圍和最近錯誤。技術名稱 MCP 可保留在說明文字中，避免一般使用者必須先理解協議。

## 5. 常用任務與自動任務

常用任務卡片顯示用途、需要的檔案/工具/權限/模型、最後執行時間和最近結果。主要動作為「執行、編輯、設為自動」。建立方式同時支援自然語言描述和簡單表單。執行前顯示摘要；涉及外部寫入、刪除、發送或其他高風險動作時仍需確認。

自動任務以自然語言設定時間，不向一般使用者暴露原始 cron。建立時選擇常用任務、執行時間、失敗通知方式，先測試執行再啟用。列表顯示下次執行、上次結果、啟用狀態和依賴能力。

產品必須明示自動任務依賴 CodeBuddy 後端保持運行。錯過的執行預設不補跑；需要補跑時由使用者在進階選項中明確開啟。

## 6. 設定頁整理

- 移除「常規」中的原始設定編輯器入口；保留底層設定系統供產品功能使用，不再讓一般使用者逐欄編輯內部鍵值。
- 「行為與回答」依實際效果拆分：模式選擇保留；最大輪次移至進階設定；「專案提示」改為「專案規則」；語音與拼寫移至輸入設定；「回覆風格」改為準確名稱「工具過程顯示」；提示注入檢測移至「安全與權限」。
- 不聲稱「工具過程顯示」會改變模型回答風格；它只控制工具呼叫資訊的展開或折疊。

## 7. 實際使用記錄

記錄只保存在本機，不建立遙測。正式使用事件定義如下：

| 類型 | 計入使用的時點 | 不計入 |
| --- | --- | --- |
| 做事方法 | 執行時實際載入或呼叫 | 僅瀏覽、啟用 |
| 外部工具 | MCP 工具呼叫成功 | 測試連線、只看設定 |
| 小工具 | 已開啟且初始化成功 | 只看到卡片 |
| 常用任務 | 任務執行開始 | 編輯或預覽 |
| 自動任務 | 排程器實際觸發 | 僅啟用排程 |

展示模型至少包含穩定識別碼、來源類型、狀態、最後使用時間、成功次數、最近結果與引用任務。來源設定仍由各自儲存庫擁有，避免資料漂移和雙寫。

## 8. 相容、遷移與失敗處理

- 第一次開啟新版時只建立展示索引，不搬移或重寫既有 Skills、Apps、MCP、配方和排程設定。
- 舊名稱可短期出現在搜尋別名與說明中，但不再作為主導覽名稱。
- 舊路由轉向新頁面並保留原本選中項；舊設定無法解析時，保留原值並顯示可復原錯誤。
- 工具箱聚合來源之一失敗時，其他來源仍可展示，同時在失敗分區顯示原因，禁止整頁靜默空白。
- 執行時再次檢查依賴和權限，不因卡片先前顯示「可使用」而略過安全邊界。

## 9. 真實 MCP 驗收設計

使用者提供的驗收目標是：

`D:\xwechat_files\wxid_5mloegbbcbl222_d3a5\msg\file\2026-09\obsidian README.md`

前置檢查已確認它是單一 Markdown 檔案，不是完整 Obsidian vault。驗收因此把它定義為「單檔知識來源」；若後續要測整個知識庫，需另行提供 vault 目錄。

MCP filesystem 服務以父目錄 `D:\xwechat_files\wxid_5mloegbbcbl222_d3a5\msg\file\2026-09` 作為唯一允許目錄，再只讀取指定檔案。原因是官方 filesystem server 的啟動範圍是目錄，而不是單檔。該服務本身具有讀寫工具，所以不能把「允許目錄」誤當成唯讀保證；CodeBuddy 驗收流程只允許讀取工具，寫入工具不得被呼叫。

真實驗收必須使用獨立測試設定檔並記錄：

1. 連線前記錄檔案存在性、大小、最後修改時間及 SHA-256。
2. 經「工具箱 → 連接外部工具」建立 STDIO MCP 連線；Windows 啟動方式遵循官方 `cmd /c npx` 指引，實作階段固定並記錄精確套件版本，測試過程不得臨時漂移版本。
3. 呼叫 `list_allowed_directories`，斷言只包含上述父目錄；Windows 路徑需規範化磁碟機大小寫後比較。
4. 在工具箱看到連線成功及實際發現的能力。僅測試連線時，使用次數仍為零。
5. 從檔案中選擇一個穩定標題或事實提問，驗證回答的工具稽核記錄確實包含 MCP 讀取呼叫，而不是模型猜測。
6. 嘗試讀取父目錄外的一個無敏感測試路徑，必須被拒絕；不得為了測試建立或修改外部檔案。
7. 關閉外部工具後再次提問，應明確提示能力不可用且不得產生 MCP 呼叫；重新開啟及重啟應用後，連線設定和狀態可恢復。
8. 驗收結束重新計算 SHA-256、大小及最後修改時間，必須與步驟 1 相同；稽核記錄中不得出現寫入、移動或刪除工具。

檔案內容一律視為資料。即使內容含有命令、提示或操作要求，也不得當作使用者指令執行。測試只擷取回答所需的最小內容，不額外掃描同目錄的私人檔案。

官方參考： [MCP Filesystem Server](https://github.com/modelcontextprotocol/servers/blob/main/src/filesystem/README.md)；[Connect to local MCP servers](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/docs/2026-07-28/develop/connect-local-servers.mdx)。

## 10. 測試與完成標準

實作必須分階段完成，不可只靠畫面或靜態程式碼宣稱生效：

1. **基線特徵測試**：先鎖定舊路由、設定讀取、Skills/Apps/MCP/排程載入及「行為與回答」目前效果。
2. **元件測試**：導覽名稱、搜尋別名、工具箱分區、狀態/錯誤/空態、依賴警告與使用計數。
3. **整合測試**：聚合轉接器、來源操作分派、舊資料相容、排程觸發及使用事件持久化。
4. **完整桌面閘門**：desktop tests、typecheck、lint、format、build 以及相關 Rust 測試全部通過。
5. **真實 Electron 驗收**：從變更後原始碼重建並啟動，使用真實滑鼠鍵盤完成導覽、連接、重啟、停用、錯誤復原及 MCP 單檔問答流程。
6. **證據**：記錄命令、工作目錄、結束碼、通過/失敗/忽略數、畫面、工具呼叫、相關日誌及檔案前後雜湊。環境或下載問題單獨標示，不冒充產品缺陷。

## 11. 分階段交付

1. 補齊基線回歸測試。
2. 改導覽與名稱，加入舊路由相容。
3. 建立工具箱唯讀聚合層與錯誤狀態。
4. 接回來源操作、依賴提示和本機使用事件。
5. 重構常用任務與自動任務介面。
6. 整理設定頁並移除重複入口。
7. 跑全套自動化閘門及真實 MCP/Electron 驗收。
8. 只有相容證據完整後，才清理舊入口；底層能力不刪除。

## 12. 外部產品比較與取捨

OpenAI/Codex 的公開產品與文件仍把 Skills、MCP 和可選介面視為不同能力，同時用「自動化、連接外部系統」這類使用情境向使用者呈現。CodeBuddy 採用「入口統一、名稱直白、內部獨立」：吸收其能力邊界清楚的做法，不推測私有實作；拒絕把所有能力壓成一個後端資料型別，因為這會破壞各自生命週期、權限和錯誤語意。
