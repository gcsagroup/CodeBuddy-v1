# 工具箱与对话同步

## 扩展故障与预览版本（2026-11-07）

编辑旧外部扩展时，缺省的连接超时在表单内统一采用已有的 300 秒默认值，避免画面显示 300 而“测试连接”被空值校验禁用；明确的零或无效值不自动修正。打开或测试表单不写回用户配置。

失败通知按单个扩展记录最近结果；其他扩展变化、结果排序、切换会话和部分结果不会重复提醒未变化的错误。已确认恢复后再失败、或诊断发生变化会重新提醒。这个有界缓存只影响当前窗口通知，工具箱仍显示真实连接状态，不授予权限、不控制重连。

预览后台记录启动时 runtime 源码指纹，通过只读 `runtime/status` 提供运行身份及是否需要重启。桌面每 30 秒及获得焦点时检查，变化后提示等待任务完成再退出重启，不自动中断任务。指纹用于开发版本诊断，不是安装包签名或完整构建证明；依赖、工具二进制、测试和素材不参与扫描。启动器复用 SQLite 进程租约保护准备与运行期，已有后台时拒绝重复启动并保留原启动记录。

Scrapling 的依赖冲突应在独立 Python 环境修复，验证 `pip check`、真实 MCP 初始化、工具发现和相关调用后，仅替换该扩展的可执行路径。运行中的 profile 不允许被离线配置写入器覆盖；退出后持有原 profile 锁，备份配置，再通过现有 Settings 保存，保留参数、环境变量、启用状态和其他扩展。此次用户机器上的安装经过单独授权，不代表应用启动时自动安装依赖。

普通新对话跟随工具箱中当前启用的能力。任务执行期间保存技能、工具或 MCP 配置，不重建正在运行的作用域；下一条排队消息或下一轮发送在执行前重新读取当前配置。停用、删除的工具还受每次调用的当前策略检查约束。技能内容由 Harness 原生目录和内容版本负责，不能通过修改技能抹除模型已经看到的历史文字。

工具变更由后端在下一轮任务前自动应用。工具箱已移除顶部同步模式面板与卡片上的待同步提示。卡片继续提供连接结果和必要的操作反馈，状态来自同一后端快照。可见页面每三秒读取状态，连接检查沿用后端已有的执行中保护。

远端 MCP 按完整单服务器配置申请官方 Harness `agent-preset-registry` 租约，包括凭据、工具过滤及超时；最多缓存 64 个可复用配置。一个服务修改、失败或删除不重启其他服务。每个会话用原生 scope 投影自己选中的工具、资源和说明，不修改共享 scope 的继承关系。stdio 继续按会话和工作目录隔离。协议、任务、Apps、工具回执和授权仍使用现有适配；断线不自动重放工具动作。资源授权验证当前投影的工具定义，并绑定源连接的代次，重连后旧授权失效。

旧会话的名单来源不明确时保持自定义，不自动扩大权限。显式切换“跟随工具箱”后只使用当前全局启用项，保留旧名单及加密定义但不执行它们；切回“自定义选择”恢复原名单，并应用当前全局停用和删除策略。没有旧名单时，切换自定义会固定当前有效名单。删除标记阻止历史副本复活，显式重新添加才恢复对应名称。此过程不改写历史消息、不重放旧工具、不删除用户配置，重启后保持选择。

已移除整组 MCP 连接缓存入口和卡片独立查询/缓存工具数量的路径。Rust 独立 MCP 工具仍是有效能力，不属于本次删除对象。Scrapling 等外部进程的依赖损坏需要修复它自己的运行环境；状态同步与有界错误诊断不能代替依赖安装。

设计参考：锁定的 MIT、开发预览版 Harness 0.2.1-alpha.2 的 [preset registry](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/agent-preset-registry/README.md)、[MCP 生命周期](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/mcp.md)，以及 [MCP 工具列表变化协议](https://modelcontextprotocol.io/specification/2025-06-18/server/tools)。采用原生租约和作用域；保留产品所需 Apps、Tasks 和审批适配，不另建 Agent 执行核心。本改动未升级依赖。

## 首次回复与列表加载（2026-11-06）

桌面会话启用 `backgroundMcp`：先建立所选连接的原生 scope，stdio 与远端 MCP 在后台并行握手，普通回复不再等待最慢的可选扩展。连接状态为 `connecting / ready / error`；配置已同步不代表连接已完成，后台连接不会被旧的加载结果弹窗误报失败。工具箱仍读取同一状态，并区分连接中与配置待应用。

`mcp-bridge` 唯一持有连接就绪 Promise、诊断与销毁；`search_mcp_tools` 返回正在连接的服务名称，模型以结构化 `servers` 或精确工具名选择需要等待的连接，其他连接不阻塞搜索。等待可取消，不执行工具、不授予权限；真正的工具与资源仍经现有注册、角色过滤、策略、审批与回执路径。失败服务的诊断也随指定服务的搜索返回。首次连接失败不自行反复启动，已成功连接后的恢复仍沿用原生命周期。

预热与会话复用同一远端配置身份；后台启动模式不是凭据或连接身份。stdio 正在连接时同配置重配也复用；删除、替换、关闭仍销毁其 scope，迟到的注册不能复活已删除选择。运行中的配置修改继续在下一轮应用，停用/删除仍受每次调用检查。无需迁移持久化状态、安装依赖或恢复旧 Rust Agent。

连接日志新增 initialize（含进程启动/协议协商）、tools/list 和总耗时。原会话准备日志在后台模式下只表示 scope 准入，不再表示全部 MCP 握手完成。

工具箱的技能、扩展、使用记录继续并行读取，先返回的目录先显示。每个卡片组先挂载 24 项，接近滚动底部加载下一批，保留键盘可操作的“加载更多”。搜索和深链接始终使用完整目录，新增、删除、编辑仍消费最新快照；不是只在已显示的 24 项中搜索。本次没有把后台目录 API 改成分页接口，也没有升级依赖。
