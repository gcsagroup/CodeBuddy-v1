# 统一工具箱与能力开关设计

日期：2026-09-09。状态：用户已批准，并授权开发、自动化测试和真实桌面验收。

[繁體中文（默认版本）](2026-09-09-unified-toolbox-design.md) · [English](2026-09-09-unified-toolbox-design.en.md)

## 目标与界面

把 CodeBuddy 的平台内置工具、技能和外部 MCP 放入同一个“工具箱”。提供“全部／内置工具／技能／MCP”分类及统一搜索；项目使用一致的图标、名称、简介、类型、状态、最近使用、详情和开关布局，但保留不同的配置及权限语义。

`ComputerClient` 作为“电脑控制”内置工具组显示，不把鼠标、键盘、截图等函数拆成大量顶层卡片。详情中列出窗口与 UIA 观察、截图、鼠标、键盘、等待、结果验证、支持角色、平台限制、权限和最近证据。

点击项目打开统一详情对话框。工具箱开关保存全局默认并影响后续新任务；现有会话选择器保留单次任务覆盖。进行中的物理输入事务不中途切断，后续发现和调用使用新状态。启用能力不代表跳过登录、UAC、删除、发送或其他高风险操作审批。

## 操作规则

- 系统核心工具锁定开启，只能查看，不能关闭或删除。
- `ComputerClient` 等可选内置工具可以启停和查看，但不能删除。
- 内置技能可以启停和查看，但不能编辑或删除。
- 用户安装技能可以启停、查看、编辑和删除。
- 外部 MCP 可以启停、查看、测试、配置和删除。
- UI 与 ACP／后端同时拒绝删除内置项目；内部版本迁移走单独的受控路径。

## 数据与错误

复用现有技能管理和扩展配置，将 `builtin`、`platform`、技能及 MCP 映射到统一展示模型，不创建第二套能力存储。项目记录稳定 ID、类型、来源、启用状态、允许操作、工具清单、使用情况及不可用原因。

开关提交期间显示忙碌状态，成功后重新读取实际配置；失败时恢复原值并显示原因。平台不支持、角色受限、需要配置、连接失败和用户关闭分别展示。搜索匹配本地化名称、原始标识、描述和来源。

## 清理与验收

移除误导性的 `goose-doc-guide`：它读取上游 Goose 在线文档，却显示为 CodeBuddy 文档指南。同步更新内置正文、注册与展示映射、快照、自检及测试。未来如有需要，另建读取 CodeBuddy 自有文档的技能。

先补回归测试，再逐步接入平台工具、统一卡片、详情及开关。完成相关 Rust／桌面测试、typecheck、lint、format、build 和 `goose-self-test.yaml`。从修改后的源码启动 Electron，真实操作详情、启停及重启持久化；新建真实对话证明关闭 `ComputerClient` 后 Agent 不可发现／调用，重新开启后能发现并完成安全桌面操作。每阶段记录命令、cwd、退出码、测试统计与证据路径；失败未解决前不进入下一阶段。

保留主目录既有修改，不建分支或工作树，不提交，不使用 reset、checkout 覆盖或 clean。
