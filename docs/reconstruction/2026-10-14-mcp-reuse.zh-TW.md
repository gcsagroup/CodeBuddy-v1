# 新會話復用遠程 MCP

本切片解決新建會話重復連接遠程 MCP；不改變模型、思考檔位、工具選擇或前端。工作目錄為 `D:\CodeBuddy-v1`，沒有 `.git`，源碼身份用最終回執中的 SHA256 記錄；保留既有文件，無分支、提交、推送、依賴安裝或升級。

## 原因與采用方案

舊適配在每個 Agent 的會話插件里創建 MCP，`configureSession` 先釋放該插件再創建，導致不同新會話重復初始化同一遠程服務。此前真實窗口 Exa 建連為 2.625s / 8.126s，見[上一輪診斷](2026-10-14-harness-latency-comparison.zh-TW.md)。

采用固定安裝版本 `0.2.1-alpha.2` 的官方 `dsh-agent-preset-registry`、`dsh-scope` 和 Cordis 生命周期。官方 registry 為配置聲明創建長期作用域；`acquireScope` 返回原生租約，負責舊修訂保留與最終釋放。包為 MIT，源碼在[官方倉庫](https://github.com/deepseek-ai/deepseek-harness)，本次沒有更新上游包。

- 相同遠程 MCP 配置在同一運行時共享長期組合。身份使用規范化后的完整配置，包括服務名、地址、憑據、超時和重連設置；摘要僅作內存索引，不寫明文憑據或派生配置到磁盤。
- registry 位于私有服務域，避免把連接組合當作用戶 Agent preset 寫入會話歷史；會話的原生執行、調度、完成判定保持不變。
- 會話通過官方 scope 父鏈借用組合；工具清單、資源、服務提示詞按作用域繼承，每次執行仍經過該會話的審批和權限路徑。禁用 MCP 的會話不會繼承它。
- 配置變化產生另一組合，舊會話保留原連接。最多保留 8 組可再次取得的配置；退出此緩存的修訂如仍有原生租約，繼續由 Harness 保留。共享失敗的首次啟動不緩存，下次取得可重試。
- 工具列表動態更新通過 Harness `tools/change` 同步會話的繼承工具限制，保留禁用原生工具的限制。資源讀取及 MCP Apps 元數據繼續使用已有適配。
- stdio 仍按會話創建并釋放，因為它可能綁定工作目錄、進程及會話狀態；未擅自將跨項目本地進程全局共享。重啟運行時后第一次連接也仍需初始化。

拒絕每會話繼續重建、禁用 Exa，以及自建客戶端連接池。當前復用的是 Harness 的組合、作用域和租約機制；MCP SDK 和現有 `mcp-bridge.mjs` 繼續承載協議及 Apps 元數據，未宣稱已刪除所有適配或替換該橋的重連實現。
