# Per-turn execution receipts and stale snapshots

Harness native logs remain authoritative for tool calls, results and turn boundaries. Each request receives a bounded index of at most eight recent calls per turn and current structured process facts. It does not duplicate arguments, code, output or command bodies. A native dynamic system section supplies only the current index instead of appending successive runtime-context snapshots. Native logs are unchanged.

Existing system behavior continues to require actual execution and truthful reporting; the receipt index carries structured facts only. Without current receipts, the model should perform requested implementation/validation or state that it has not done so. Previous returned operations are recorded work; explicit repetitions and repairs remain possible. Pending, failed, interrupted or unknown outcomes are not completed effects. Tool-level `isError:false` does not establish a process exit code or task acceptance. Assistant prose and code examples never enter the receipt projection.

While a tool is in progress and native steering is available, newly queued supplemental input enters the current turn at its next step through the existing steer API. Without a running tool, the ordinary queue still waits. Editing, paused queues, connection/cancellation barriers, stale Escape generations, historical tools and returned calls cannot trigger automatic steering. Rejection or uncertain delivery preserves and pauses the input without automatic replay. Harness retains admission, execution, cancellation and terminal authority.

Inputs composed while the desktop is busy retain optional `queuedWhileBusy:true`. Existing ACP `_meta` carries `codebuddy/input-origin=queued-while-busy`; Compat recognizes that exact value and Harness includes `inputOrigin` only in the request's receipt context. User text is unchanged. Ordinary inputs and explicit retries are unmarked. Old queues keep their prior behavior; malformed optional provenance is dropped without losing text. This fact provides context, not permission or a host decision about whether repetition is authorized.

The controlled-supplement mode approved on2026-11-16 is enabled by default: after a second native user input in a turn, or a queued follow-up in an existing session, every non-read-only proposal requires native per-call approval. Initial startup queues are not supplemental work. Existing cards show exact proposed arguments and up to eight preceding receipts; long historical commands are explicitly truncated, current arguments are not. Session grants and global allow rules cannot bypass this confirmation. Only allow-once/reject are offered. Native approval:never, cancellation and unknown replies do not execute the proposal. Ordinary subsequent turns retain their normal permissions; already-started effects are not rolled back. The model can still propose repetition, but unapproved repetition has no effect. Intentional repetition can be approved. No command-string equivalence or natural-language authorization rules are introduced.

Native turn completion means execution ended, not independent acceptance. The host retains an unverified report even for zero-tool answers; the desktop omits the fixed per-turn acceptance reminder and notifications report only execution ending, without promoting historical checks to current PASS. Model prose is not acceptance evidence. No removed reviewer model, external acceptance script or second executor is restored. Tasks without an independent acceptance contract remain unverified; arbitrary model prose is not guaranteed truthful.

Automatic steering reuses isConversationTurnStart to locate actual user input. ACP tool responses may also use the user role; slicing at those responses can discard a still-running tool in a shared assistant message, especially after tool discovery. A tool receipt is not a new human instruction.

Windows native execution defaults Python pipes to PYTHONIOENCODING=utf-8 while respecting explicit overrides. This is limited to standard streams, preserving default file encoding. The old GBK bytes for 状态 are also valid but incorrect UTF-8, so post-hoc guessing cannot resolve the ambiguity. Set encoding before output is produced. Existing legacy-program fallback, raw offsets and truncation remain; this does not promise reliable automatic decoding of arbitrary mixed encodings. [Python's official documentation](https://docs.python.org/3/library/sys.html) describes pipe defaults and explicit overrides. [LangGraph's approval design](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/interrupts.mdx) places approval before the side effect; CodeBuddy reuses Harness rather than importing that dependency.

The desktop keeps the newest full snapshot per `(sessionId,runId)`. Older chat notifications, control responses and reconnect refreshes return the existing projection without notifying subscribers. Same-sequence event conflicts, invalid versions and invalid identities remain errors. Independent connections cannot be assumed to preserve a shared delivery order.

Regressions cover native receipt-context delivery, no-action explanations, empty-response recovery, stale projections and refresh/notification races. Real-model acceptance must inspect files, tool results, input consumption and effect counts instead of trusting completion prose.

Design comparison: [LangGraph's official documentation](https://github.com/langchain-ai/docs/blob/main/src/oss/langgraph/functional-api.mdx) describes restoring completed task results and designing idempotent effects. CodeBuddy reuses its existing native receipts; it does not add LangGraph, another execution engine, or command-string deduplication.
