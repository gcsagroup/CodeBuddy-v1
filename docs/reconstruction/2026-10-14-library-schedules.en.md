# Harness integration for recipes, skills and scheduled tasks

This batch uses `D:\CodeBuddy-v1`; `source-baseline.json` identifies the source baseline. The directory has no Git repository. No branches, commits or pushes were created. Renderer files remain frozen; changes add host compatibility modules and isolated regression tests.

## Implementation and ownership

- `runtime/library.mjs` stores actual recipe YAML, skill files and agent templates. Recipes support parsing, CRUD, share-link encoding/decoding and slash commands. Schedule times project directly from `state.schedules`, with no duplicate scheduler state. Agent templates support global/project CRUD and import/export.
- Global skills live in `store.directory/harness/agents/skills`; project skills live in `<project>/.agents/skills`. Discovery reuses the official `FileSystemSkillProvider`; successful writes call `driver.refreshSkills()` to refresh Harness discovery. Existing management interfaces support creation, editing, enable/disable, local import, copy, deletion and restoration. Deletion requires the original reverse ACP confirmation with a matching nonce. Durable backups support restoration. Previews are connection-bound, expire after five minutes, are single-use, and verify filesystem identity plus content versions including companion files.
- `runtime/recipe-execution.mjs` exports `prepareRecipe(library, meta, sessionId, connection)`. It prepares a session without calling a model. Parameters use the original `session/recipe/request-params` form; cancellation returns `recipe_params_cancelled`. IDs, share links and saved scheduled recipe snapshots use one rendering path for prompts, instructions, model settings and extension parameters. File parameters require an explicit user-selected path, reject default paths, and read at most 1 MiB of UTF-8 text.
- `settings.max_turns` reaches Harness as a positive integer limit and takes precedence over the global setting. Reaching the limit is a resumable pause boundary. HTTP extension `envs` and `env_keys` merge before expanding `$NAME` / `${ NAME }` in the URI and request headers. Explicit `envs` wins, substitution runs once, and process environment remains unchanged. Session definitions use existing credential protection; missing variables and invalid URLs produce errors without actual credential values.
- Parameter templates reuse Nunjucks 3.2.4. Its official documentation states that it does not sandbox templates. A positive AST allowlist therefore permits only scalar parameters, conditions, bounded single-level loops and pure text filters before compilation. Member access, calls, macros, imports, loaders and unknown variables are rejected. Expansion is bounded before compilation and output is limited to 1 MiB afterward. This is not an operating-system sandbox.
- `runtime/schedules.mjs` exports `ScheduleService`, the sole writer for scheduled execution records and state. The official `@deepseek-ai/dsh-schedule` package owns five-field cron, timezone and DST calculations. The adapter only removes the literal zero seconds field emitted by the original six-field UI picker. CRUD, manual execution, pause/enable, inspection, cancellation and session history are connected. The compatibility layer supplies `run(job,{signal,onSession})` through the shared Harness session entry. It must persist `onSession(id)` before executing a prompt, then return a structured completed/cancelled result.
- New tasks default to paused; explicit `paused:false` retains request semantics. Only completed runs set `tested:true`; enabling requires that evidence. Failures and cancellations pause the task. Restarted in-flight tasks become interrupted; untested tasks remain paused. Next occurrences are computed from the current time without replaying missed runs. Each task permits one concurrent execution.
- Project-scoped sources accept the original UI's `projectId` as well as explicit `projectDir`. `WorkspaceService` resolves the authoritative project record; unknown or ambiguous multi-directory targets produce errors instead of global writes. Scheduled extension definitions use the host credential protection mechanism. State JSON and scheduled YAML projections omit plaintext extension definitions. User-authored recipe YAML remains an ordinary file; literal credentials saved in those files are not encrypted storage.

## Explicit boundaries

Remote skill downloads and local import are connected; see 2026-10-14-skill-download.en.md for the additional verification. Recipe `retry`, `sub_recipes` and structured `response.json_schema` remain unconnected. Saving a recipe or creating a scheduled task rejects these fields before persistence, identifies the exact field, and leaves existing files unchanged. Existing recipes remain parseable, viewable and exportable; execution also rejects unsupported fields explicitly.

JSON output format and subrecipes are visible advanced UI options: the advanced panel in `RecipeFormFields.tsx` contains the JSON Schema and `subRecipes` editors, and `CreateEditRecipeModal.tsx` writes them into the DTO. New recipes collapse that panel and leave these two fields empty, so the basic title/description/instructions path works. `retry` and `settings.max_turns` have no dedicated form controls but may arrive through imports or preserved settings. `RecipeExtensionSelector.tsx` passes HTTP `envs`, which now takes effect. The schedule form selects recipes through files or share links and therefore uses the same execution validation on creation.

Nonzero-second/seven-field cron expressions and HTTP socket extension configuration remain unsupported. Skill/workspace identity checks do not hold continuous OS directory handles. The advanced options above remain outstanding within the full-functionality objective.

Existing YAML and official Harness packages are reused; the main integration task installed and owns the Nunjucks dependency. The legacy agent execution core is not used.
