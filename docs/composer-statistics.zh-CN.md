# 输入框统计栏

生成期间显示当前请求最近采样时段的输出速度，每次采样至少间隔半秒。已识别的 vLLM 服务会随流返回累计输出 token 数；其他服务也可提供逐块计数。只有输出片段时使用 Harness 的 token 估算，并标记 `≈`。采样从首个输出开始，按请求重置。生成结束后显示原有的会话平均速度。

输入框上方区域用于输入，下方操作栏保留权限、模型和发送按钮。独立统计行显示平均生成速度、缓存命中和上下文占用；窄窗口允许换行，详细口径可通过悬停或键盘聚焦查看。

- **平均生成速度**：复用锁定的 Harness 0.2.1-alpha.2 官方 `@deepseek-ai/dsh-session-stats` 插件。`decodeTokens / (decodeMs / 1000)` 是当前会话已完成模型请求的平均解码速度，不包含首 token 等待和工具执行。请求完成后更新，不是即时 GPU 性能或逐字估算；跨模型会话也仍是会话平均值。原始统计由 Harness 日志投影拥有，重载不会把闲置时间加入分母。
- **缓存命中**：使用现有消息用量回执，展示最近一次非压缩请求的缓存读取占总输入比例。优先用 `totalTokens - outputTokens` 得到总输入；没有总量时按 Harness 的未缓存输入、缓存读取、缓存写入三个桶求和。写入不算命中。缺少或不合法的回执显示“未上报”，明确上报的零命中显示 `0%`；未完全命中不四舍五入成 `100%`。
- **上下文**：沿用现有计量和提醒组件。估算值带 `≈`，不把上下文占用当作累计计费 token 或缓存命中。

接入仅启用已安装插件，并通过既有 `status_message.data` 的 `context_meter` 结构传递可选 `sessionStats`；SDK 会过滤 `usage_update` 上未定义的元数据，所以不依赖该通道。没有新增模型请求、独立计时器、统计数据库或核心执行循环。无统计的历史记录和旧服务保持可用。

参考与取舍：主要采用本地锁定 Harness 包的 README、projection 和 Web 统计栏口径（MIT）；它的整个 Web 插件依赖自己的界面容器，不能直接替换 Electron 输入框，所以只复用官方统计插件和现有 React 格式化/提示组件。[LM Studio](https://lmstudio.ai/docs/developer/rest/chat) 将生成速度与首 token 耗时分开；[Cline](https://docs.cline.bot/core-workflows/task-management) 展示可用缓存统计并按请求更新。参考这些信息分层方式，不引入其代码或依赖。

局限：速度与缓存采用不同范围，提示中明确为“会话平均”和“最近请求”。数据精度受模型服务上报及 Harness 适配器影响；不反推服务端未上报的 KV cache 命中。

缓存回执修正：在现有锁定适配器兼容点保留原始服务明确上报的零值，避免被原生 `mapUsage` 的非零筛选丢掉。缺失值显示“未上报”（替代 `—`），零值显示 `0%`，正值按真实回执计算；状态按请求隔离并随原生会话持久化。vLLM 的启用前缀缓存与返回 `prompt_tokens_details.cached_tokens` 是独立配置；仅启用缓存或监控存在命中不能提供当前请求的比例。旧记录不会补造缓存值。
