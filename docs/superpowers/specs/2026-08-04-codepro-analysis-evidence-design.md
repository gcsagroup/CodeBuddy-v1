# CodePro 分析证据与安全折叠设计

## 背景

CodePro 的分析报告由后端直接写入 `<details>` 和 `<summary>`，聊天正文却只启用了安全 Markdown 渲染，没有启用原始 HTML。结果是技术证据标签以普通文字显示。与此同时，零工具、零证据的分析也会被格式化为正式报告，并显示“无”，让用户误以为项目已经完成分析。

## 目标

- 技术证据在聊天正文中显示为可展开、可收起的原生界面。
- 不启用任意原始 HTML，避免扩大 XSS 攻击面。
- 没有读取路径或执行命令时，不显示空技术证据区。
- 零证据分析不能被当成成功结果；系统先自动纠正一次，仍失败则明确显示“CodePro 分析未完成”。
- 保持右侧任务栏现有报告解析和历史会话兼容。

## 方案

### 1. 受控技术证据解析

在 `MarkdownContent` 前增加一个纯函数，仅识别 CodePro 后端生成的精确结构：

```text
<details>
<summary>查看技术证据……</summary>
……Markdown 内容……
</details>
```

普通正文继续交给 `ReactMarkdown`。匹配到的技术证据区由 React 原生 `<details>`、`<summary>` 渲染，内部内容仍交给安全 Markdown 渲染。其他 HTML 标签继续按当前安全策略处理，不引入 `rehype-raw`。

### 2. 空证据报告处理

`render_analysis_report` 只在至少存在一条去重后的有效证据时生成技术证据区。证据为空时不再输出 `<details>`、`<summary>` 或“无”。

### 3. 零证据分析终态

只读分析准备结束但没有任何读取路径或命令证据时：

1. 首次出现时，不向用户发布空报告；向当前模型追加一次明确纠正要求，要求使用只读工具检查当前项目。
2. 第二次仍然没有证据时停止重试，输出简短的“CodePro 分析未完成”，说明没有读取任何项目文件，不能给出可靠结论。
3. 不允许无限重试，也不把模型生成的报告标题视为完成证据。

## 数据流

```text
模型输出
  -> 宿主检查是否有真实读取/命令证据
     -> 有证据：生成正式报告和技术证据区
     -> 无证据（首次）：追加纠正指令并继续一次
     -> 无证据（再次）：生成“分析未完成”，无技术证据区
  -> 前端拆分受控技术证据区
     -> 正文：安全 Markdown
     -> 技术证据：原生折叠组件 + 安全 Markdown
```

## 测试

- Rust 单元测试：有证据时生成折叠区；无证据时不生成标签和“无”。
- Rust 执行器测试：零证据触发一次纠正；连续零证据最终为未完成且不会循环。
- React 单元测试：受控技术证据渲染为可折叠组件，标签文字不出现在页面中。
- React 安全测试：普通或恶意 HTML 不会因为本次改动获得执行能力。
- 回归测试：现有 Markdown、右侧任务报告解析、类型检查全部通过。

## 非目标

- 不启用全局原始 HTML。
- 不重构所有 CodePro 报告模板。
- 不改变右侧任务栏的数据模型。
