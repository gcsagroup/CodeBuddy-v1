# Reviewer Agent（独立审查与闭环裁决）

## 职责

Reviewer 是只读的独立裁决者，核对用户目标、任务合同、累计 Patch、真实测试证据、Worker 报告和剩余风险。它不修改文件、不执行测试，也不能把自己的文字结论当作测试证据。

## 输入与宿主硬门禁

输入分为不可信数据块：

- 用户原始目标与任务合同；
- 从本轮启动基线累计到当前的真实 Patch；
- Tester 的结构化命令、工作目录、退出码和有界输出；
- Worker 报告、已知风险和敏感文件命中结果。

调用模型前，宿主先执行硬门禁：

- 修改工作流缺少 Patch 或成功测试证据时拒绝；
- 纯测试工作流允许没有 Patch，但必须有与目标匹配的真实成功测试证据；
- 非零退出码、缺失命令或无法识别的自报文本不计为通过证据；
- 敏感文件命中时停止模型审查，且不把敏感内容写入提示或返工合同。

Reviewer 只加载 `codepromemory` 只读扩展，不加载 developer、Shell、文件写入或子 Agent 工具。提示中的需求、Patch、报告和测试输出均按不可信数据处理，不能覆盖系统规则。

## 结构化裁决

批准裁决不得携带问题或返工项：

```json
{
  "approved": true,
  "summary": "测试和变更证据满足验收要求",
  "issues": [],
  "remediation_tasks": []
}
```

修改工作流被拒绝时，必须提交可由宿主校验的返工合同：

```json
{
  "approved": false,
  "summary": "仍有一项未满足",
  "issues": ["错误处理未覆盖原始复现条件"],
  "remediation_tasks": [
    {
      "problem": "错误处理未覆盖原始复现条件",
      "files": ["src/example.rs"],
      "acceptance_criteria": "原始复现测试通过且现有回归测试保持通过"
    }
  ]
}
```

宿主拒绝未知字段、空字段、超限列表、绝对路径、遍历路径、敏感路径和越出原 Coder 写入合同的文件。Reviewer 只能缩小已有权限，不能定义角色、依赖、状态、预算或新增文件授权。

## 模型和失败处理

- 默认提供商：`ollama_cloud`
- 默认主模型：`minimax-m3`
- 默认备用模型：`glm-5.2`
- 配置键：`GOOSE_REVIEWER_PROVIDER`、`GOOSE_REVIEWER_MODEL`、`GOOSE_REVIEWER_FALLBACK_MODEL`

主模型的 Provider、JSON 解析或合同校验失败后，宿主只再完整尝试一次备用模型；合法的拒绝裁决不会触发备用模型。两个模型都失败时，系统追加“独立审查执行失败”，但保留已经完成的任务、文件、命令、退出码和输出。

## 返工闭环

合法拒绝由宿主编译为固定分支：

`定向返工 Coder → 独立复验 Tester → Reviewer 复审`

每个返工 Coder 只允许写 Reviewer 合同列出的精确文件，Tester 随后重新产生真实命令证据。首次审查后最多创建两轮返工；第三次仍被拒绝时不创建 `review-fix-3`，系统列出剩余问题并交给用户决定。纯测试拒绝、宿主前置门禁拒绝或缺少合法返工合同都不会猜测创建 Coder。
