# 对话标题、分支与主对话

顶部标题使用可用宽度，只有实际溢出时才省略。侧栏保留完整名称，长名称末端渐隐；悬停或键盘聚焦时缓慢展示，遵守系统“减少动态效果”设置。数字副本后缀固定显示在右侧。

打开历史对话时先完成可见内容的布局并直接定位到末尾，再移除加载提示；重新进入缓存对话也执行定位，不从顶部缓慢滚动。进入后主动向上翻阅仍保留阅读位置，实时输出沿用原有跟随行为。

旧对话的计划、目标与权限读取共用已有原生会话加载队列，避免并发打开同一写入句柄。已加载会话直接复用，不因只读查询初始化工具。

新分支使用原名称加 `(1)`、`(2)`，继续分支沿用同一来源名称。已归档分支参与编号；用户明确改名的对话作为新名称来源。旧名称和历史不会批量改写。编号只用于显示，身份及来源仍由会话 ID 和 `forkedFrom` 决定。

分支仍调用官方 Harness fork 并核对历史边界，原生历史落盘后才发布产品会话。产品状态插入复用现有提交队列和原子替换，只克隆新会话并复用其他历史的序列化数据；归档、恢复及改名使用单会话更新。写入失败不发布成功状态，文件格式和权限不变。

空白主对话显示 CodeBuddy 简介和能力示例；出现历史或执行任务时收起。这些展示及标题动画不发起模型请求。

真实窗口的 CPU 采样还定位到工具表更新的重复工作：每个会话收到工具变化通知后，对每个工具重复查询完整视图。现在先比较名称，仅对全局同名工具核对定义身份；默认继承角色跳过不必要的权限掩码扫描。继续使用上游公开接口，同步应用过滤规则，没有延迟权限更新。

对照锁定的官方 Harness 0.2.1-alpha.2 会话控制器后，移除了计划模式、任务目标只读查询中的执行工具初始化。两者直接读取原生状态，发送任务和执行工具前仍按原有入口准备能力。分支沿用官方 `sessionController.fork`，不替换历史或持久化协议；没有引入第三方实现或升级依赖。参见[官方会话文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/session/README.md)。

本地隔离基线约 27 MB、120 段历史，三次样本中状态层分支从 175–195 ms 降至 44–46 ms，归档从 125–151 ms 降至 43–52 ms。此基准模拟原生 fork，仅验证状态处理成本，不能替代安装版完整操作耗时及双平台验收。

交互动画参考 [WCAG 动画交互指南](https://www.w3.org/WAI/WCAG21/Understanding/animation-from-interactions)。评估了 [React 乐观更新](https://react.dev/reference/react/useOptimistic)，本次保留持久化成功后更新的语义；没有引入外部实现或依赖。
