# 內建影片生成

## 工作流來源（2026-10-26 更新）

圖片與影片預設讀取所設定 ComfyUI 左側已儲存的 workflows 目錄。Agent 先 inspect，再選擇回傳的 saved:<檔案路徑>.json；多個適用工作流由 Agent 依需求與結構化參數選擇。提交時重新讀取伺服器儲存版本，不使用內建匯出副本；瀏覽器中尚未儲存的編輯不包含在內。原畫布透過 extra_data.extra_pnginfo.workflow 隨工作提交，回執記錄來源路徑與內容雜湊。僅修改提示詞、種子、參考圖、輸出前綴與明確指定且受支援的參數，不覆寫伺服器原檔。

完整讀取目錄後，只有缺少目前模式適用且相依項目齊全的工作流才回傳 creation_allowed=true；提交 fallback_workflow 時再次核驗。讀取失敗、不支援的格式、排隊、逾時或執行錯誤皆不允許建立替代工作流。支援 API 格式、具明確控制項值的儲存格式、子圖及基本重新佈線。自訂前端序列化、重複子圖實例及旁路等不支援結構會明確報錯；可在 ComfyUI 匯出 API 格式並儲存，或修復原工作流。相依項目存在不代表模型組合正確。

參考 [ComfyUI 官方 API 格式](https://github.com/Comfy-Org/docs/blob/main/development/api-development/workflow-api-format.mdx)。官方前端為 GPL-3.0 且依賴瀏覽器執行環境，未複製或引入其實作；本適配器僅轉換已儲存資料。

圖片與影片使用相同的授權介面，提供拒絕、僅此次允許與本對話允許此工具。對話授權僅作用於目前對話中的對應工具及服務位址；圖片與影片分別授權。選擇後，後續生成、查詢及取消同一服務的工作可重用授權。重新啟動程式、移除工具、替換實作或更換服務位址後重新確認；明確禁止規則仍優先，不寫入全域允許設定。

完成後傳回本機 MP4 與外部播放連結。聊天中的媒體卡片可直接在目前視窗右側播放本機影片，不依賴 ComfyUI 持續在線；外部播放連結則需要服務在線。舊回執仍可查詢補齊外部連結，不必重新生成。

於「設定 → 模型與執行 → 圖片與影片 · ComfyUI」儲存服務位址。Agent 可透過工具探索載入 generate_video，沿用圖片工具的位址與會話權限。

文生影片：「生成 5 秒小熊貓在溪流邊揮手的影片，640×384，帶流水和鳥鳴。」圖生影片：「以工作區 reference.png 為首幀生成 5 秒動畫。」目前圖生影片接受工作區 PNG，寬高請配合圖片比例。

generate 的 mode 為 text_to_video、image_to_video 或 reference_to_video。尺寸、時長及幀率預設保留伺服器工作流設定；明確指定的尺寸為 32 倍數且最多 1344×768，時長為有限正數（支援小數），需要可辨識的秒數參數；請求與完成 MP4 均不設固定秒數上限。Agent 必須保留使用者指定時長，沿用工作流的幀數對齊與幀率。實際節點驗證、模型能力、記憶體、磁碟與既有 128 MiB 下載預算仍適用。參數綁定或伺服器失敗須明確回報，不自動縮短或替換工作流。

使用已安裝 MiniMax H3 FL2VA int8、Qwen3-VL 32B MiniMax int8、影片 fp16 VAE、音訊 fp32 VAE 與原生節點，20 步基礎採樣，不自動下載模型或安裝節點。更換服務需具備相同模型與節點。

提交一次後以相同 job_id 查詢 status，每次等待最多 30 秒，HTTP 上限 300 秒。伺服器完成且下載的 MP4 結構、影片軌元資料通過檢查並寫入 generated-videos/<job_id>/1.mp4 後才回報 completed。回執依會話保存，舊任務保留原服務位址；未知提交結果不自動重送。cancel 僅針對該任務；暫停 Agent 等待與取消 GPU 任務各自獨立。

模型與節點沿用伺服器儲存的工作流，復用 Harness 工具呼叫與對話權限，不下載模型或安裝節點。

## 在聊天和右側查看媒體

生成工具回傳已完成的本機產物後，聊天中顯示圖片或影片縮圖卡片。點擊「在右側查看」即可在目前視窗預覽圖片，或播放、暫停和拖動影片進度；無須複製路徑到外部播放器。歷史回覆中的連結、行內程式碼或獨立程式碼區塊所列的本機媒體路徑，也會在確認檔案存在且屬於目前對話工作區後顯示卡片。

預覽讀取本機檔案，已儲存的影片不依賴 ComfyUI 在線。圖片支援 PNG、JPEG、GIF、WebP（32 MiB 內）；影片支援 MP4、WebM、MOV 容器（128 MiB 內），解碼仍取決於 Electron 支援的編碼。生成中維持工具任務狀態，完整影片於實際完成並儲存後提供預覽。檔案遺失、超過限制或編碼不受支援時顯示錯誤，不修改檔案。

實作沿用對話工作區檢查和右側檔案面板，並採用 [Electron 自訂串流協定](https://www.electronjs.org/docs/latest/api/protocol/)；不開放任意磁碟路徑或執行媒體內容。
## 生成過程與寵物入口

Agent 查詢回執包含按任務隔離的暫時 `progress`（階段、節點、步數、總步數、連線狀態與觀察時間），終態清空。採樣百分比只描述目前階段，不代表整體完成度。右側背景查詢和 Agent 查詢共用每次請求 300 秒的下載逾時，並合併同一任務的並行更新。提交結果不確定時，在提交結束後重新查詢原任務，不重新生成；確認排隊、執行或完成後清除過期的提交錯誤。下載失敗保持未完成狀態，可針對原輸出恢復下載，無需再次生成。

圖片與影片生成任務提交後，右側自動開啟「生成預覽」，共用本機點陣動畫，顯示目前階段、階段步數及等待時間，不顯示中間預覽畫面。階段百分比來自服務進度，並非整個任務的總進度；沒有步數時顯示「請稍候」。斷線後重連，不重複提交；失敗或取消後停止動畫。完成儲存後，同一卡片自動切換為圖片或可播放影片。遵循系統的減少動畫設定。

新任務統一提交 `extra_data.preview_method: none`，關閉 ComfyUI 的標準中間預覽生成，仍保留 WebSocket 文字進度及狀態查詢。舊任務或自訂節點傳來的二進位預覽畫面直接丟棄，不編碼、不快取、不傳給前端。已提交任務的服務端設定不會追溯修改；最終產物需要的解碼與儲存節點仍正常執行。設定依據 [ComfyUI 的預覽實作](https://github.com/Comfy-Org/ComfyUI/blob/v0.37.0/latent_preview.py)。

自訂寵物僅準備新任務範本，使用者傳送後才建立對話。卡片描述最多三行，停留可看完整內容，啟用按鈕底部對齊。

即時資料沿用 [ComfyUI 官方 WebSocket 協定](https://docs.comfy.org/development/comfyui-server/comms_messages)，沿用既有依賴，不複製第三方實作。
