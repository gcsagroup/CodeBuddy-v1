# CodeBuddy：逐提交修改说明与原因

[繁體中文](2026-10-23-commit-rationale.zh-TW.md) · [English](2026-10-23-commit-rationale.en.md)

本文说明 `main` 上从 `d43fcbb` 到 `78bc5ba` 的四个提交。详细测试和构建记录见[合并交接文档](2026-10-23-merge-handoff.zh-CN.md)。

## `6491d44` — 安装包与原生工具修正

**改了什么：** 调整 Windows 安装/卸载进度、详情和排版；将 `UsePreviousAppDir` 改为 `no`，默认目录恢复为 `%LOCALAPPDATA%\Programs\CodeBuddy`，仍允许手工选择。完善 macOS DMG 布局、签名与架构校验、已运行工具的替换、Keychain 自检，以及电脑控制的窗口位置和按键处理。

**为什么改：** Windows 安装目录配置本身没有写死 D 盘，实际原因是安装器继承了以前的 D 盘安装位置，所以修的是路径继承行为，不是移动源码、改变构建暂存目录或迁移用户数据。Mac 在存在同名旧挂载卷时，Finder 布局可能失败，因此改为操作明确创建的 Finder 窗口。原生工具的其余调整用于检查实际签名、架构和凭据访问，并让窗口移动后的观察位置可核验；屏幕上的窗口位置与窗口内输入坐标仍明确区分。

## `11e8c28` — Harness、浏览器、模型预设与桌面交互整合

**改了什么：**

- 接入 `/goal`、`/plan`、目标编辑和计划审核，执行、压缩与完成状态仍由官方 Harness 管理。
- 增加会话绑定的内置浏览器控制、Playwright 入口和电脑操作技能；首轮提供权限允许的写文件、编辑与浏览器工具。
- 截图经过官方附件服务入库，保存持久图片引用；观察失败时保留已经执行的动作回执。
- 新安装预置 LAN 与 Ollama Cloud，统一默认配置来源；已有用户配置及主动删除预设的选择继续保留。
- 优化长代码流式渲染、工具参数状态和文件卡片；增加宠物新对话、附件及任务提示；精简设置入口，同时保留旧数据位置兼容和卸载的数据保留边界。

**为什么改：** 实际验收曾出现只输出代码不写文件、写完仍要求用户自己保存的情况，因此增加首轮可用工具并要求根据真实回执报告结果。模型仍负责理解用户是否只要示例，宿主不会通过关键词强制写文件，也不会跳过权限过滤。

内置截图曾因没有经过官方附件入库，导致下一次模型请求缺少 `attachmentId`。修复必须保留附件入库和持久引用链路。动作执行成功与后续图片观察失败是两个不同事实；观察失败不应抹掉动作回执，否则容易重复点击或输入。

长代码反复高亮是已复现的前端开销来源，因此流式代码和超过 8000 字符的历史代码改用完整纯文本，保留内容、复制和滚动；布局更新合并到动画帧。工具参数生成单独展示，是为了避免把“参数还没生成完”误认为“工具已经开始执行”。

双模型预设是为了让新用户安装后可以直接选择 LAN 或 Cloud；只在首次初始化应用默认值，是为了不覆盖老用户设置。Cloud 首项调整为实测的 `kimi-k2.6`，因为 `kimi-k3` 空正文已在直连 API 中复现，不能按前端显示故障处理。共享 Key 的分发文件由 Git 忽略，拉取源码不会自动取得 Key。

长期目标、计划、宠物提示和完成状态统一消费 Harness 或会话的真实状态，是为了避免各界面自行推断而互相矛盾。保存目标不等于执行，重启不自动恢复长期目标，点击跳转不等于已经查看会话。移除数据迁移等设置入口也不代表删除兼容读取逻辑，否则已迁移用户可能启动后看到错误的数据目录。

## `7ebdfcc` — 三语合并交接与验收说明

**改了什么：** 新增简体、繁体和英文交接文档，整理修改范围、关联文件、依赖版本、构建步骤、共享凭据交接方式和验收限制；为旧阶段记录补充最新状态说明。

**为什么改：** 这批修改跨运行时、桌面和安装脚本，只看单个文件容易遗漏关联修改。旧记录里的“待重建”“Mac LAN 待确认”等已经被后续验收更新，需要说明时间顺序，避免同事据此重复修复或误判。文档同时区分自动测试、真实安装版验收和未覆盖场景，明确真实 Key、安装包与本地证据不在 Git 中。

## `78bc5ba` — 补充 Go 验收结果

**改了什么：** 更新三语交接文档，记录使用本机现有 Go 1.27.2 完成补测：`go test -count=1 -json ./...` 的 31 项测试全部通过，0 失败、0 跳过；`go vet ./...` 无诊断，两条命令均退出 0。没有修改 Go 产品源码或重新生成安装包。

**为什么改：** 此前 Go 不在 PATH，测试命令实际没有启动。进一步找到本机已有工具链后补齐验证，将“未复测”更新为有实际命令和日志支持的结果。测试没有发现需修复的问题，因此没有额外修改产品实现；这些测试也不替代真实桌面输入或 macOS Swift 助手验收。
