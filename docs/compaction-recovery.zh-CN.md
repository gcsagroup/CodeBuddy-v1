# 上下文压缩故障修复

压缩仍由锁定的 Harness 0.2.1-alpha.2 负责范围选择、工具配对、历史替换和持久化。沿用 summarize 扩展点和校验 SDK 摘要的兼容加载器，不升级依赖，不增加另一套会话状态机。

默认摘要输出预算为 32768 token（2026-11-10 用户追加调整；额外预留 headroomTokens 保持 1024），小窗口限制为窗口的四分之一。预算包含服务端计入的思考 token。仅在模型声明支持 low 时使用低思考档位；主任务设置不变。若明确耗尽预算，仅追加一次双倍预算尝试，上限为 32768 和窗口二分之一中的较小值。实际请求仍通过适配器完整输入加输出空间校验，不靠截断原始记录凑空间。调整思考档位可能降低部分服务的前缀缓存命中率。

空摘要、服务端提前截断、两次预算耗尽均不提交检查点。同一轮同一路由后续自动压缩不再反复调用失败的摘要请求；进入空闲、切换路由或用户明确手动压缩后可以重新尝试。网络与权限失败不被伪装为预算耗尽，也不自动换模型。

手动压缩保留真实失败原因，不再一律说摘要不够小；界面使用一条历史内提示，技术详情默认折叠，同次失败不叠加红色 Submit error。日志增加摘要用途、模型、请求预算、思考档位、用量及正文/思考字符数，不保存请求正文或凭据。

回归覆盖截断重试、空回复、取消、工具配对、原始用户指令、超窗前检查、重启恢复及继续任务。安装包验收结果单独记录，不以源码测试替代安装测试。同事原模型/原会话未在本机复现时，不能宣称原环境问题已完全关闭。

Reference: [Harness compaction design](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-basic/README.md).
