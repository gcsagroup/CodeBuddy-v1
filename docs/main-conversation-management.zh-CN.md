# 主对话管理项目与对话 · 设计提案

用户在主对话说“建一个官网项目，开两个对话分别做设计和开发”，应当收到项目路径和两个可打开的对话。之后问“开发卡在哪”，主对话能指出对应任务、最后一次工具回执、更新时间和待用户处理的事项。第一版的全局范围是当前 CodeBuddy 数据配置中的项目与对话。

## 在主对话中选择处理方式

主对话根据用户要的是建议、一次性交付，还是需要在某个工作区持续执行来选择。单次小文件可以直接制作。已有项目里的小改动也应回到原项目。新建多阶段产品时，主对话可以创建项目、开发对话并启动首个可验证里程碑。完全访问下，用户明确指定操作和目标后直接执行项目、对话的增删改及派发。操作或目标不明确时先询问。更改对话权限仍须确认。项目对话结束后，主对话显示该轮的实际结果。目标对话继续独立执行，权限、取消和结果归属该对话。多个目标同名且无法区分时先确认目标。

查询进度时，一次读取返回近期用户要求、对话最近一次回复、当前运行状态和近期工具回执。回复是对话自述，实际完成情况应核对回执。清空按钮只重置当前主对话的消息与模型上下文，保留其他会话、项目文件和已保存的记忆。原生历史分叉可能保留旧日志。

可重复使用的验收提示词如下。每轮检查实际项目路径、对话 ID、受理回执或文件内容。

| 场景 | 给主对话的提示词 | 核对 |
| --- | --- | --- |
| 直接回答 | 把 2 GiB 换算成 MiB，只回复数字。 | 2048，零工具调用 |
| 一次性文件 | 直接在这里制作 hello.txt，内容为 HELLO-MATRIX。 | 主对话目录中的文件 |
| 设计咨询 | 网盘的账户、上传、分享怎么拆？现在只想了解思路。 | 回答方案，零项目创建 |
| 跨对话进度 | 帮我看一下 CodeBuddy-v1 那边上次在忙什么，实际查到了哪个提交？ | 对应对话历史与 Git 回执 |
| 同名目标 | 两个 CodeBuddy 项目中，把那个进度核查对话的权限调整一下。 | 先问具体项目和权限 |
| 新产品开工 | 开始做一个网盘系统。第一步由项目开发对话写 MILESTONE.md，包含 DRIVE-M1 和账户、上传、分享。 | 单一项目、开发对话及真实文件 |
| 跟进 | 刚才云盘的第一步做到哪了？根据执行结果回答。 | 回执、真实产物、无重复派发 |
| 续作 | 继续刚才的云盘项目，在同一个项目里新增 ACCEPTANCE.txt。 | 复用原项目和对话 |
| 只需启动 | 帮我开工团队网盘，先在项目中创建 M1.md，给我接单回执即可。 | 确认一次，目标对话接单，主对话目录没有同名副本 |
| 混合要求 | 让网盘开发对话创建 M2.txt。另外在这里回答 64 MiB 是多少 KiB。 | 原对话执行，主对话也回答 65536 KiB |
| 清空范围 | 先记录一次性口令。清空主对话后问“我之前在这条主对话说过什么口令？” | 旧口令无法从当前历史取回，其他对话和项目仍在 |

## 已实现的使用方式

在主对话中说出项目名称或路径，即可询问当前运行状态和最近任务。也可以直接要求创建项目文件夹和对话、改名、归档、恢复、删除对话、移除项目登记或调整单个对话的权限。新项目位于当前配置的工作区根目录，移除登记保留磁盘文件。管理工具显示目标与变更内容，用户确认后提交。归档和删除沿用原有活动任务检查。

权限覆盖可选只读、工作区内修改、完全访问或恢复继承。空闲会话立即应用，已有轮次保留开始时的覆盖，下一轮使用新值。会话索引的可选字段 `permissionOverride` 保存选择，原生 Harness 执行权限。旧客户端保留原有全局设置接口；降级前应检查依赖单会话限制的项目。

查历史时，主对话可按当前产品会话回读原生用户原话，按时间倒序分页，并返回消息 ID 和事件序号。进度详情可读取有界工具回执。当前实现按需读取原生日志，尚未增加独立全文索引。

## 界面与数据

通用的 CodeBuddy 介绍、图标和三项能力说明移到「新任务」，下方保留工作区选择与任务输入。主对话有历史时直接续聊。空主对话介绍项目进度、对话管理和单对话权限。运行中可以回到主对话查看目标，再点回原对话。

每份数据配置已通过 `runtime/main-conversation.mjs` 获取唯一主对话。它专属的 `workspace_memory` 当前只读召回登记工作区的有效记忆。工作目录位于 `backend/main-conversation`。产品身份在 `backend/state.json`，按 `globalConversation` 找记录，再用 `nativeSessionId ?? id` 定位 `backend/harness/sessions` 下的原生日志。建议在主对话菜单提供「打开聊天记录所在文件夹」，运行时解析当前位置，兼容迁移数据根目录和清空历史后的原生会话切换。

## 长历史怎样保持准确

用户输入草稿时仍可看见介绍；发送后让位给消息，回放历史时显示原有加载界面。

**当前行为。** Harness 将原生事件写入 JSONL，在上下文压力下压缩选中片段，并支持 `/compact`。文件路径可从所选区间内成功的配对工具回执带入压缩检查点。原生日志仍在磁盘；模型单次请求受上下文预算限制。摘要可能省略一个否定条件、旧版本号或后来的修正。2026-11-11 在隔离配置中使用真实 Gemma 4 26B A4B，加入约 3.6 万字符输入，两次运行 `/compact` 后重启后端。重启后的指令没有重复目标和新名称。模型检索了更正原话与项目目录，仅将 `west-site` 的「开发」更名为「核验-351a2f」，`east-site` 的同名对话保留原名。这是一次实测。另一次真实 Electron 验收走通了创建项目、创建对话、单独改为只读。长输入中关键信息的位置会影响部分模型在检索任务中的表现。 [原始研究](https://arxiv.org/abs/2307.03172)

**建议的读取与执行流程。**

1. 问“当时为什么选 A”时，按当前数据配置、项目、会话及时间检索原生消息。摘要用于找候选；取回用户原话、附近上下文及后续修订，并给出可打开的消息来源。多条相互矛盾且作用范围无法确定时，指出冲突再询问。问“现在用什么”时，读取当前项目配置或运行状态。
2. 涉及执行时，先绑定当前用户指向的项目 ID、会话 ID 和目录。宿主在动作提交前重新读取有效权限、目标状态和已有回执，避免跨项目或重复执行。历史记录中的“已批准”只能解释过去的决定。
3. 原生日志仍由 Harness 唯一写入。如需加速检索，先测量扫描延迟，再建立可重建的本地增量索引，只存必要检索字段和事件位置。查询按页返回有限片段；重启后从已验证的位置继续。清空、分叉或删除后按生效的原生历史范围隔离旧条目。工作文件夹不额外写一份聊天全文。分别测量打开耗时、检索耗时、日志与索引体积，再决定归档策略；自动压缩上下文不会给磁盘日志设上限。
4. **验收案例。** 在两个同名项目中安排早期约定、中段更正与末尾撤销，加入许多无关工具输出，跨过两次实际模型压缩再重启。分别核对旧约定的原文、当前生效选择、目标 ID、真实工具回执和重复执行次数。再测清空后检索，确认旧内容无法进入新主对话。按模型与实际上下文占用报告正确数/总数、误操作数和延迟；关键约束误用或作用于错误项目即视为阻塞。

## 操作与执行边界

| 用户动作 | 产品行为 |
| --- | --- |
| 查进度、项目或历史 | 首次读项目、会话和活动任务快照，按 ID 订阅变化，重连后重取快照。查看细节时有界读取原生历史、工作区 diff 或真实测试回执，附来源与时间。任务结束、代码已修改、测试通过和用户验收各自呈现。后台仅刷新状态，用户询问时才做模型分析。 |
| 创建项目并开对话 | 解析目标父目录，复用工作区分配、项目登记、创建会话与失败补偿。请求重试按操作 ID 合并。返回每个已创建对象；中途失败可继续缺失的步骤。 |
| 修改、分派或跟进 | 可修改项目显示名、重命名对话、追加目标或在指定项目开新任务。目标对话按自身工作区和权限执行，主对话收到受理回执后提供跳转。忙碌目标复用已有排队或跟进语义。 |
| 删除或归档 | 明确区分归档/恢复对话、删除聊天记录、从列表移除项目以及物理删除文件夹。物理删除须展示实际路径与影响，由用户明确选择。复用现有活动任务检查与逻辑删除回执。 |
| 调整权限 | 展示目标、当前模式、拟变更模式和生效时间。宿主验证当前主对话身份和真实用户授权，读取的其他对话内容仅作为数据。对话没有权限为自己发放管理身份。 |

管理工具只注册给现有主对话，由宿主校验目标 ID、规范化路径和作用范围。保留 Harness 对原生运行、取消、工具回执与历史的所有权，Store 及项目登记逻辑继续写各自的状态。全局概览只消费这些事实。对于同名项目或可能影响多个目标的操作，显示候选路径让用户选择。

当前 `runtime/compat.mjs` 的 `session/set_mode` 写全局 `preferences.gooseMode` 并同步多个会话。建议保留原接口的全局语义，增加显式的单会话覆盖，优先于全局默认并受宿主策略约束。默认从下一轮生效；活动轮需要立即收紧时，先请求停止并等真实停止回执。已有待审批操作沿用原请求。展示修改前后值，支持恢复继承全局默认。旧记录缺省即继承，降级前检查仍在使用的会话覆盖，尤其是更严格的限制。

## 实施与验收

1. 界面迁移和全局只读概览分开交付。用两个有运行记录的项目验证状态、断线重连和来源跳转，检查空记录与中断状态。
2. 开放项目与对话管理，验证同名目标、重复请求、中途失败、已有文件保护和活动会话删除。用户只在主对话输入也能完成“创建项目 → 分派 → 查看结果”。
3. 接入单会话权限，验证只改 A 时 B 和全局默认保持原值，运行中变更时下一轮按新值执行，重启恢复设置。跨模块测试后用真实桌面、隔离配置和真实模型走完上述流程。

## 设计参考

OpenCode 的公开服务提供项目/会话查询和全局事件，适合借鉴“先取快照，再订阅变化”。Deep Agents 提供上下文隔离的任务委派，适合借鉴“按需读取和返回结果”。两者都有公开维护的 MIT 仓库。这里采用接口设计思路，沿用现有 DeepSeek Harness，避免引入第二套执行与会话持久化。 [OpenCode 服务](https://opencode.ai/v1/docs/server/) · [OpenCode 仓库](https://github.com/anomalyco/opencode) · [Deep Agents 文档](https://docs.langchain.com/oss/javascript/deepagents/overview) · [Deep Agents 仓库](https://github.com/langchain-ai/deepagentsjs)
