# Coder Agent（实现与返工）

## 职责

Coder 按 Planner 的单个任务和验收标准，直接在用户当前项目中完成最小范围修改。
CodePro 不要求项目是 Git 仓库，不复制整个项目、不切换分支，也不自动执行 `git init`。
写入任务串行执行，避免多个 Coder 同时覆盖真实文件。

## 输入与输出

输入：

- Planner 分配的任务、依赖和验收标准；
- 已完成的上游任务；
- 当前项目真实文件；
- Reviewer 返工时的具体问题清单。

输出：

- 最多 12 行的简明执行报告，只包含“结论、修改、验证、限制”；
- 相对本次运行基线的真实 Patch；
- 变更文件列表；
- 实际执行过的测试信息（如有），不得虚构。

执行报告不重复任务描述、不粘贴完整日志、不使用表格。历史报告中的问题没有当前
复现证据时只能标为“未确认”；质量检查未通过不能直接称为业务 Bug。

Git 项目使用临时 index 收集差异，不改动用户暂存区。非 Git 项目使用有大小和文件数
上限的原生快照生成差异。`.env`、私钥等敏感文件只记录文件名和哈希，不把内容放进
Patch、聊天或审查提示。

## 安全边界

- 只修改当前项目内且与任务直接相关的文件；
- 禁止 `git reset --hard` 和静默覆盖已有修改；
- 删除大量文件、项目外写入、提权、发布和推送仍受权限层控制；
- 网络型外部扩展不会自动继承给内部 Worker；
- 本轮结束后生成可校验的撤销包；若用户后来又改了目标文件，撤销会拒绝覆盖。

## 模型和失败处理

- 提供商：`ollama_cloud`
- 主模型：`kimi-k2.7-code`
- 备用模型：`glm-5.2`
- 配置键：`GOOSE_CODER_PROVIDER`、`GOOSE_CODER_MODEL`、
  `GOOSE_CODER_FALLBACK_MODEL`

主、备用模型均失败、任务取消或执行报告为空时，Coder 失败，下游任务被阻断。

## 闭环位置

`Planner → Coder → Tester`

Coder 完成不等于整轮成功。每次实现和 Reviewer 返工都必须重新经过 Tester。
