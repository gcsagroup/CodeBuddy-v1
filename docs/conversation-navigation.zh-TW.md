# 對話標題、分支與主對話

頂部標題使用可用寬度，僅實際溢出時省略。側欄保留完整名稱，長名稱末端漸隱；懸停或鍵盤聚焦時緩慢展示，遵守系統「減少動態效果」設定。數字副本後綴固定顯示在右側。

開啟歷史對話時先完成可見內容的版面配置並直接定位至末尾，再移除載入提示；重新進入快取對話也執行定位，不從頂部緩慢捲動。進入後主動向上閱讀仍保留位置，即時輸出沿用原有跟隨行為。

舊對話的計畫、目標與權限讀取共用既有原生會話載入佇列，避免同時開啟相同寫入控制代碼。已載入會話直接重用，不因唯讀查詢初始化工具。

新分支使用原名稱加 `(1)`、`(2)`，繼續分支沿用同一來源名稱。已封存分支參與編號；使用者明確改名的對話作為新名稱來源。舊名稱與歷史不會批次改寫。編號僅供顯示，身分與來源仍由會話 ID 和 `forkedFrom` 決定。

分支仍呼叫官方 Harness fork 並核對歷史邊界，原生歷史寫入後才發布產品會話。狀態插入沿用現有提交佇列及原子替換，只複製新會話並重用其他歷史的序列化資料；封存、還原與改名使用單會話更新。寫入失敗不發布成功狀態，格式與權限不變。

空白主對話顯示 CodeBuddy 簡介與能力範例；出現歷史或執行任務時收起。這些展示與標題動畫不發起模型請求。

真實視窗的 CPU 採樣也定位到工具表更新的重複工作：每個會話收到通知後，對每個工具重新查詢完整視圖。現在先比較名稱，僅對全域同名工具核對定義身分；預設繼承角色跳過不必要的權限遮罩掃描。沿用上游公開介面，同步套用過濾規則，不延遲權限更新。

對照鎖定的官方 Harness 0.2.1-alpha.2 會話控制器後，移除了計畫模式、任務目標唯讀查詢中的執行工具初始化。兩者直接讀取原生狀態，傳送任務與執行工具前仍由原有入口準備能力。分支沿用官方 `sessionController.fork`，不替換歷史或持久化協定；未引入第三方實作或升級相依套件。參見[官方會話文件](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/session/README.md)。

約 27 MB、120 段歷史的本地隔離基準中，三次狀態層分支耗時由 175–195 ms 降至 44–46 ms，封存由 125–151 ms 降至 43–52 ms。基準模擬原生 fork，不能取代安裝版完整耗時與雙平台驗收。

動畫參考 [WCAG 指南](https://www.w3.org/WAI/WCAG21/Understanding/animation-from-interactions)。評估 [React 樂觀更新](https://react.dev/reference/react/useOptimistic) 後，保留持久化成功才更新的語義；未引入外部實作或依賴。
