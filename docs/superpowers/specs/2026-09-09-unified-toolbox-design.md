# 統一工具箱與能力開關設計

日期：2026-09-09。狀態：使用者已核准，已授權開發、自動化測試及真實桌面驗收。預設版本：繁體中文。

[简体中文](2026-09-09-unified-toolbox-design.zh-CN.md) · [English](2026-09-09-unified-toolbox-design.en.md)

## 目標

將 CodeBuddy 的平台內建工具、技能與外部 MCP 整合到同一個「工具箱」入口。使用者可搜尋、查看用途與狀態，並控制可選能力是否向 Agent 暴露；不同能力共用視覺語言，但保留其不同的設定、權限與生命週期。

`ComputerClient` 以「電腦控制」內建工具組呈現。頂層不拆成逐個滑鼠、鍵盤或截圖函式；詳細資料列出其視窗與 UIA 觀察、截圖、滑鼠、鍵盤、等待、驗證、支援角色、平台限制、權限及最近使用證據。

## 資訊架構與互動

- 工具箱使用「全部／內建工具／技能／MCP」分類與統一搜尋。列表採相同的圖示、名稱、摘要、類型、狀態、最近使用、詳細資料及開關布局。
- 點擊項目開啟同一種詳細資料對話框；內容依類型顯示工具清單、技能指令摘要或 MCP 連線與資源資訊。
- 工具箱開關保存全域預設，影響後續新任務；既有會話選擇器保留單次任務覆寫。進行中的實體輸入交易不在中途切斷，之後的發現與調用使用新狀態。
- 啟用只代表能力可被發現及調用，不取代工具權限、登入、UAC、刪除、傳送或其他高風險操作的個別授權。

## 類型與變更規則

- 系統核心工具：鎖定啟用，可查看，不可停用或刪除。
- 可選內建工具（包括 `ComputerClient`）：可啟停及查看，不可刪除。
- 內建技能：可啟停及查看，不可編輯或刪除。
- 使用者安裝技能：可啟停、查看、編輯及刪除。
- 外部 MCP：可啟停、查看、測試、設定及刪除。
- 內建刪除限制同時由 UI 與 ACP／後端執行，不能只隱藏按鈕。內部版本遷移使用獨立受控路徑。

## 資料與錯誤處理

工具箱沿用既有技能管理及擴充設定來源，將 `builtin`、`platform`、技能及 MCP 映射為統一展示模型，不建立第二套能力儲存。每個項目包含穩定 ID、類型、來源、啟用狀態、可執行操作、工具清單、使用情況與可用性原因。

開關提交時顯示忙碌狀態，成功後重新讀取實際設定；失敗則回復原值並顯示可理解的原因。平台不支援、角色受限、需要設定、連線失敗與使用者停用必須是不同狀態。搜尋同時匹配本地化名稱、原始識別碼、描述和來源引用。

## 內建文件技能清理

移除 `goose-doc-guide`。它讀取上游 Goose 線上文件，卻以 CodeBuddy 文件指南呈現，無法可靠涵蓋本產品新增能力。同步移除內建正文、註冊／展示映射、快照、自檢及測試引用；不增加供使用者刪除內建項目的入口。未來如有需要，另建使用 CodeBuddy 自有文件的技能。

## 驗收

1. 先增加模型、操作規則與 UI 回歸測試，再實作每一階段。
2. 驗證平台 `computer` 出現在內建工具中，核心工具鎖定，可選內建工具可啟停，所有內建項目都不可刪除。
3. 驗證技能與 MCP 使用統一樣式且保留各自操作，開關失敗能回復，搜尋與三語文案正確。
4. 執行相關 Rust／桌面測試、型別檢查、lint、format 和 build，更新並執行 `goose-self-test.yaml`。
5. 從變更後原始碼啟動 Electron，以真實滑鼠鍵盤查看詳細資料、切換能力並重啟應用核對持久化。
6. 新建真實對話：關閉 `ComputerClient` 時 Agent 不可發現／調用；重新開啟後 Agent 可發現並完成一個安全桌面操作。核對對話工具記錄及後端狀態，不以開關顏色代替證據。

每階段記錄命令、工作目錄、退出碼、通過／失敗／忽略數及證據路徑。新回歸未解決前不進入下一階段。保留主目錄既有修改，不建立分支或工作樹，不提交、不 reset、checkout 覆蓋或 clean。
