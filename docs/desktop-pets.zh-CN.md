# 桌面虚拟宠物

多个对话默认全部展开；点击列表标题可收起，再次点击可展开。收起后仍保留当前优先对话，列表过长时可滚动。

设置 → 虚拟宠物提供小熊猫、奶油猫和白狐。首次使用不选择任何宠物；点击卡片先预览，点击“设为桌面宠物”才选择并显示。已有选择保留，隐藏后可点击“显示此宠物”重新启用；早期 `buddy` 选择迁移为 `red-panda`。已选素材缺失时恢复为未选择，不自动换成其他宠物。

支持待机、挥手、跳跃、工作、等待输入、受阻、检查完成和观察方向。拖动移动，点击打招呼，双击跳跃。任务提示消费 ACP 的结构化会话状态；点击提示打开对应会话。减少动画可在设置中开启。

完成提醒在对应会话实际显示且窗口获得焦点后才标记已读；点击跳转本身不提前清除提醒。隐藏会话或后台窗口不会误清除提示，下一轮的新完成记录会再次提醒。移除会话时同步撤下该会话的宠物提示。

一个宠物承载可展开的对话列表，优先显示等待用户处理、受阻、未读完成、工作中的会话。每条显示会话标题及真实活动（思考、撰写回复、当前工具、整理上下文等），已有结构化工作阶段时一并显示；完成项带勾选。新会话尚未命名时显示首条请求摘要。点击哪一条就跳转到哪一条，不推算百分比或从回复文字推断完成。

任务卡使用浅色圆角、柔和阴影及分层标题；状态和操作保持分开，长标题最多显示两行，展开列表可滚动。参考 [Fluent 通知设计](https://fluent2.microsoft.design/components/web/react/core/toast/usage)的阅读层次，未引入外部 UI 依赖。

拖动位置按多个显示器工作区的联合范围校验，允许窗口跨越相邻屏幕接缝；超出外缘或断开显示器后，回收到最近的可见工作区。鼠标经过宠物时仅更新点击穿透，不主动抢置顶；直接操作宠物时才恢复其层级。这项调整用于减少与截图浮层的冲突，并非全局截图检测或自动暂停动画。微信截图及不同缩放比例的双屏行为仍需对应环境的实际验收。

## 素材与创建

单击宠物可展开“主对话”输入框。Enter 发送，Shift+Enter 换行；中文输入法确认候选词时不会误发。发送后打开全局持久主对话并追加消息，不创建项目或新的工作区；执行中收到的消息进入现有持久消息队列，待上一轮结束后顺序发送。重启恢复的未发送队列沿用原有规则，需用户确认继续。只有主窗口确认消息已保存到队列后，宠物才清空输入。关闭输入框保留未发送草稿，窗口交接失败时保留文字并允许重试。点击任务卡仍打开对应任务；拖动移动、双击跳跃保持可用。

完成勾选与侧边栏绿色未读点消费同一份完成记录，实际查看会话后一起清除。Agent 通过 `ask_user_question` 提问时，宠物显示“等待你回复”和问题摘要，点击进入对应问题；仅查看不会代替回答。工作中可点击“暂停”，沿用会话停止操作；“继续跟进”打开原对话，供用户发送后续要求。

“自定义宠物”在当前窗口新建对话，预填形象、名字、颜色、画风、动作和补充要求模板。用户修改后发送，预填本身不会调用模型，也不会新开窗口。

内置素材随应用打包，日常显示不依赖图像服务。三个角色基于用户确认的原创概念图制作，使用 ComfyUI 的 Qwen Image 2.1 图生图工作流生成连续姿势。网页参考只用于风格调研，没有复制第三方成品素材。

“自定义宠物”打开 CodeBuddy 的主 Agent 会话。Agent 先询问未明确的形象、颜色、风格和名字，再调用内置 `create_desktop_pet`：`prepare` 返回素材要求，`assemble` 装配真实图像、校验并注册预览包。新包会自动出现在设置中，也可手动刷新；用户预览并点击“设为桌面宠物”后才启用。

主 Agent 负责整个流程，通过内置 `generate_image` 调用设置中的 ComfyUI，先生成角色参考图，再生成八组动作网格。聊天模型负责理解需求和编写提示词，ComfyUI 负责生成像素，装配工具负责校验与注册。配置、支持的参考图格式和任务查询见[内置图像生成](image-generation.zh-CN.md)。缺少图像服务时应明确说明，而非把静态复制帧当作新动画。

创建会话使用设置页显示的自定义素材目录作为明确工作区，并预填素材要求供用户编辑后发送。若当前会话缺少图像工具，可以提供自己已有的图像服务和可用工作流，再由 Agent 检查实际可调用性；服务地址、凭据或可用模型不会从 Codex 自动继承。

每个自定义包位于设置页展示的目录内，以稳定英文 ID 为文件夹名，仅包含 `pet.json` 和 `sprites.png`。保留 ID：`buddy`、`red-panda`、`cream-cat`、`white-fox`。

`pet.json` 使用版本 1：`schemaVersion: 1`、`image: "sprites.png"`、`columns: 6`、`rows: 8`、`cellWidth: 192`、`cellHeight: 208`、`fps: 6`，另含 `id`、`name`、`description`。PNG 为透明 RGBA，尺寸 1152×1664。行顺序与上述八组动作相同；观察行依次为上、右上、右下、下、左下、左上。每格保留至少 2 像素透明边缘，每个动作至少有 3 个不同的真实姿势。

坏素材会报告错误并保留已验证版本。内置包异常时可回退到其他有效宠物；没有有效素材时不打开空白悬浮窗口。

## 素材装配

`runtime/assets/assemble-pet.py` 只裁切、缩放、排列生成图，并导出预览及检查记录，不绘制角色；原 `ui/desktop/scripts/assemble-pet.py` 保留为同一实现的入口。内置工具只接受会话工作区内的图像，在临时目录校验成功后一次发布完整包，不覆盖已有 ID，也不自动改变选中宠物。像素校验不等于角色一致性或动作语义验收，仍需预览。生成原图、工作流及本地验收文件放在 `target/pet-redesign`，不随应用分发。

宠物输入框采用紧凑的两行布局，随文字增长至限定高度。点击回形针可选择文件或图片，附件标签支持移除；每条最多 10 个附件，单张源图片最多 20 MB。图片沿用聊天的压缩和图片输入，普通文件作为本地路径引用，不额外复制文件。右键宠物可选择“隐藏宠物”或“宠物设置”；设置直接打开虚拟宠物页面，隐藏后可在该页重新显示。

## 全局主对话（2026-11-04）

侧栏主对话的清空按钮只在悬停或键盘聚焦该行时显示。宠物权限通知直接显示当前审批选项，可批准或拒绝，不拉起聊天窗口；详情可展开查看完整工具名称、提示和参数。按钮使用原 ACP 审批选项与回执，绑定本次请求的临时令牌；过期、重复或已处理请求不可再次批准。需要填写内容的问题、工作区确认仍保留“去处理”入口。

主对话入口固定在“聊天”折叠区上方，右侧垃圾桶按钮在确认后清空消息和模型上下文，保留会话身份、目录与已保存记忆。执行中或存在待发送队列时不清空，先处理任务或队列。清空复用官方历史分叉机制，旧原生日志仍按已有审计规则留存，不作为当前对话上下文。

宠物转交编号沿用为持久队列及提交消息编号；同一转交通知重复到达只入队一次，相同文字的新发送仍正常接收。宠物窗口保持原生可聚焦以提供输入法定位上下文，空闲展示使用 `showInactive`，始终隐藏任务栏入口。

侧边栏“主对话”与宠物共用唯一会话。会话保存在现有运行时存储内，以 `globalConversation` 标识；内部文件目录为运行时数据根下的 `main-conversation`，不加入项目分组，也不能通过目录选择器更换工作区。普通聊天沿用模型配置和 Harness 执行，主对话不额外启动另一套 Agent。

只有主对话注册 `workspace_memory`，可先列出已有会话及角色绑定登记的工作区，再按工作区只读检索已批准且未过期的记忆；返回工作区来源。它不检索历史对话、不修改记忆、不向普通会话授予跨工作区记忆工具。既有文件与工具权限仍独立生效，此功能不是文件系统沙箱。

Windows 输入和右键菜单切换可聚焦状态后会重新设置隐藏任务栏。自定义智能体工作区从运行时绑定列表补充到“最近项目”，即使尚未进入桌面目录历史也可以选择。

## 动作播放与素材质量

触发动作（挥手、跳跃、工作、等待、受阻、完成）播放两轮后回到待机，不因相同状态快照重复而持续重播。任务卡仍显示真实状态；新的会话、完成/失败记录、权限请求或点击可以重新触发。默认 6 fps 时两轮约 2 秒。设置页可点击“重播动作”重新预览。

待机以静止中性姿势为主，间隔 4–7 秒播放一次短动作，不叠加整张图片的缩放。实时鼠标观察仍使用方向姿势；减少动画保持静止。

创建素材时要求六格属于同一连续动作，稳定角色比例、镜头及地面；待机只做小幅眨眼或耳尾动作，跳跃包含蓄力、起跳、腾空、下落、落地、恢复。动作首尾尽量接近中性姿势。生成要求不能保证模型输出质量，需按实际播放速度检查角色漂移、滑步及姿态突变；现有内置素材未在本次重新生成。

设计参考：[Godot OneShot](https://docs.godotengine.org/en/stable/classes/class_animationnodeoneshot.html) 的短动作退出机制，以及 [Spine 动画教程](https://us.esotericsoftware.com/spine-animating)的关键姿势和时序方法。只参考公开设计，没有复制代码、素材或引入引擎依赖。
