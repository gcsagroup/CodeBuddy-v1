# CodePro 自适应行动续期与无损恢复设计

日期：2026-08-04

状态：已确认，等待实施计划
适用范围：CodePro 主 Agent、Planner、Coder、Tester、Reviewer、任务调度器、状态持久化和桌面端任务进度界面

## 1. 背景

CodePro 当前根据任务类型给每个 Agent 分配初始行动额度和硬上限。达到硬上限前进入收尾区，停止提供工具并要求 Agent 输出阶段报告。该机制能够限制死循环和资源消耗，但会把正常的长任务截断，尤其影响大型项目分析、全项目测试、复杂 Bug 修复和跨模块开发。

本设计是 `documentation/codebuddy/U-36-阶段3动态行动预算与死循环保护设计.md` 的后续升级。U-36 中关于结构化证据、循环保护、暂停状态和项目失败分类的约束继续有效；“只允许扩展一次”“复杂任务必须等待用户继续”和“较低硬上限直接进入收尾”的部分由本设计替代。

## 2. 参考机制与设计结论

### 2.1 Codex

Codex 把执行过程建模为可持久化的 Thread、Turn 和 Item。动作具有开始、增量和完成事件；中断会形成明确的 `interrupted` 终态；历史可以恢复或分支；上下文压缩也有独立进度事件。设计重点是生命周期、恢复和结构化错误，而不是让较低的行动次数成为正常任务终点。

参考：https://github.com/openai/codex/blob/main/codex-rs/app-server/README.md

### 2.2 Claude Code

Claude Agent SDK 默认不限制工具往返轮次，开发者可以主动设置轮次或费用上限。Claude Code 使用自动上下文压缩、会话恢复、文件检查点和独立子 Agent 上下文支撑长任务；重复压缩仍无进展时才停止循环。

参考：

- https://code.claude.com/docs/en/agent-sdk/agent-loop
- https://code.claude.com/docs/en/how-claude-code-works
- https://code.claude.com/docs/en/checkpointing

### 2.3 Hermes Agent

Hermes 使用较高的最终保险上限，不再在 70% 或 90% 时向模型注入额度压力提示。额度真正耗尽时提供一次收尾调用；停滞监视器只通知用户；Provider 重试、模型回退、流停滞和任务停滞分别处理；每轮结束后持久化会话并支持恢复。

参考：

- https://github.com/NousResearch/hermes-agent/blob/main/website/docs/user-guide/configuration.md
- https://github.com/NousResearch/hermes-agent/blob/main/website/docs/developer-guide/agent-loop.md

### 2.4 CodePro 采用的组合

CodePro 采用以下组合，而不完整复制任一产品：

1. 使用 Codex 风格的持久化任务、动作事件和明确终态。
2. 使用 Claude Code 风格的自动压缩、恢复检查点和独立子 Agent 上下文。
3. 使用 Hermes 风格的高保险上限、无提前压力提示、停滞通知和最终收尾宽限。
4. 保留 CodePro 的意图分类、四角色协作、宿主证据和报告分类。

## 3. 目标

1. 正常长任务不得因为一次较低行动额度耗尽而失败或停止。
2. 只要存在可核验进展，系统自动续期，不询问用户。
3. 等待测试、编译、下载、后台进程或子 Agent 时不消耗模型行动额度。
4. 无进展、重复失败和危险循环必须被宿主确定性识别并停止。
5. 中断、超时、额度耗尽和进程重启后保留已完成步骤、文件修改和验证证据。
6. 用户始终能看懂系统是在继续工作、等待、暂停，还是确实失败。
7. 项目代码失败与 CodePro 自身未完成继续严格分开。

## 4. 非目标

1. 不取消费用、时间、安全权限和危险操作限制。
2. 不允许模型或 Planner 自行提高最终保险上限。
3. 不把内部推理文本作为进展依据或持久化契约。
4. 不通过不断切换模型掩盖环境缺失、命令错误或重复失败。
5. 不让一次用户任务无限占用计算资源；超过最终保险上限需要用户明确继续。

## 5. 核心概念

### 5.1 行动

一次行动指一次需要模型继续决策的 Provider 往返。下列行为不计入行动额度：

- 宿主等待已经启动的命令；
- 宿主接收命令输出流；
- 等待仍存活的子 Agent；
- 写入事件日志和检查点；
- 前端渲染或恢复事件；
- 不调用模型的确定性测试解析、差异统计和证据聚合。

### 5.2 软检查点

达到软检查点时不停止任务。宿主根据最近一个窗口内的结构化事件判断任务是否有进展，并决定续期、恢复尝试或暂停。

### 5.3 续期租约

续期租约是宿主授予当前任务或节点的一段额外行动额度。租约只允许宿主发放，模型文本、Planner 输出和旧会话数据不能扩大租约。

### 5.4 最终保险上限

最终保险上限防止失控消耗。达到该上限后停止创建新动作，保存检查点并执行一次无工具收尾。它不是正常任务的预期结束条件。

### 5.5 恢复纪元

用户在最终保险上限后点击“继续执行”会创建新的恢复纪元。新纪元继承任务状态、证据、修改文件、失败指纹和已完成节点，但拥有新的保险额度。历史纪元及其消耗必须保留，不能伪装成首次执行。

## 6. 默认预算策略

| 任务类型 | 首次软检查点 | 单次续期 | 单纪元最终保险上限 | 收尾宽限 |
|---|---:|---:|---:|---:|
| Conversation | 4 | 0 | 8 | 1 |
| ReadOnly | 30 | 20 | 150 | 10 |
| FocusedTest | 30 | 20 | 150 | 10 |
| ProjectTest | 60 | 30 | 300 | 10 |
| SimpleChange | 45 | 20 | 150 | 10 |
| BugFix | 60 | 30 | 300 | 10 |
| ComplexChange | 80 | 40 | 500 | 10 |

Conversation 不自动长期续期。问候和普通问答应直接完成；若实际需要工具，主 Agent 必须重新分类为对应任务类型。

角色上限继续作为单个 Worker 的隔离边界：Planner 50、Coder 100、Tester 120、Reviewer 80。一个 Worker 达到角色上限但根任务仍有进展时，Scheduler 创建携带检查点的 continuation Worker，而不是让同一 Worker 无限增长上下文。所有 Worker 行动同时计入根任务的单纪元总账。

## 7. 确定性进展判定

进展只能来自宿主结构化事件，不能解析 Agent 自述。每次软检查点评估最近一个租约窗口。

### 7.1 正向信号

- DAG 节点发生有效状态迁移：`Pending -> Running`、`Running -> Done` 或进入可验证的返工节点；
- 新增去重后的读取文件、命令、测试、诊断或差异证据；
- 文件产生新的有效 Patch，且内容指纹不同于已有 Patch；
- 新测试运行完成并产生退出码；
- 失败测试数量下降，或上一轮失败转换为通过；
- 发现新的、可定位且未重复的问题；
- 子 Agent 返回新的结构化结果；
- 当前命令或子 Agent 仍存活并持续产生心跳或输出。

### 7.2 无进展信号

- 重复相同工具和规范化参数，结果没有变化；
- 反复读取同一文件范围而没有产生新证据；
- 连续模型轮次没有工具动作、任务状态变化或最终回答；
- 切换命令写法但实际执行目标和错误指纹相同；
- 已知环境依赖缺失后继续尝试依赖该环境的同类动作；
- Provider 重试只重复同一网络错误，未发生成功或有效回退。

### 7.3 决策规则

1. 存在任一正向信号且没有确定性循环：自动发放一个续期租约。
2. 只有存活等待信号：保持当前状态，延后检查，不消耗行动额度。
3. 没有正向信号但尚未进行恢复尝试：授予一次最多 10 行动的恢复租约，并要求切换方法、缩小范围或检查环境。
4. 恢复租约仍无进展：形成 `PausedNoProgress` 检查点。
5. 相同失败动作连续两次：沿用现有循环保护，立即暂停当前 Worker；根任务可在一次受控恢复策略后继续其他节点。
6. 环境缺失已被宿主确认：停止依赖该环境的节点，记录 `BlockedEnvironment`，继续不依赖该环境的节点。

## 8. 状态机

```text
Pending
  -> Running
     -> WaitingExternal
        -> Running
     -> LeaseReview
        -> Running                  有进展，自动续期
        -> RecoveryLease            暂无进展，切换一次策略
        -> PausedNoProgress         恢复后仍无进展
     -> Finalizing                  达到最终保险上限
        -> Done                     结果和证据完整
        -> PausedBudget             仍有未完成项
     -> PausedUser                  用户中断
     -> BlockedEnvironment          环境缺失
     -> FailedExecution             CodePro 自身不可恢复错误
     -> Done                        正常完成或已获得真实失败证据
```

真实测试退出非零仍可使测试节点 `Done`，因为节点已经完成“运行测试并收集证据”的目标；项目测试结果单独记录为失败，不能改写成 `FailedExecution`。

## 9. 超时与停滞分层

行动额度、API 超时、工具超时和任务停滞必须分开：

1. **Provider 首字节/流停滞超时**：只处理模型连接；允许有限重试和 Provider 回退。
2. **工具超时**：按工具或命令类型配置；超时后保留已有输出和进程状态。
3. **活动停滞监视器**：默认 300 秒无事件时只通知用户，不杀死任务。
4. **确定性循环保护**：基于动作指纹停止重复失败。
5. **单纪元保险上限**：限制模型行动总量，不限制已经启动的有效工具自然结束。
6. **用户停止**：取消模型和受管工具，形成 `PausedUser`；无法立即取消的外部动作显示真实状态。

## 10. 持久化检查点

每个任务检查点至少保存：

- 根任务 ID、会话 ID、恢复纪元和任务类型；
- 用户原始目标及当前已确认范围；
- DAG 和每个节点的状态、依赖与角色；
- 当前软检查点、已使用行动、续期次数和保险上限；
- 最近结构化进展信号及循环指纹；
- 已完成步骤、未完成步骤和下一可执行节点；
- 修改文件、Patch 摘要和文件内容哈希；
- 命令、工作目录、退出码、有界输出和制品引用；
- 测试结果、环境阻塞和候选问题；
- 正在运行或无法确认终态的工具与子 Agent；
- Provider 重试、回退和恢复租约使用情况；
- 暂停或停止的宿主原因码。

检查点只保存必要的有界证据和制品引用，不重复写入大段工具输出、完整文件或模型内部推理。

## 11. 恢复规则

恢复时必须先进行宿主对账：

1. 检查修改文件是否仍与检查点哈希兼容；
2. 检查后台进程和子 Agent 的真实终态；
3. 已完成且证据完整的节点保持完成；
4. 只把未完成、失去终态或明确需要返工的节点重新放入队列；
5. 不重复执行已成功且没有输入变化的危险或昂贵动作；
6. 若项目文件已被用户修改，标记冲突并缩小恢复范围；
7. 用户点击“继续执行”创建新纪元，并在 UI 中显示“从上次进度继续”，不能显示成新任务从零开始。

## 12. 前端交互

### 12.1 正常长任务

前端显示业务进度，不显示模型额度压力：

```text
CodePro 正在继续处理
已完成 7 / 12 项 · 正在运行集成测试
系统已根据有效进展自动延长执行时间
```

### 12.2 停滞提醒

停滞监视器只显示通知：

```text
这个步骤较长，5 分钟没有新输出。
CodePro 仍在等待测试进程，你可以继续等待或停止任务。
```

### 12.3 暂停和继续

暂停卡片必须包含：

- 为什么暂停；
- 已完成多少；
- 当前修改是否保存；
- 哪个步骤尚未完成；
- “继续剩余任务”按钮；
- “查看技术证据”入口。

达到最终保险上限时使用“CodePro 已保存进度，等待继续”，不能使用“Agent 执行失败”或“项目可能有 Bug”。

## 13. 事件协议

新增或统一以下宿主事件，全部带 `task_id`、`epoch`、`sequence` 和时间戳：

- `budget/lease_started`
- `budget/lease_extended`
- `budget/recovery_started`
- `budget/finalization_started`
- `budget/paused`
- `progress/meaningful`
- `progress/stall_warning`
- `checkpoint/saved`
- `checkpoint/reconciled`
- `task/resumed`

前端只消费事件和结构化状态，不解析“正在继续”“达到上限”等自然语言。事件写入持久化日志后再广播，重连时按序号补发，避免界面丢步骤或一直旋转。

## 14. 报告契约

报告分类保持互斥：

- 项目测试真实失败：测试程序已运行并返回非零结果；
- 已确认代码问题：具有位置和可复现证据；
- 环境阻塞：缺少运行所需工具、权限或外部服务；
- CodePro 未完成：无进展暂停、保险上限暂停、用户中断或不可恢复执行错误；
- 未验证：没有执行对应场景。

行动额度、超时、循环保护和用户中断不得被写成项目 Bug、测试失败或“项目可能有 Bug”。

## 15. 安全与资源边界

1. 最终保险上限、费用上限和危险操作审批由宿主控制。
2. 自动续期不扩大文件系统、Shell、网络、MCP 或外部系统权限。
3. 恢复纪元不自动重复部署、推送、付款、删除或其他外部副作用。
4. 全局费用上限优先于行动续期；费用达到上限时保存检查点并暂停。
5. 日志不持久化密钥、完整敏感参数或无限工具输出。
6. 用户停止必须终止新的模型调用，并明确显示后台工具是否已真正停止。

## 16. 迁移与兼容

1. 旧状态缺少恢复纪元时按纪元 1 读取。
2. 旧的 `current_limit_turns` 映射为当前租约结束位置。
3. 旧的 `extension_used` 只用于审计，不再阻止后续基于进展的续期。
4. 旧的行动上限暂停状态可以直接生成新纪元并恢复。
5. 现有 U-36 重复动作保护、测试证据分类和 Paused 持久化继续复用。
6. 首次发布使用功能开关；旧策略保留一个版本作为回退路径。

## 17. 测试策略

### 17.1 预算与进展单元测试

- 每种任务类型获得准确的软检查点、租约和保险上限；
- 有新证据时连续多次自动续期，直到任务完成；
- 等待中的命令不消耗行动额度；
- 重复读取、重复失败和无输出不能制造虚假进展；
- 恢复租约最多一次且长度不超过 10；
- Planner 和模型不能扩大宿主额度；
- 单 Worker 达到角色上限后创建 continuation Worker。

### 17.2 状态与恢复测试

- 在模型调用、文件修改、测试运行和子 Agent 等待阶段分别中断；
- 重启后恢复完整步骤、文件、证据和事件序号；
- 已完成节点不重复运行；
- 用户修改项目后能够检测冲突；
- 旧版状态能够迁移并继续。

### 17.3 超时与熔断测试

- Provider 5xx、流中断和工具超时互不混淆；
- 300 秒无活动只产生提醒；
- 相同失败动作连续两次暂停 Worker；
- 有持续输出的长测试不会被误判停滞；
- 最终保险上限触发一次无工具收尾，失败时由宿主生成报告。

### 17.4 前端测试

- 自动续期不生成错误红卡；
- 暂停、停止、等待和失败具有不同图标与文案；
- 重连后步骤不丢失、不重复且旋转状态正确结束；
- “继续剩余任务”从检查点创建新纪元；
- 普通用户区不显示内部行动次数，技术区可查看额度审计。

### 17.5 真实桌面验收

至少覆盖大型项目只读分析、全项目测试、复杂 Bug 修复、长时间编译、Provider 短暂 5xx、用户中断后继续、应用重启后继续和确定性死循环八个场景。

## 18. 成功标准

1. 有持续结构化进展的任务不会在原有 20/40/60/80/90 次位置停止。
2. 正常长任务自动续期时不要求用户确认。
3. 无进展任务在一次恢复租约后确定性暂停，不会无限消耗。
4. 最终保险上限后始终存在可读报告和可恢复检查点。
5. 中断或重启后继续时不重复已完成节点。
6. 等待有效工具或子 Agent 不消耗模型行动额度。
7. 用户界面不再显示“子 Agent 达到行动次数上限，任务尚未完成”作为普通失败。
8. 项目测试失败、环境阻塞和 CodePro 未完成在状态、统计和报告中完全分离。
9. 所有自动续期、恢复和暂停决定都有宿主事件和可核验测试。

## 19. 实施边界

实施应按以下四个独立增量进行：

1. 后端租约、进展判定和保险上限；
2. 检查点、恢复纪元和重启对账；
3. 事件协议与前端暂停/继续交互；
4. 报告分类、迁移、真实桌面验收和旧策略清理。

每个增量必须先写失败测试，完成后立即运行对应定向测试，再进入下一增量。完整实现计划在本设计通过用户复核后单独编写。

## 20. 自检结果

- 占位符：无。
- 一致性：软检查点负责评估，租约负责续期，最终保险上限负责资源兜底，三者职责不重叠。
- 范围：只升级行动续期、停滞、恢复和对应 UI/报告契约，不改变四角色职责或权限系统。
- 歧义处理：正常长任务自动续期；只有无进展、环境阻塞、用户停止或最终保险上限需要暂停。
