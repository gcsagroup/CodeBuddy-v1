# CodeBuddy Git 工作树生命周期计划：Task 1 兼容性修订

本文是英文主计划中 Task 1 的简体中文修订说明。Task 1 除原定三个文件外，还必须修改
`crates/goose/src/agents/agent.rs`：如果只持久化描述符而不阻断危险恢复路径，旧状态仍可能被执行。

采用明确的三种模式：

- `direct`：保持当前直接工作区行为；描述符不授予 Git 权限，仍需现有会话/工作区绑定。
- `legacy_unresolved`：旧状态没有描述符且 `source_repo` 与 `worktree_path` 不同；保留两条路径供查看，但不提供可执行目录，也不推断 Git 工作树归属。
- `git_worktree`：必须包含完整且经过验证的 Git 元数据；Task 1 只定义和验证结构，不创建、重开或路由到工作树。

加载时，缺少描述符且两条路径等价的状态迁移为 `direct`；路径不同的状态迁移为
`legacy_unresolved`，不得拒绝或静默隐藏。保存时先克隆并规范化状态，保证新写入的状态都含描述符。
暂时保留旧路径字段，并要求它们与描述符投影一致。

恢复检查点时，必须在基线捕获、证据收集和工具执行之前识别 `legacy_unresolved`，保留任务供查看，
并返回明确的 needs-attention；不得把验证错误吞成“没有可继续任务”。链接重放是在当前已绑定目录中新建运行，
不是检查点恢复，必须用回归测试固定该区别。

路径等价必须复用现有可信规范化逻辑，不能用自造字符串比较授予权限。Git 对象 ID 接受 40 或 64 位十六进制；
路径字符串或对象 ID 本身都不能证明工作树归属。

最小 RED 测试：

1. 缺少描述符且路径等价时迁移为无 Git 元数据的 `direct`。
2. 路径不同时仍可读取为 `legacy_unresolved`，并保留两条路径。
3. `legacy_unresolved` 不提供已验证执行目录。
4. 其检查点恢复在基线和工具调用前进入 needs-attention，正常 `direct` 恢复不回归。
5. 状态列表仍显示未解决的历史任务。
6. 保存旧形状状态后，持久化结果包含非空描述符。
7. direct/未解决模式携带 Git 元数据、git_worktree 缺元数据、不支持的版本、空路径、非法 OID、投影不一致均失败关闭。
8. snake_case 序列化、40/64 位 OID、Windows 规范路径等价和链接重放边界保持稳定。

Task 1 只验收持久化合同、安全迁移、消费者阻断和投影；不代表工作树发现、创建、隔离、重开、应用或丢弃已经实现。
