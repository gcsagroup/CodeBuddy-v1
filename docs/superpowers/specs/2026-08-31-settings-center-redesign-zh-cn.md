# CodeBuddy 设置中心重构设计

## 目标

将当前横向标签、按实现模块堆叠的设置页重构为以用户目标组织的设置中心。保留现有模型路由、本地推理、Provider、权限、记忆、凭据、扩展和应用设置能力，不以重构为由删除或降级既有功能。

## 已确认决策

- 使用“分组侧栏 + 设置搜索”的主结构。
- 设置页负责模型连接与 Agent 模型配置；不在设置中心提供 GGUF/HuggingFace 下载器。
- 普通用户只看到“CodeBuddy 模型”和“自定义模型连接”，不展示厂商市场。
- CodeBuddy 模型在开发完成前显示为“开发中”，不可选择，也不伪装成可用。
- 自定义连接支持本机、局域网和自建公网端点；默认采用 OpenAI 兼容协议并通过 `/v1/models` 发现模型，发现失败时允许手工输入模型 ID。
- 后端能力不可用时保留入口，显示原因和修复路径，不再静默隐藏整个页面。
- 系统提示模板属于高级功能；普通用户通过“行为与回答”调整体验。

## 信息架构

### 常用

1. **常规**：启动行为、窗口行为、睡眠策略和成本显示。
2. **外观与语言**：主题、界面语言和显示偏好。
3. **通知与更新**：任务通知、操作系统通知入口、版本和更新策略。

### AI

1. **模型与运行**：当前模型、连接状态、快速切换和 Agent 模型配置。
2. **行为与回答**：默认模式、回答风格、工具详情显示、拼写检查和项目提示。
3. **记忆**：项目记忆开关、可读记忆列表、添加、编辑和删除；配额、过期、导出及清理进入高级管理。

### 连接与安全

1. **工具与连接**：扩展、外部后端和连接状态。
2. **账号与凭据**：GitHub 及自定义端点密钥；密钥只显示状态，不回显明文。
3. **权限与隐私**：工具权限、只读判断、工作区授权、遥测和数据边界。

### 高级

1. **快捷键**：全局、应用、搜索和窗口快捷键。
2. **系统提示模板**：底层模板列表、差异、校验、保存和恢复默认。
3. **开发者与诊断**：原始配置、能力声明、日志和诊断导出。

## 设置外壳

- 左侧固定分组侧栏，右侧显示单个设置页面。
- 顶部提供设置搜索；搜索结果显示设置名称、说明和所在路径。
- 每项说明保存范围：全局、配置档、项目或当前会话。
- 每项说明生效时机：立即生效、下次对话或需要重启。
- 页面只在存在异常时显示状态卡片，避免把设置首页变成持续占位的运维面板。
- 保留旧深链接并映射到新路径，避免现有入口失效。

## 模型与运行

设置摘要显示当前模型、运行位置、连接健康状态和“切换模型”“配置 Agent 模型”操作。

模型来源只包含两类：

1. **CodeBuddy 模型**：完成前只显示开发中，不提供虚假下载或选择入口。
2. **已配置连接**：用户已经验证的本机、局域网或公网端点。

自定义连接向导步骤：

1. 选择运行位置。
2. 输入连接名称、基础 URL、协议和可选密钥。
3. 测试网络与认证，再请求模型列表。
4. 从发现结果选择模型；仅在发现失败时手工填写模型 ID。
5. 保存后选择是否设为默认模型。

本轮连接测试以可安全读取模型列表为成功标准。测试失败必须区分连接拒绝、超时、TLS、认证、模型列表缺失和协议不兼容；失败的连接不能成为默认模型。流式输出与工具调用能力由实际会话验证，不在连接向导中自动发起可能计费的推理请求。

公网端点必须使用 HTTPS。HTTP 只允许环回地址和用户明确确认的局域网地址。密钥存入现有安全凭据存储，不写入项目文件、日志或导出诊断。

## 记忆

- 第一屏回答“是否启用、作用于哪个项目、记住了什么、如何修改或删除”。
- 空状态提供“添加记忆”和可复制示例，例如“记住：本项目统一使用 pnpm”。
- 每条记录优先显示自然语言内容、类别、来源和更新时间。
- 置信度、内部作用域、证据引用和到期时间折叠为技术详情。
- 关闭记忆不删除数据；删除单条和清空项目记忆分别确认。
- `AGENTS.md` 等强制规则与记忆明确分离。

## 行为与提示模板

“行为与回答”面向普通用户，提供可逆、安全的选项。系统提示模板移入高级设置，并按“始终使用、特定功能、仅 CLI 或本地模型”分组。

模板保存前必须校验 Jinja 语法、必需变量和最小试渲染。编辑器提供默认差异、风险等级和恢复默认。`system.md` 与 `permission_judge.md` 标记为高风险；校验失败时禁止保存。

## 状态与数据流

设置页面只消费统一的设置描述和状态接口，不直接推断编译特性。后端返回每项能力的 `available`、`reason` 和可选 `recoveryAction`。前端据此显示可用、开发中、需要安装、需要登录或当前构建不支持。

模型连接采用“草稿 → 测试通过 → 保存 → 可选择”的状态流。修改活动连接先创建待验证草稿；验证通过后原子替换，避免把当前可用模型改成坏配置。

## 兼容与迁移

- 复用现有 Provider、模型默认值、凭据存储和本地模型目录。
- 不删除旧配置键；新增适配层把旧 Provider 配置投影成自定义连接。
- 旧厂商卡片从普通界面移除，但底层 Provider 实现暂时保留，避免历史配置失效。
- 首次进入新设置中心时迁移 UI 索引，不复制或重写密钥。
- 本地推理入口不再只由 `localInference` 布尔值决定是否渲染。

## 错误处理

- 保存失败时保留表单内容并显示具体失败阶段。
- 登录、权限、连接测试和安全确认属于可续跑等待，不报告成项目失败。
- 修改连接时保留旧的可用配置，只有新草稿验证成功后才替换。
- 删除连接前显示受影响的默认模型、当前会话与 Agent 角色。
- 诊断导出默认脱敏 URL 凭据、令牌、请求正文和用户文件内容。

## 分阶段交付

1. 设置外壳、侧栏、搜索、路由兼容和能力状态。
2. 模型与运行、Agent 模型配置、自定义连接向导。
3. 行为与回答、记忆和权限与隐私。
4. 工具与连接、账号凭据、系统提示模板和开发者诊断。
5. 全量三语文案、迁移验证、Release 绑定和真实桌面验收。

每阶段独立通过测试后才能进入下一阶段，不进行一次性整页替换。

## 验收

- 组件测试覆盖导航、搜索、深链接、不可用能力、表单持久化和危险操作。
- ACP/后端测试覆盖模型发现、手工模型 ID、认证、TLS、超时、协议和原子更新。
- 回归现有 Provider/模型路由、本地推理、权限等待、工作区授权、记忆持久化、凭据和更新功能。
- 打包后的后端必须声明与实际编译能力一致；入口不可因能力缺失无解释消失。
- 在真实 Windows 桌面完成设置搜索、自定义本地连接、模型切换、重启恢复、记忆管理、提示模板校验和恢复默认。
- Release 安装包重复执行关键流程，并记录命令、退出码、测试数量和证据路径。

## 非目标

- 本轮不建设第三方厂商市场。
- 不在 CodeBuddy 模型未完成时伪造可用模型或下载地址。
- 不重写模型推理引擎或 Provider 协议实现。
- 不借设置重构更改现有权限语义、自动修复状态机或存储位置。

## 已批准补充：本地连接与 Agent 模型

- 删除模型控制台中的 GGUF/HuggingFace 推荐、搜索和下载界面，不删除底层兼容代码或用户已有模型文件。
- “模型与运行”仅展示 CodeBuddy 自有模型（开发中）、已配置连接和新增连接入口，不展示厂商市场。
- 所有模型选择器保留“厂商”和“模型”两个下拉框。厂商只列出配置成功且可激活的连接；模型只列出所选厂商发现或保存的模型。
- 厂商下拉框底部固定提供“使用其他厂商…”。该入口只打开 Ollama（推荐）、OpenAI 兼容和手动配置，不打开完整厂商目录。
- Ollama 默认地址为 `http://127.0.0.1:11434`。先检测连接，再自动发现模型；发现失败时才允许手工填写模型 ID。失败草稿不替换现有可用配置。
- 新连接保存成功后返回原模型选择器，并选中新厂商和模型。既有云端连接保留且继续可选，但不重新推荐。
- 原“模型控制台”改为“Agent 模型配置”：包含默认 Agent 模型，以及可选的 Planner、Coder、Tester、Reviewer 高级路由。
- 高级路由关闭时四个角色跟随默认 Agent 模型；开启后每个角色分别使用“已配置厂商 + 对应模型”。不向普通用户暴露会话标题、上下文压缩和权限判断等内部辅助模型。
- 连接失效或模型消失时显示不可用状态，不静默回退或改写用户选择。

### 官方行为对照与取舍

- 采用 Ollama 官方 `GET /api/tags` 模型列表接口和本机 `11434` 端口惯例；界面默认使用明确的 `127.0.0.1`。
- 采用 OpenAI 官方 `GET /v1/models` 的 `data[].id` 结构作为 OpenAI 兼容端点的发现契约。
- 不推测或复制 Codex 私有设置实现；只采用可观察的简洁设置与不暴露内部辅助模型原则。
- 拒绝完整厂商市场、自动下载大模型，以及连接测试时发送可能计费的推理请求。

参考：[Ollama List models](https://docs.ollama.com/api/tags)、[OpenAI List models](https://platform.openai.com/docs/api-reference/models/list)。
