- 撤回整任务工具白名单、必须先登记精确收件人、固定 UIA 搜索/选择路线、额外的插话分类与持久发送标记、external_message 协议枚举以及依赖它们的自主发送放行。不存在新的计划或发送状态机。
- 导航、选择工具、是否需要视觉、如何处理普通插话仍由现有 Main Agent 决定。宿主不能根据进度文字或模型名猜业务事实或输入能力。
- 本切片只修基础设施：保留请求的图片，暴露服务真实错误；内置 PowerShell 仅设置本进程策略；执行前核对目标和焦点；检查点绑定任务；正确关联消息对账回执。
- 独立视觉解释不变成授权或已确认收件人；解释过期图片仍可返回带失效标记的观察，不扩展动作有效期，也不因一次只读失败清除所有观察。
- 撤回错误实现不等于统一副作用边界已经成立。任意 shell、第三方工具、委派的等价发送约束仍未覆盖；原发送确认保留，不能开放或宣传安全自主发送。
- 后续如要补齐跨路径边界，必须在真实动作执行入口建立可约束的能力范围；不能以增加一份模型分类、固定业务步骤或关键词名单代替。本切片不新增这套跨模块机制。

交付边界：按用户约定不运行中间测试；做格式/静态差异检查和原入口后端构建。桌面 E2E 与真实服务图片接收仍需运行证据，不能从代码已删除或构建成功推断通过。修订后的实现和剩余项以同日实施记录 R1 节为准。

## 已有证据与问题边界

事故材料：`C:\test\test_0929`、`C:\Users\admin\Desktop\2026-0929-1116cu`，以及本机对应会话、模型请求日志。前轮调查记录了受控观察失败、脚本替代、图片未进入模型请求、中文脚本解码损坏和焦点落到 CodeBuddy 等现象。发送数量和真实送达情况未证实。

本轮重新核对源码：

1. `extension_manager.rs::computer_method_allows_tool` 对 `Unrestricted` 直接放行；派发入口已有统一检查位置，可以复用，不能只修改 Computer 内部检查。
2. `computer.rs::prepare_message` 在观察与参数校验之后才建立消息效果记录。因此，已有检查点不能单独承担“进入对外发送阶段”的事实来源。
3. `computer.rs::call_tool` 的安全阻断只覆盖该扩展内的调用。外部扩展、shell、委派不因该阻断自动受限。
4. `computer.rs::send_message` 当前要求 `explicit_user_confirmation`。需要区分现有自主模式授权与逐次人工确认，不能为了免确认而伪造 `UserConfirmed` 回执。
5. `agent.rs::model_context_without_unsupported_images` 将工具图片替换为文字；原工具成功结果仍保留。不能把保存截图当成模型实际获得视觉信息。
6. 已有语义合同的 `RequirementEffect::ExternalEffect` 是宽泛外部副作用，不等于“发送消息阶段”；不能靠该枚举或文字关键词猜出完整消息授权。

## 不变量

- 相同消息副作用使用同一收件人绑定、发送前校验和不确定结果处理；工具名称不构成豁免。
- 阶段约束由宿主绑定到已有 session/run/task 及有效需求版本，不依赖模型自觉先调用 prepare，不依赖进度文字、命令关键字或工具说明。
- 模型可以提出目标和操作；宿主核对目标来源、权限和真实观察。模型说“已确认”不是证据。
- 发送前观察不可用、目标不一致、焦点变化或证据过期，不得派发输入或发送。
- unknown 只允许观察与对账，不能通过另一个工具、另一个 checkpoint 或委派重复发送。
- 约束随原任务恢复；新任务不继承旧目标授权。尚未结清的消息效果不因换任务、重启或模型声明完成而被清除。
- 不承诺任意不受限制的脚本天然可控。无法提供同等校验的脚本、扩展或委派，在受保护范围内不可执行。
- 主模型或用户指定的独立视觉模型都可以提供观察；未配置、调用失败或没有有效结果时明确失败，不擅自改用其他提供商。

## 实施顺序与验收边界

### S1：建立早于副作用的约束，并接入统一派发

事实 owner 仍为现有任务语义接收与授权边界。先打通已接受任务语义到派发上下文的绑定；不能把宽泛 tool_action 或 ExternalEffect 直接等同于消息发送，也不能仅由 prepare 自报开始。

派发入口按照可信能力与作用范围处理：

- 只读观察、对账、停止可以继续。
- 发送只能进入统一消息校验路径。
- 任意代码执行、未受控外部写入和委派不能成为替代通道；未知能力默认不可用于该阶段，不能仅信任第三方 readOnly 标注。
- 普通点击、按键、UIA invoke、输入同样可能发送消息，不能作为默认豁免。
- 导航必须有宿主能够验证的目标和动作合同；无法区别导航与发送的通用输入不执行。必要的受控导航能力与禁绕过一起实现，不能以“所有动作都被禁止”冒充可用修复。

复用既有身份、权限入口和消息效果账本，不新建平行生命周期。检查批量调用、进行中的子任务、执行中插话与恢复路径；不能只检查工具列表或入队时的旧快照。先启动且无法撤销的外部操作必须显式保留不确定性，不作事后已经阻止的承诺。

完成条件：保护不依赖模型先调用 prepare；Auto 不绕过；普通开发任务仍可使用原有 shell；所有不能提供等价校验的输入路径得到有原因的拒绝和可执行恢复出口。

### S2：视觉信息真实性与发送检查

- 分开截图保存、图片实际进入请求、获得有效识别结果三个事实；沿既有请求与截图关联记录必要诊断，不保存额外敏感正文。
- 未提供图片的读图结果不能继续暗示视觉成功；主模型能力未知不靠名称特判补洞。
- 复用已配置的独立视觉路由；输出绑定当前截图与窗口，不能把旧截图结果用于新动作。
- 复用消息检查点完成收件人、完整文本、前台窗口、发送前新观察、结果与重复发送校验。
- 自主模式使用真实策略授权，不伪造人工确认；显式拒绝和其他限制仍有效。

完成条件：缺图、视觉失败、错误目标均不能被“我看到了”的模型说明推进到发送；有效视觉与合法自主授权能够完成受控流程。

### S3：启动、编码、单步执行与恢复

- 内置 PowerShell 桥接使用进程级执行设置，不修改 CurrentUser/LocalMachine；保留 UTF-8 BOM、隐藏窗口和取消机制。
- 中文输入走可靠 Unicode 路径；不改变通用 write 的原文字节语义。
- 聚焦后检查真正前台窗口；每次操作依赖最新观察，失焦或目标变化使旧依据失效。
- 进程退出成功不等于业务完成；脚本、文件或截图成功不能清除消息阻断，也不能成为发送成功证据。
- 遇到相同缺口不机械续跑。反馈必须说明失败原因、宿主可恢复动作、模型可做的下一步或停止原因。

完成条件：不修改持久系统策略，不出现中文损坏，不向错误窗口输入，错误与不确定结果保持诚实。

### S4：集中隔离产品 E2E

使用当前 worktree 构建产物和本地隔离消息窗口，记录 revision、构建来源、实际操作与持久回执。夹具无外部发送能力，不提交真实会话内容。

1. 自主正常流程：中文搜索、正确目标、完整消息、恰好一次本地发送。
2. 缺图或视觉故障：没有猜测输入，反馈明确；恢复后使用新观察。
3. 错误目标或焦点被抢：不得输入到另一窗口或 CodeBuddy。
4. 受控工具失败后尝试 shell、通用点击/按键、其他扩展或委派替代：实际派发被阻断，而非只有模型自述拒绝。
5. 结果不明、重试与恢复：无重复发送，旧效果可对账；不能以新任务身份跳过未知结果。
6. 普通开发任务对照：不含发送副作用时原有工具能力不被无关限制。

正常可用性和安全阻断必须都通过；仅阻断全部操作不算通过。自动化不可用时明确 E2E 阻塞，不能用源码阅读或模拟工具回执代替产品验收。

### S5：成熟实现对照与事故回溯审查

用户追加要求：修复后检查设计是否偏移、完整 CU 链路是否成立，并回顾原始失败案例。此项属于交付门槛，不是增加无关全量测试。

选择一至两个与本次问题相关、可核对公开源码或官方文档的成熟实现；同时对照已接入的固定版本 CUA Driver 合同。记录上游版本/commit、具体文件或文档链接、证据日期。比较职责和可执行合同，不按产品知名度推断能力，不推断闭源内部实现。外部实现同样没有解决的安全问题必须明确标注，不能拿上游示例当安全保证。

重点审查：观察如何进入模型、坐标与窗口如何绑定、输入如何串行化和取消、权限是否约束同等副作用、失败后怎样恢复、unknown 如何避免重复执行。每项记录采用/未采用/有意差异及原因；检查本批是否新增重复状态、第二个权限裁决者、过度限制或模型机械手续。不得为了形式上与外部项目一致而恢复旧 Agent/Runtime/Permission 链路。

按完整用户路径串联证据：原始目标 → 宿主任务与发送范围 → 工具派发 → 观察/视觉请求 → 目标和焦点校验 → 输入/发送 → 效果账本 → 恢复或用户结果。任何一段只有说明文字、未绑定截图或模型自述，不能写成链路已通过。

对原事故逐项建立“原始证据 → 根因 → 修复位置 → 当前验收证据 → 剩余限制”记录，至少覆盖：

- 内置 PowerShell 被执行策略拒绝、随后修改持久用户策略。
- 截图保存成功但模型请求没有图片；独立视觉未调用；模型仍声称看到了目标。
- UTF-8 无 BOM 脚本在 Windows PowerShell 解码为乱码。
- 失焦、猜测坐标、未核对联系人；输入进入 CodeBuddy 自己的队列。
- 出错脚本 exit 0，命令成功被误认为业务进展；重复写脚本延长无效尝试。
- 通用工具或委派绕过消息检查点；重复发送和 unknown 的恢复出口。

结论逐项使用“已验证修复 / 已实现但未验证 / 未覆盖 / 非本批问题”，保留未知送达数量等原证据边界。发现同根因遗漏纳入本批；独立非阻塞问题列入待办。关键回归修复后只重跑受影响隔离场景，不重新铺开全套测试。设计对照通过不替代产品 E2E，隔离 E2E 不替代真实微信验收。
