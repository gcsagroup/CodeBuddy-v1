## 目标与不变量

用户在发送需求、等待、回看、执行、收尾和打开交付物之间能持续理解发生了什么。体验改善必须使用真实活动和回执，不伪造进度、不新增模型分类请求、不规定模型业务步骤。

依据 `CODEPRO_FACT_AUTHORITY_ZH_CN.md`：Provider 提供生成消息，Runtime 与工具拥有派发/结果事实，Session 保存历史，宿主绑定计划，完成层消费既有事实，UI 仅投影。预览不执行、不写入模型历史；计划复选框不控制执行；旧版本不自动升级；最终答复不提前越过完成门槛。

本批不新增持久化状态机、公共协议或权限能力。若证据证明必须改变上述边界，停止相关项并报告比较方案；不阻塞其他独立修复。

### 第二项 思考展示与阅读位置

证据：同一模型响应被拆分成工具请求后复制思考，历史逐条渲染；组件没有内部跟随滚动，活跃状态有旧内容冒充新接收的问题。

- 核查工具请求的消息身份、思考复制和重放。优先在展示投影处理，不删除持久化内容或 Provider 需要的签名/上下文。
- 只对同一连续工具展示序列中完全一致的重复内容做展示去重；不得模糊匹配，不跨新的用户输入或公开说明合并，不作业务裁决。若现有身份足以定位原响应，优先使用身份。
- 公开思考更新时可默认展开；手动收起/展开优先；用户在底部才跟随更新，上翻阅读时保留位置并提供返回最新入口。结束后自动展开部分收起，用户手动打开的不强关。
- “正在接收”不能仅依据消息含 thinking。核查 ACP 实时事件与重放边界，在已有会话展示 owner 内提供暂态活动依据；不将这个 UI 活动信息用于控制面。
- 验证实时到历史、多个工具、下一轮相同文字、停止、手动折叠、上翻与回到底部。

## 计划审查

实施前由本 Agent 做一轮独立于方案编写的反向审查，不将其称作另一个 Agent 的评审。逐项回答：

1. 当前证据支持根因，还是只支持症状？预览缺失保持待定位。
2. 是否保留既有 dirty 改动？修改前阅读对应 diff，不重置。
3. 是否将展示去重扩成删除模型内容？禁止。
4. 是否以时间推断模型内部正在想什么？禁止；活动只依据已收到事件，不承诺持续计算。
5. 是否因合同版本变化自动继承旧计划？禁止。
6. 是否把预览计数当写入事实、把文本查看当应用启动？禁止。
7. 是否为了通过测试改变完成门槛、扩大权限或增加模型流程？禁止。
8. 验证是否对应真实缺陷、是否存在停止和回放反例？没有则补最小回归，不堆无关覆盖率。
