# 工具与技能目录的 SDK 适配

该适配减少未使用能力的常驻输入，保留完整技能和工具调用能力。它不删减用户指令、项目规则、权限边界或已加载技能正文。

## 实现与所有权

- SDK 固定为 `0.2.1-alpha.2`，加载前校验技能插件和注册表源码哈希。适配在内存中生效，不修改 `node_modules`；上游升级需重新审核适配点。
- 主 Agent 的技能摘要索引预算为 640 字符，项目／用户安装的技能优先于内置默认技能。预算仅覆盖索引行；使用规则单独保留。完整目录仍写入原生 `source.entries`，不会放进模型请求正文。子 Agent 和没有兼容发现工具的 scope 保留完整原生展示。
- `search_mcp_tools({kind:"skills",query,offset})` 每页返回最多 5 个当前允许调用的技能摘要。无匹配可换关键词或空查询分页；加载仍调用原生 `skill({name})`。候选不执行、不授权、不把正文提前塞入输入。
- MCP 常驻服务名称索引有 320 字符预算；工具描述和 schema 按需加载。查询回执包含 `discoveryOnly` 和阶段，明确区分候选、定义加载与真实工具结果。
- 文件技能正文变化使用目录已有文档版本哈希；注册表适配转交原生 winning candidate 的版本，原生发布摘要识别正文变化并提示重新加载。其他 provider 未提供版本时仍保持原有语义。未另建目录缓存或权限状态。
- 请求诊断只记录分组字符数／字节数，不记录正文或凭据，也不把字符数冒充 token。模型服务的 usage 是实际总 token 依据。

## 兼容和回退

移除 `profile.mjs` 中 `catalogIndexMaxCharacters` 即恢复完整原生目录展示，仍保留原生加载和内容版本支持。可选 `source.presentation` 与 entry `revision` 缺失时兼容旧历史，并在需要时重新发布；不迁移、不重写、不删除用户消息。旧会话已经保存的长目录不会被本次适配追溯抹除，之后的上下文压缩仍归 Harness。

## 验证边界

回归覆盖最终提供商 HTTP 请求在 10／100／1,000 技能下的大小、完整分页发现、范围和调用策略、热增删、正文更新、配置回退、冷恢复、原生技能加载以及工具执行许可拒绝。原生合同测试核对公开 driver、模型元数据入口和真实服务入口的加载兼容性。

早期问候样本记录了 1,368 → 948，但当时诊断没有完整保存缓存字段，不能追溯重建完整输入；后续以修正统计口径后的样本为准。夹具不是用户截图的完整配置，不能用它冒充对 2,277 的同条件比较或宣称达到 40% 目标。

更正：早期工具／技能样本只累加原生 `inputTokens`，漏记 `cacheReadTokens`／`cacheWriteTokens`。之前的 6,692 → 3,223 和 13,386 → 4,367 是未缓存输入，不能证明总输入降低，也不能推断计费节省。诊断现保留缓存读写和总 token 字段；完整输入按未缓存输入＋缓存读取＋缓存写入计算。旧样本保留，但不再作为整轮优化证据。

测试中曾发现并修复正文更新未触发技能重载，以及定义查询容易被误读为执行结果。初始失败日志保留在本地验收目录。提示与结构化回执不能保证模型永不编造结果；验收以实际调用和返回值核对，不能只看回答文字。

本轮为 Windows 当前源码的 SDK／真实模型调用验证，不是 Windows／Mac 完整桌面 E2E，也未重建安装包。旧桌面进程和旧安装包不能证明本次改动；源码修改后需按 README 重启预览。
