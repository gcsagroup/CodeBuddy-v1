# 工具箱与安装默认模型

全新安装预置两条连接：默认选中的 **CodeBuddy LAN**，以及 **ollama** 云服务（`https://ollama.com`）。Ollama 预置用户于 2026-10-23 已加载的 22 个模型名称，可在连接配置中刷新；不把该快照当成永久有效的服务目录。本批按用户明确授权附带统一的 Ollama Cloud Key，新用户安装后可直接选择云模型，无需填写 Key。首次启动将共享 Key 存入本机 DPAPI/Keychain 保护的配置；构建用明文凭据文件只在本地打包并由 Git 忽略。客户端内置共享 Key 可被提取，额度及费用归对应账户。当前用户已配置的 Ollama 连接和所选模型保留。云端需要 API Key，见 [Ollama 官方认证说明](https://github.com/ollama/ollama/blob/main/docs/api/authentication.mdx)。

工具箱“全部”按内置能力、技能、外部 MCP 分组。电脑控制是执行工具；桌面操作指南（computer-use）是模型加载的技能，不会自动打开电脑控制开关。本地 Git 管理工作区仓库，GitHub 连接远端仓库、议题、拉取请求与 CI。

全新安装的 Windows/macOS 桌面通过同一个 Harness 状态初始化入口读取 runtime/default-model.json，默认使用 http://192.168.9.101:8001 的 gemma-4-26B-A4B-it-uncensored-FP8-W8A16，配置上下文为服务在 2026-10-22 返回的 65,536 tokens。安装启动不主动发送用户内容，也不要求模型服务器在线。

主模型和辅助图像识别默认选择同一服务。2026-10-23 使用隔离的红蓝图片实测，该模型正确识别了左右颜色；发行预设因此启用图像输入。此结果只证明本次图片请求成功，不代表电脑控制或其他工具已经验收。

这是一项局域网预设，其他网络可能无法连接。用户可在设置 → 模型与运行中修改服务地址、添加自己的提供商，并分别切换主模型、图像识别模型及图像能力设置。已有 state.json 不注入或覆盖默认值；用户删除预设后，重启不会重新添加。不改变系统网络授权。

2026-10-23 实测发现 `kimi-k3` 的 Ollama 原始流存在正文为空的问题，因此全新安装的云模型列表将 `kimi-k2.6` 排在首位，原目录仍保留。既有配置不调整。第三方目录中的其他模型不视为已逐一验收。
