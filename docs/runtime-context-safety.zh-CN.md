# 长任务运行快照与压缩失败恢复

本次修复针对运行快照、过期进程失败提醒持续进入模型上下文的问题。执行、回执、权限、压缩范围、工具配对和检查点事务仍由锁定的 Harness 负责；不新增执行循环，不从命令文案或模型自述判断任务成功。

## 回执提醒

`command-evidence.mjs` 接收原生前台进程的结构化结果，以完整的工具名、工作目录和命令的哈希关联重跑。只有同一身份的成功进程回执才能移除对应项；超时、中断、拒绝、runner 失败和无关命令成功都不会清除失败。

活动 run 的索引只保留未解决的进程项，每个原生 turn 开始时重置。正常读取、文件写入和成功的无关进程不会进入索引，也不会改变提醒。该索引不持有任务验收或业务失败权威；不同验证是否足以完成任务仍由模型依据真实回执判断。

提醒最多 4,096 个 UTF-16 码元、8 项；命令预览最多 256 个码元，并注明未展示数量。这些是字符预算，不是 Token 或费用。完整命令、文件正文、输出及回执仍在原生日志中。显示上限不会删除未解决项。

## 统一模型可见历史

alpha2 的 `Session` surface fold 对有结构化 `runtime-context` 来源的完整快照做替代投影：新快照使此前同类快照不再生成模型消息。只有 `user/message`、用户角色、来源 kind 精确匹配，且 form 为 `snapshot` 或兼容旧版本的缺省值时适用。普通用户输入、工具调用/结果、未知 form 和其他插件消息不受此规则影响；不匹配文字前缀。

原始事件和 positional surface 节点保留，旧版摘要引用的 seq 范围仍可回放。失效快照投影为无消息；清除快照仍作为最新状态保留，最新快照被摘要替换后不会复活旧权限。逐前缀恢复和 fork 依据该前缀已有事件重新投影，不提前使用未来状态。

TokenMeter 的增量回放复用原有 Session `SurfaceManager`，在相同的事件前缀下定价；计量、摘要输入、请求序列化、恢复和 fork 消费一致的模型历史。工具结果裁剪仍只处理工具结果；运行快照治理独立于 80% 压力阈值，不需要额外模型请求。

旧版本的 provider usage 可能包含已经被替代的快照。冷恢复时，若旧请求视图发生了这种变化，当前占用改按可见内容估算；原始账单记录不变，收到本进程新请求的实际用量后恢复校准。因此可见节点价格保持一致，但不能宣称冷恢复后的占用总值必然等于旧版本或旧进程的用量样本。

图片预算恢复同样消费可见消息：原生图片卸载器跳过无消息节点，旧图片卸载记录重放时不会复活已经隐藏的快照，原生图片发生项校验和取消边界保留。此处修正的是 `measure()` 和 CodeBuddy 当前占用；SDK 独立的 `contextPressure` / `contextBreakdown` 原始统计投影没有改写，不能将其历史值当作本次新投影的精确发送规模。

完整快照的模型可见数量固定为最多一份，因此没有再增加“8 份快照/8K Token”策略。最新必需权限、目录和角色不截断；若最新状态本身过大，仍由已有请求 fit 门槛拒绝，不谎报容量或省略安全约束。

补丁通过已有哈希/版本校验入口加载，不修改安装依赖：

- `sdk-budget/runtime-context-patch.mjs`：Session 统一投影、TokenMeter 的原生前缀回放和旧用量校准保护、图片卸载消费者适配、Agent Loop 恢复时忽略失效快照。
- `sdk-budget-contract.mjs`：先加载 Session 和计量补丁。
- `runtime-context-contract.mjs`：工具及子代理兼容层加载完成后，再加载 Agent Loop 补丁，避免破坏既有模块身份。

本次没有更改 Session 格式、持久化事件或公共 RPC。新版本读取旧记录时不改写文件；旧版本仍能读原始日志，但不会获得新的投影行为。

## 摘要失败后的有界恢复

保留原有失败抑制。相同配置下，失败之后须同时经过 30 秒且当前计量至少增加 8,192 Token，才允许自动重新尝试；有效请求配置或摘要配置变化可提前重新尝试。每次原生活动周期最多两次自动恢复，成功摘要不会补回已经消耗的恢复次数。

原生 idle 或成功取得维护准入的显式 `/compact` 重置限制。被 busy 拒绝或在准入前取消的 `/compact` 不清除活动任务的保护。所有检查先尊重取消；备用路线、摘要输出预算、主请求网络重试、输出恢复和检查点事务继续沿用现有机制。

普通压力选区若只剩一个实际可见的旧检查点，即使夹着仍保留的位置节点，也在开启压缩事务前返回无操作，避免每步产生没有实际摘要请求的失败卡片。手动压缩和本地预算/超限恢复继续保留重新压缩检查点的能力。

日志只记录失败类别、固定阈值、恢复次数和条件，不增加原始命令、模型输入或凭据。失败缓存及恢复次数属于原有进程内 WeakMap，重启后不自动发起摘要或工具；不增加持久化恢复协议。

原生压缩事务将失败转成私有错误字符串前，兼容入口把安全诊断投影关联到该 Session 和 compactionId。Driver 只在对应结束事件上消费一次，再由既有状态提示持久化。公开信息仍由 publicFailure 的允许列表生成；不解析服务正文或旧错误字符串，不改变原生错误、摘要提交、备用路线或重试判定。缺少结构化事实的旧记录继续显示未知原因，诊断观察失败也不能改变事务结果。

## 取舍与验证边界

附带报告的远端样本统计不是本机实测 Token 或费用。最新快照替代旧快照会改变请求前缀，可能降低缓存命中；本次优先保证状态正确和输入不随快照线性膨胀，不承诺真实费用、模型质量或时延按字符数同比下降。

为保持旧摘要的位置范围可回放，宿主仍保留原生日志和失效节点。10,000 次纯快照压力夹具中，模型可见内容保持有界，但宿主扫描成本随历史增长；这不是消除所有本机历史成本或内存增长的保证。真实长任务的原生摘要仍可收拢位置范围，未在本次改动中另建日志清理机制。

参考了上游当前的 [runtime-context 所有者](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/agent-loop/src/runtime-context.ts)和 [Session surface](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/core/session/src/surface.ts)。采用原生来源标签、完整快照和统一投影边界；不把提示词里的“替代旧状态”当成实际清理，不单独升级存在紧密版本依赖的包。
