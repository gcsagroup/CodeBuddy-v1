## 3. 方案比较与推荐

| 方案 | 收益 | 代价与判断 |
|---|---|---|
| 自定义 Harness profile + Host 兼容插件 + 独立能力服务 | 保持既有界面合同，复用上游核心，复用现有成熟能力 | 需开发协议/状态适配；推荐 |
| 直接把后端换成 dsh ACP 或现成 SDK 进程 | 最快接通普通对话 | 完整控制、实时展示和产品扩展存在缺口；不满足当前范围 |
| 在 Harness 上重写全部外围服务 | 统一实现技术 | 重复迁移 Git、电脑控制、记忆等能力，回归面大；本轮不采用 |

推荐用受版本约束的插件组合，避免长期修改上游核心。保留 Rust/Go/Swift 能力服务属于实现复用；新任务的旧 Agent 循环、Planner、TaskScheduler、旧控制面及恢复执行入口必须退出运行链。

## 4. 目标结构与职责

```text
冻结的 CodeBuddy 界面
    ↓ 既有 ACP / goose 扩展合同
Electron 启动与通信桥
    ↓ 本机认证连接
CodeBuddy Host 兼容插件
    ├─ Session Controller：历史、实时流、分叉、取消
    ├─ Harness agent-loop / subagent / jobs：唯一执行与调度核心
    ├─ CodeBuddy 产品策略插件：角色配置、任务控制、权限与结果投影
    └─ 独立能力服务：MCP、电脑控制、Git、记忆、模型/配置等
```

| 单元 | 唯一职责与边界 |
|---|---|
| Electron 宿主 | 启停、就绪、崩溃报告、连接鉴权与打包；不解释用户任务或调度 agent |
| Host 兼容插件 | 验证既有请求，转换事件、标识与错误；不自行运行第二套模型循环 |
| Harness 与产品策略插件 | Harness 执行/子任务机制负责运行；产品策略在其扩展点实现现有角色、计划、任务生命周期和完成条件 |
| 产品状态 | 每项状态仅一个写入者；新运行事件进入 Harness 会话日志，旧 UI 快照为可重建投影；不把 turn/end 等同于任务已完成 |
| 能力服务 | 完成具体工具、存储或系统操作并返回真实回执；不自行创建旧 Agent |
| 历史适配器 | 读取迁入的旧格式历史，支持既有查询/导出/管理；不恢复旧检查点或执行权限 |

自定义 codebuddy profile 经上游启动机制装配插件；优先调用 ctx.sessionController 及已公开服务，复用跟随流/重连逻辑。避免单独复制一套 Harness 启动器或完整 Web UI。

兼容层保留既有请求字段、能力协商、错误形状、消息/工具标识、任务序号和权限选项。长 prompt 与控制操作保持独立通道，防止停止/快照查询被阻塞。流式增量、持久事件和最终提交分开处理，重连去重；公开思考仅转发供应商实际提供的内容。

## 5. 界面冻结办法

- 冻结范围包括 App/路由、components、样式、国际化资源、交互 hooks/store、消息/任务展示转换及其公开类型。
- 通信例外仅限 main/preload/gooseServe、连接传输实现，以及必要的构建/打包/依赖接线；同一文件中的窗口、菜单、快捷键等行为仍保持原样。
- ACP 业务适配器与 SDK 的对外类型合同保持。每个例外文件在变更清单中说明理由，不扩大为整个目录可改。
- 实施前保存当前源文件清单、哈希和 dirty 状态；复制纳入基线的源码、文档和未提交新文件。排除 .git、依赖、构建产物、缓存及私人数据；被忽略但必要的源码/资源单独列明后纳入。
- 此时冻结的是复制时的完整工作树；原项目之后的修改通过显式增量合入，不自动覆盖新版。
- 验收同时检查冻结文件零差异与真实功能。零差异只是源码约束证据，不等于功能通过。

## 7. 数据迁移设计

1. 新版使用独立应用数据根、Electron userData 与凭据命名空间；P0 同时固定安装目录、安装器身份、Bundle ID、单实例标识、协议/文件关联归属与更新通道。候选版本不接管旧版注册，正式切换另列精确交接操作；可见界面文案保持。旧目录始终保留，迁移操作只写新版。
2. 旧 SQLite 使用一致性快照或数据库备份接口，处理 WAL/SHM；日志/附件记录清单、来源和校验摘要。重复导入幂等，局部失败可重试。
3. 旧聊天、工具回执和任务历史保留原状态。历史窗口续聊维持原交互，后台建立新 Harness run，关联只读历史上下文；不继承旧检查点、活进程句柄、授权或待执行工具。
4. 既有新建/分叉入口保持。旧历史删除、改名等操作仅作用于新版档案副本，不修改源应用。
5. 迁移模型/MCP、技能、配方和偏好；凭据引用单独映射。系统 keyring、OAuth 与 GitHub 登录逐项处理，不在报告或日志写出密钥；迁移失败沿现有界面重新登录。
6. 项目记忆保留启用状态、来源、审核信息、TTL 与项目身份；路径变化显式映射。Hindsight 等派生索引按本地权威记录重建，不复活已禁用或已删除内容。
7. 已确认：导入日程为暂停且待验证，沿现有“立即运行”流程验证。“立即运行”会真实执行，验收使用受控任务。启用前核对旧版同源日程已停用并记录原日程 ID 与交接状态，确保单一触发方；退出旧应用本身不构成永久停用证据。迁移器不擅自修改旧日程，源日程仍启用或状态未知时保持新版暂停，沿现有错误反馈交接缺口。旧运行实例不迁成活任务。
8. 保留队列恢复后暂停的现有语义；待发送、发送结果不明及草稿分别处理，避免重放。外部后端连接配置须校验，防止新版意外连回旧核心。

新旧并存用于回滚应用版本；运行中的任务不在两个核心间热切换。新事件不会回写旧格式，也不要求旧版能继续执行新版任务。

## 8. 分阶段实施与门槛

| 阶段 | 交付 | 进入下一阶段前的门槛 |
|---|---|---|
| P0 基线与合同 | 源码/冻结哈希、全部功能与RPC清单、现有缺陷台账、数据映射、精确变更清单、固定上游版本 | 当前与目标可追溯；原有失败与新增回归区分；只读验证不修改环境 |
| P1 最小真实接入 | 原界面 → Host 插件 → Harness；连通真实模型、工具、权限、取消、历史/重连 | 协议与组件测试通过；真实浏览器/桌面关键链通过；确认旧核心调用为零 |
| P2 执行与调度迁移 | 角色、多 agent、计划、任务状态、插话、暂停/恢复及定时入口 | 状态/取消/并发/幂等/崩溃测试通过；真实多任务流程通过 |
| P3 全部能力适配 | 完成第6节逐项合同，补足 MCP Apps、模型、记忆及原生能力 | 每项自动化先通过，再验收相关真实交互；未通过项不得标记完成 |
| P4 数据迁移 | 只读旧源导入、历史桥、凭据/记忆映射、暂停日程及回滚记录 | 真实格式脱敏样本含附件/工具错误/残缺日志；失败重试及新旧隔离通过 |
| P5 Windows 交付 | 与冻结界面配套的新运行时与安装产物 | 全功能回归、完整开发任务与电脑控制流程、安装启动/升级/退出检查 |
| P6 macOS 交付 | 对应平台运行时、原生能力与安装产物 | 真实 Mac 构建/签名状态、权限、完整用户流程及平台差异验收 |

每个功能按“自动化 → 真实关键路径”推进，不把所有真实验证积压到最后。测试只针对改动和合同风险；修改文档不运行产品测试。电脑控制工具验收用于电脑操作能力；其他界面交互使用浏览器/Electron 测试入口。

## 9. 验收、风险与交付边界

- 后端必须覆盖状态机、协议校验、事件去重、并发控制、取消、持久化及迁移边界；输入使用原项目真实格式的脱敏样本。
- 沿用前端组件测试；在真实浏览器/Electron 中验证现有交互。跨模块流程覆盖需求输入、计划、实际文件改动、测试、结果展示、停止/恢复和历史。
- 模型验收覆盖现有使用方式中的云端、自定义兼容端点、本地模型及视觉路径；使用真实配置时另记录凭据可用性与调用成本，当前不读取用户凭据。
- 采集首个可见增量、工具耗时、取消完成、重连恢复、token与费用，与原版同条件对比；尚无基线时不承诺固定性能收益。
- 原版已有缺陷单列，不把它们固化为必须保留的正确行为；影响迁移验收的缺陷明确处理归属，不用隐藏功能或返回伪成功绕过。
- 上游接口变更通过显式升级处理；锁定版本、通知、插件边界和兼容合同，避免自动追随 master。
- Mac 验收需要真实 Mac 环境；Windows 证据不能代替。开发构建、自动测试、真实产品验收和安装包验收分别报告。
- 完成标准：冻结界面无未授权变化；全部合同映射闭合；新任务只走 Harness；所有迁入日程初始暂停，启用有单一触发方交接证据；数据可追溯且原版可回退；新版安装、更新及卸载均不破坏旧版；两个平台分别有验收证据。

不在本轮设计中创建分支、提交、推送、安装依赖或修改系统环境。实施所需依赖、构建环境与真实数据迁移先列出精确操作；方案批准不视为任意环境变更授权。
