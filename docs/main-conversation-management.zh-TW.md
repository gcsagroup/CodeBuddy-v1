# 主對話管理專案與對話 · 設計提案

使用者可在主對話說「建立官網專案，開兩個對話分別負責設計與開發」，取得路徑與可開啟的對話。詢問開發進度時，可查到對應工作、最近一次工具回執、更新時間與待處理事項。第一版涵蓋目前 CodeBuddy 資料設定中的專案與對話。

## 選擇處理方式與驗收

主對話直接回答諮詢及製作一次性小檔案。屬於現有專案的修改交回原開發對話。開始多階段新產品時，主對話可建立專案、開發對話並啟動首個里程碑。完全存取時，使用者明確指定操作及目標後直接執行專案、對話的新增、刪除、修改及派發；操作或目標不明確時先詢問。變更對話權限仍須確認。專案對話結束後，主對話顯示該輪的實際結果。工作由目標對話執行，受理與完成分別由原生事件和執行結果證實。目標有歧義時先確認。

查進度一次讀取近期要求、對話回覆、執行狀態與工具回執。清空只重設目前主對話的訊息與上下文，保留其他對話、專案檔案及已儲存的記憶，原生分叉可能保留舊日誌。

使用者只需啟動時，可在確認視窗看到「專案接單後結束本輪」。確認後直接顯示目標目錄及接單結果。混合要求可繼續處理其他交付。例如，派發檔案工作後也要回答單位換算；應核對兩項結果及主對話目錄中沒有重複檔案。

驗收涵蓋單位換算、製作小檔案、僅詢問網盤架構、讀取兩個同名專案的 Git 提交、澄清目標、建立並派發首個網盤里程碑、查核實際檔案、在原對話續作，以及清空前後的一次性口令。

## 已實作的使用方式

在主對話中說出專案名稱或路徑，即可詢問目前執行狀態及最近工作。也可要求建立專案資料夾及對話、重新命名、歸檔、還原、刪除對話、移除專案登記或變更單一對話的權限。新專案建立在目前設定的工作區根目錄，移除登記保留磁碟檔案。管理工具顯示目標及預定變更，使用者確認後提交。

權限可選唯讀、工作區內修改、完整存取或恢復繼承。閒置對話立即生效，既有執行保留開始時的覆寫，下一輪使用新值。會話索引的選用欄位 `permissionOverride` 保存選擇，Harness 執行權限。舊客戶端沿用全域設定介面；降級前應檢查依賴單對話限制的專案。

查詢歷史時可按目前對話讀取原生使用者原話，按時間倒序分頁並附訊息 ID 和事件序號。詳細進度可查閱有限長度的工具回執。目前按需讀取日誌，尚未新增全文索引。

## 介面與資料

CodeBuddy 的通用介紹、圖示與三項能力移到「新任務」，保留工作區選擇與輸入框。主對話有歷史時直接續聊。空主對話介紹專案進度、對話管理和單一對話的權限。

每份資料設定透過 `runtime/main-conversation.mjs` 取得唯一主對話。`workspace_memory` 可唯讀查閱已登記工作區的有效記憶。`backend/main-conversation` 是工作目錄。在 `backend/state.json` 按 `globalConversation` 取得產品記錄，以 `nativeSessionId ?? id` 在 `backend/harness/sessions` 定位原生日誌。建議提供「開啟聊天記錄所在資料夾」，每次依目前資料根目錄與原生對話身分定位。

## 長歷史與準確性

輸入草稿時保留介紹，送出後顯示訊息；回放期間沿用載入畫面。

Harness 將原生事件寫入 JSONL，在上下文壓力下壓縮選定片段，也可使用 `/compact`。選定區間中成功且配對的工具回執可將檔案路徑帶入檢查點。模型每次請求受上下文預算限制；摘要可能漏掉否定條件、版本或更正。2026-11-11 以真實 Gemma 4 26B A4B 在隔離設定中輸入約 3.6 萬字元，執行兩次 `/compact` 並重新啟動後端。重新啟動後的指令省略了目標與新名稱。模型查回更正原話與專案目錄，僅將 `west-site` 的「开发」改為「核验-351a2f」，`east-site` 的同名對話保留原名。這是一次實測。另一次真實 Electron 驗收完成建立專案、建立對話及單獨改為唯讀。長輸入中的資訊位置會影響部分模型的檢索表現。 [原始研究](https://arxiv.org/abs/2307.03172)

1. 詢問過去的決定時，以目前資料設定、專案、對話及時間檢索，取回原話、上下文與後續修訂，附可開啟的來源。有衝突且範圍不明時向使用者釐清。詢問現況時讀取目前設定或執行狀態。
2. 動作提交前由宿主核對專案 ID、對話 ID、路徑、有效權限與既有回執。舊授權只能解釋當時的決定。
3. 原生日誌由 Harness 持有。先量測掃描耗時，再視需要建立可重建的本機增量索引，僅存必要檢索欄位與事件位置，按頁取回有限片段。重啟後由已驗證位置繼續。清空、分支、刪除後限制可檢索歷史。工作資料夾無須另存聊天全文。量測開啟與檢索延遲、日誌及索引大小後再決定歸檔策略；上下文壓縮不會限制磁碟用量。
4. 以兩個同名專案放入早期約定、中段更正、末尾撤回與大量無關工具輸出。經兩次真實模型壓縮、重新啟動後，核對原文、目前決定、目標 ID、工具回執及重複執行次數。另測清空後無法取回舊內容。按模型與實際上下文用量記錄正確數／總數、誤操作數及延遲；誤用關鍵限制或操作錯誤專案即阻擋交付。

## 管理操作

| 操作 | 產品行為 |
| --- | --- |
| 查詢專案、進度與對話 | 先讀取快照，再按 ID 訂閱事件，重新連線後重取快照。需要細節時才讀相關歷史、程式差異或測試回執，附來源與時間，分別呈現工作結束、程式變更、測試與使用者驗收。背景更新狀態，使用者詢問才呼叫模型分析。 |
| 建立專案與對話 | 沿用工作區分配、專案登記、建立對話與失敗補償。重試以操作 ID 去重，回傳已建立物件，部分失敗可續辦。 |
| 修改或分派 | 支援專案顯示名稱、對話重新命名、追加目標及建立指定工作。目標對話依其工作區和權限執行；忙碌時沿用既有排隊或跟進機制。 |
| 歸檔或刪除 | 區分歸檔與還原、刪除聊天記錄、從清單移除專案與實體刪除資料夾。實體刪除先列出路徑及影響供使用者選擇；沿用活動檢查與邏輯刪除回執。 |
| 調整權限 | 顯示目標、目前模式、新模式與生效時間。宿主檢查主對話身分和使用者授權。其他對話的內容只作為資料。 |

管理工具專屬於主對話。宿主核對 ID、正規化路徑與範圍；同名或有歧義時列出候選路徑。Harness 持有執行、取消、回執與歷史；Store 與專案登記各自保存狀態。概覽僅呈現這些資料。

現有 `session/set_mode` 會寫入全域 `preferences.gooseMode` 並同步多個對話。保留此行為，新增單一對話覆寫，在宿主策略範圍內優先於全域預設。預設下一輪生效；需要立即收緊時先停止並等待回執。待審批事項沿用原請求。可恢復繼承全域預設。舊記錄缺省即繼承，降級前檢查仍生效的覆寫，特別是更嚴格的限制。

## 實施與驗收

1. 分開交付歡迎區遷移與全域唯讀查詢。以兩個專案測試執行中、斷線、中斷、空記錄與來源跳轉。
2. 開放專案與對話管理。驗證同名、重試、部分失敗、既有檔案保護及活動對話刪除，再從主對話完成建立、分派與查看結果。
3. 加入單對話權限，驗證只調整 A 時 B 與全域預設維持原值，並測試執行中變更及重新啟動。跨模組測試後，以隔離設定、真實模型與桌面完成驗收。
