# 运行提示与模型选择

这是本轮运行情况的提示，不是模型评级、任务失败判定或新的 Agent 执行核心。截图仅参考卡片布局，未推断 Codex 私有触发逻辑。

## 触发与交互

| 已观察到的事实 | 默认显示条件 | 提示方向 |
|---|---|---|
| 请求在连接或等待内容 | 本次请求 90 秒 | 服务忙碌或连接延迟，不能据此判断模型能力 |
| 正在接收本次模型生成 | 本次请求 180 秒 | 可等待、换模型或降低思考强度；不宣布失败 |
| 工具回执连续未成功 | 3 次 | 先检查参数、权限和环境，不归咎模型 |
| 响应格式/空响应/截断等恢复 | 3 次且无成功工具回执 | 模型或服务格式可能不适合本任务，可尝试其他已配置模型 |

等待审批、运行工具、压缩上下文、子任务与取消期间不显示此卡。一次请求结束或工具实际启动时清除生成计时；成功工具回执清除失败计数。HTTP 与网络失败保留现有连接诊断，不计为模型响应恢复。计数是观察事实，不是“任务无进展”的语义裁决；只读检查成功也会清零。

“继续等待”只隐藏当前轮次的卡片，不发请求。新轮次可重新提示。关闭应用或重载后不保证保留隐藏选择；不持久化模型评分或用户偏好。“停止并选择模型”先通过原有取消控制器停止，收到空闲状态后打开已有模型选择器；不自动选择、重发或改写任务，不删除文件。切换聊天会取消待打开选择器的 UI 请求。

## 实现边界

- `runtime/harness/driver.mjs` 消费已有 `commandEvidence/hasFailedCommand` 的进程失败事实，只补充工具回执显示元数据。
- `runtime/work-status.mjs` 持有本轮临时观察计数和请求开始时间，经既有 `execution_activity` 状态消息发送。无定时网络请求、额外模型评分、权限或完成状态改动。
- `chatSessionStore` 校验可选字段及所属聊天/轮次；旧客户端可忽略，旧服务缺字段则不显示对应提示，不迁移持久化数据。
- `useWorkStatus` 决定显示，`RunAdviceCard` 展示三语卡片；`BaseChat/ChatInput` 复用取消与模型列表入口。按本轮隐藏，不按模型名称硬编码。

## 公开方案比较

[OpenAI Agents SDK](https://openai.github.io/openai-agents-js/guides/running-agents/) 提供运行上限和独立错误类型；[LangChain 工具调用限制](https://reference.langchain.com/javascript/langchain/index/toolCallLimitMiddleware) 区分线程与本轮计数，并配置达到上限后的行为。本功能借鉴按轮次观测及错误分类，没有引入硬停止上限，不能把到达上限当成模型能力不足。

[Anthropic 长任务实践](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents) 强调跨上下文保留进展及验证实际结果。提示卡不能替代结果验证，也不能修复生成项目本身。

OpenAI Agents SDK 与 LangChain.js 的公开仓库均为 MIT 许可，本次查阅时公开文档与主分支可访问；本次仅借鉴设计，不复制代码、不安装依赖，也不替换已锁定的 DeepSeek Harness。直接导入另一套 Agent 循环会重复执行、取消和状态职责，因此不采用。

交付复核与独立验收已于 2026-11-10 按用户要求移除。此前多模型安装验收发现的功能缺陷、复核漏判和 Gemma 恢复问题仍需单独解决；提示出现不代表这些问题已修复。
