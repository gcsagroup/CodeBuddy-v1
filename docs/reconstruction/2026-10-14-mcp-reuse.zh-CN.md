# 新会话复用远程 MCP

本切片解决新建会话重复连接远程 MCP；不改变模型、思考档位、工具选择或前端。工作目录为 `D:\CodeBuddy-v1`，没有 `.git`，源码身份用最终回执中的 SHA256 记录；保留既有文件，无分支、提交、推送、依赖安装或升级。

## 原因与采用方案

旧适配在每个 Agent 的会话插件里创建 MCP，`configureSession` 先释放该插件再创建，导致不同新会话重复初始化同一远程服务。此前真实窗口 Exa 建连为 2.625s / 8.126s，见[上一轮诊断](2026-10-14-harness-latency-comparison.zh-CN.md)。

采用固定安装版本 `0.2.1-alpha.2` 的官方 `dsh-agent-preset-registry`、`dsh-scope` 和 Cordis 生命周期。官方 registry 为配置声明创建长期作用域；`acquireScope` 返回原生租约，负责旧修订保留与最终释放。包为 MIT，源码在[官方仓库](https://github.com/deepseek-ai/deepseek-harness)，本次没有更新上游包。

- 相同远程 MCP 配置在同一运行时共享长期组合。身份使用规范化后的完整配置，包括服务名、地址、凭据、超时和重连设置；摘要仅作内存索引，不写明文凭据或派生配置到磁盘。
- registry 位于私有服务域，避免把连接组合当作用户 Agent preset 写入会话历史；会话的原生执行、调度、完成判定保持不变。
- 会话通过官方 scope 父链借用组合；工具清单、资源、服务提示词按作用域继承，每次执行仍经过该会话的审批和权限路径。禁用 MCP 的会话不会继承它。
- 配置变化产生另一组合，旧会话保留原连接。最多保留 8 组可再次取得的配置；退出此缓存的修订如仍有原生租约，继续由 Harness 保留。共享失败的首次启动不缓存，下次取得可重试。
- 工具列表动态更新通过 Harness `tools/change` 同步会话的继承工具限制，保留禁用原生工具的限制。资源读取及 MCP Apps 元数据继续使用已有适配。
- stdio 仍按会话创建并释放，因为它可能绑定工作目录、进程及会话状态；未擅自将跨项目本地进程全局共享。重启运行时后第一次连接也仍需初始化。

拒绝每会话继续重建、禁用 Exa，以及自建客户端连接池。当前复用的是 Harness 的组合、作用域和租约机制；MCP SDK 和现有 `mcp-bridge.mjs` 继续承载协议及 Apps 元数据，未宣称已删除所有适配或替换该桥的重连实现。

## 改动

- `runtime/harness/mcp-presets.mjs`：私有原生 registry、配置匹配、取得租约、有限保留，以及继承工具变化同步。
- `runtime/harness/mcp-composition.mjs`：组合内并行激活已有 MCP 插件，保留每个服务的失败状态。
- `runtime/harness/index.mjs`：会话绑定和释放共享租约，stdio 保持局部生命周期，保持扩展结果原顺序。
- `runtime/harness/test/mcp-apps.test.mjs`：使用本机真实 HTTP、SSE 及实际调用验证复用和隔离。
